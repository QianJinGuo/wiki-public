## 🔍 预习

你可能觉得「Prompt 不就是打字吗」。但同样一个模型，有人用得像个实习生，有人用得像个高级工程师——差别在 Prompt。这章不讲花哨技巧，只讲**基础结构**。

## 📖 正文

### 1.1 Prompt 的四组件

[[concepts/prompt-engineering-fundamentals|Prompt Engineering Fundamentals]] 给出标准结构：

| 组件 | 作用 | 示例 |
|---|---|---|
| **指令** | 告诉模型做什么 | "翻译以下文本" |
| **上下文** | 提供背景信息 | "这是一封商务邮件" |
| **输入** | 具体任务内容 | 待翻译的英文 |
| **输出格式** | 期望的输出形式 | "JSON格式，含原文和译文" |

### 1.2 不写「输出格式」的代价

```
差：把这段话总结一下
好：把这段话总结成 3 个要点，每个要点不超过 20 字，用 Markdown 列表
```

不指定格式，模型自由发挥——可能给你一段散文、可能 10 个要点、可能 JSON。**指定格式让输出可控**。

### 1.3 角色设定：给模型一个身份

```
你是一位资深技术文档工程师，擅长把复杂技术用简洁语言解释。
请把以下 API 文档改写为面向新手的小白教程。
```

角色设定本质是**给模型一个上下文框架**，让它在这个框架内生成更聚焦的内容。

### 1.4 明确约束：少用否定，多用正向

```
差：不要用专业术语
好：用 12 岁孩子能懂的语言
```

LLM 对「不要做什么」的处理不如「做什么」稳定。**用正向指令**更可靠。

### 1.5 分步骤：复杂任务拆解

```
差：分析这段代码的问题并修复
好：
1. 找出代码中的 3 个 bug
2. 对每个 bug 解释根因
3. 给出修复方案
4. 解释为什么这样修
```

分步骤让模型**逐项完成**，每步可检查。这也是第 10 章 CoT 的雏形。

## 🎯 重点回顾

1. **四组件**：指令 / 上下文 / 输入 / 输出格式
2. **指定输出格式**让结果可控
3. **角色设定**给模型聚焦的框架
4. **正向指令**比否定更可靠
5. **分步骤**拆解复杂任务

## 🧠 费曼练习

> 向 12 岁孩子解释「为什么告诉 AI 输出格式很重要」。

提示：AI 像厨师，你说「做个菜」它可能做任何菜，你说「做个番茄炒蛋，装白盘」它就明确。

## ✅ 复习题

1. **[选择题]** Prompt 的四组件不包括？ A. 指令 B. 上下文 C. 模型温度 D. 输出格式
2. **[问答题]** 为什么「用 12 岁孩子能懂的语言」比「不要用专业术语」更好？
3. **[场景题]** 让 LLM 把会议纪要转成行动项。用四组件设计这个 Prompt。
4. **[费曼题]** 用 3 句话向新手解释「为什么 Prompt 要指定输出格式」。
5. **[关联题]** 回顾第 4 章 attention。Prompt 里的「角色设定」是怎么通过 attention 影响输出的？

??? answer "参考答案"
    1. **C**
    2. LLM 处理「不要做什么」不如「做什么」稳定。正向指令给模型明确目标，否定只给约束不给方向。
    3. 指令：把会议纪要转成行动项；上下文：产品评审会纪要；输入：[纪要内容]；输出格式：Markdown 表格，列为「行动项/负责人/截止日期」。
    4. 不指定格式，模型自由发挥，输出不可控；指定格式让结果可预期，便于下游处理。
    5. 角色设定作为 context 进入窗口，后续每个 token 生成时都会 attention 到这句话，让输出风格向"资深工程师"靠拢。
