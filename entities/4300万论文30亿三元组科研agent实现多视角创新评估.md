# 4300万论文、30亿三元组，科研Agent实现多视角创新评估

## 摘要

当大模型深度介入科研流程，研究想法的生成门槛被迅速拉低，真正稀缺的能力随之从「生成」转移到「判断」。本文介绍作者团队同期的两项工作：ICML 2026 论文 **InnoEval** 把研究 idea 的评估形式化为以外部知识为支撑、依赖多视角推理与证据对齐的系统性决策问题；**SciAtlas** 则构建了覆盖 26 个学科、4300 万篇论文、1.57 亿实体、30 亿三元组的大规模科学知识图谱，并封装为可被 Agent 直接调用的结构化科研技能。^[raw/articles/4300万论文30亿三元组科研agent实现多视角创新评估.md]

## 核心要点

- **稀缺性转移**：AI Scientist、Research Agent 让读论文、找相关工作、提假设、写草稿的成本急剧下降，候选 idea 数量随之爆炸——瓶颈从产能转向鉴别力。
- **评估是决策问题，不是打分问题**：InnoEval 把 idea evaluation 定义为 knowledge-grounded、multi-perspective 的推理与决策过程，而非单模型 LLM-as-a-Judge 给出的分数。
- **五个评审问题**：是否已被别人做过；差异在哪里；方法假设是否成立、实验是否可行；做成后是否会产生真实影响；表述是否清晰、能否被复现。
- **三环节架构**：异构深度知识搜索（论文 + 网页 + 代码仓库等多类「活知识」）→ 多视角 reviewer personas 评审委员会 → Clarity / Novelty / Feasibility / Validity / Significance 五维解耦评估，汇总为含证据与 meta-review 的报告。
- **实验证据**：从 NeurIPS 2025 与 ICLR 2025 真实投稿中抽取 idea，构建单点评估、成对比较、组内排序三类任务；三分类 point-wise 预测相比最强基线提升 16.18% F1，且报告质量更接近人类专家评审。
- **SciAtlas 的规模与结构**：26 学科 / 4300 万论文 / 1.57 亿实体 / 30 亿三元组，节点覆盖论文、作者、机构、关键词、期刊会议、领域与主题，关系覆盖引用、合作、共现与主题层级。
- **从相似度到拓扑**：neuro-symbolic retrieval 一面用关键词与语义向量召回，一面用图传播与图重排序发现深层关联，返回的不只是 paper list，还包括分数拆解与路径解释。
- **技能化封装**：quick-paper-search、literature-review、idea-grounding、idea-evaluate、idea-generate、trend-report、researcher-review 等 skill 统一复用底层 search-papers，产物落在 `runs/<run_id>/`，让每一步用了什么证据都可复查。

## 深度分析

### 稀缺性转移：当「生成」不再是瓶颈

过去一年，AI Scientist、Research Agent 与自动化科学发现方向推进得极快，大模型已经可以读论文、找相关工作、提出研究假设，甚至自动生成实验计划与论文草稿。科研流程中「生成」的产能被迅速放大，问题也随之翻转：当 idea 越来越多，谁来判断它们？同时全球论文数量仍在攀升，新的方法与观点以前所未有的密度涌现，如何在海量候选中可靠识别真正具备科学价值与长期影响力的工作，成为科研智能体时代必须回答的核心问题。作者的判断很直接——判断力比产能更贵，它无法靠更流畅的文本生成获得，必须站在已有知识之上。^[raw/articles/4300万论文30亿三元组科研agent实现多视角创新评估.md]

### InnoEval：把 idea 评审拆成知识搜索、评审委员会与解耦维度

InnoEval 不把评审当作一次打分，而当作有证据支撑的决策过程，因而拆成三个环节。其一是异构深度知识搜索：先对原始 idea 做结构化理解并生成多轮查询，同时检索在线文献、网页信息与代码仓库等多类「活知识」，经 fast search 与 slow reading 筛出质量较高的证据，形成背景知识报告。其二是创新评审委员会：真实评审不会只依赖一个人，也不会假设所有评审背景一致，因此构造带不同学术背景与评审倾向的 reviewer personas，让多个评审独立判断，缓解单一模型评审的系统性偏置。其三是多维度解耦评估：一个 idea 可能新颖但不可行，也可能扎实却影响有限，于是默认从 Clarity、Novelty、Feasibility、Validity、Significance 五个维度分别由专门的 evaluator agent 分析，最终汇总成含证据、分项评分、meta-review 与改进建议的完整报告。^[raw/articles/4300万论文30亿三元组科研agent实现多视角创新评估.md]

评测任务的设计同样值得注意：作者从 NeurIPS 2025 与 ICLR 2025 真实投稿中抽取研究想法，构造单点评估、成对比较与组内排序三类任务，使评估能力可在接近真实评审难度的设定下被度量。结果显示 InnoEval 优于 CoT、RAG、ResearchAgent、InternAgent、GraphEval 与 ScholarEval 等基线，三分类 point-wise 预测相比最强基线提升 16.18% F1，报告质量也更接近人类专家评审。^[raw/articles/4300万论文30亿三元组科研agent实现多视角创新评估.md]

### SciAtlas：把科学知识从「读物」变成「可计算对象」

InnoEval 反过来证明了一个更强的命题：创新评估的上限很大程度取决于知识 grounding 的质量。背景知识若不够宽、不够深、不够结构化，模型很容易把「自己没见过」误判为「真正新颖」，也容易漏掉跨学科中的隐含联系。SciAtlas 正是为此构建的多学科异构科学知识图谱基础设施，目前整合 26 个学科、4300 万篇论文、1.57 亿实体与 30 亿条三元组，覆盖论文、作者、机构、关键词、期刊会议、领域、主题等节点，以及引用、合作、关键词共现、主题层级等关系。它与关键词检索或向量相似度的根本差别在于：不只回答「哪些论文在文本层面相似」，而是把科学知识显式建模为可计算的结构化网络，支持沿图谱做拓扑级推理与证据追踪。于是一个 idea 不再与孤立文献做匹配，而可以经由论文语义、标题锚点、引用关系、关键词共现、作者合作网络与领域层级等多条异构路径被联合定位。^[raw/articles/4300万论文30亿三元组科研agent实现多视角创新评估.md]

在检索层面，SciAtlas 采用 neuro-symbolic retrieval：关键词与语义向量负责召回，图传播与图重排序负责发现更深层的知识关联，返回结果除 paper list 外还附带分数拆解与路径解释。更本质的一点是，科学知识本身具有一定程度的可计算结构，而当前 AI 科学智能体普遍缺乏结构化的科学认知能力；SciAtlas 试图让科学知识从「文本阅读对象」变成「结构化、可计算、可推理的认知对象」。工程上它进一步把能力封装为 Agent Skill，使用者无需理解图数据库与检索参数，即可让 Codex、Claude Code 等 Agent 按固定 playbook 完成检索、读取证据与生成报告。需要说明的是，SciAtlas 目前仍主要覆盖跨学科论文级知识的结构化建模，对科学数据集、实验数据与领域垂直资源的关联仍处早期阶段。^[raw/articles/4300万论文30亿三元组科研agent实现多视角创新评估.md]

### 为什么单纯的 LLM-as-a-Judge 不够

把上述两条线并置，可以看清「为什么不能用单个模型打分」的结构性原因。第一，新颖性判断本质上是知识密集型问题：没有足够宽深的背景知识，模型既无法确认一个想法是否已被做过，也无法刻画它与已有工作的真实差异，只能凭文本表面相似度给出印象分。第二，评审是多目标的——novelty、validity、feasibility、significance 经常彼此冲突，把多维权衡压缩成一个标量分数会丢失最有决策价值的取舍信息，解耦成多个维度并由专门 evaluator 负责才能让取舍显式化。第三，单评审必然带偏置，评审委员会的 persona 分化本质上是一种集成，用视角差异换取判断稳定性；加之判断必须可追溯，报告中的证据、分项评分与路径解释，以及 SciAtlas 落盘于 `runs/<run_id>/` 的检索产物，都是为了让「为什么这么评」有据可查。^[raw/articles/4300万论文30亿三元组科研agent实现多视角创新评估.md]

## 实践启示

1. **把评估当决策问题来建模**：先明确要回答的判断问题（是否做过、差异在哪、假设与实验是否成立、影响与可复现性），再设计检索与评分流程，避免直接向单个模型索要一个总分。
2. **知识 grounding 是评估质量的先行条件**：在评估环节之前先建好可追溯的证据层，检索结果要保留分数拆解与路径，否则「新颖」只能是模型的主观印象。
3. **用视角差异换判断稳定**：让多个带不同背景与偏好的评审角色独立判断再做汇总，比反复调用同一个模型更接近真实评审的共识机制。
4. **维度解耦优于分数压缩**：把新颖性、可行性、有效性、影响力、清晰度分开评估，冲突本身就是要交付给决策者的信息。
5. **把工具封装成 Agent Skill 而非 API**：固定 playbook + 落盘产物（request/response/summary/report）让研究者无需理解图数据库与检索参数，也让每一步证据可回溯、可复查。
