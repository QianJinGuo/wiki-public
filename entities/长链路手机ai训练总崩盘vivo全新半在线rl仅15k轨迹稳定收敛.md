## 研究背景：在线RL太贵，离线RL太“短视”

在长程GUI任务上应用RL，两条主流路线各有硬伤：^[raw/articles/长链路手机ai训练总崩盘vivo全新半在线rl仅15k轨迹稳定收敛.md]


- 在线RL：
  能捕捉环境的真实动态反馈，但在30步以上的长任务中交互成本高、奖励稀疏、方差极大，常常在学到可用策略之前就已“训练崩溃”。 ^[raw/articles/长链路手机ai训练总崩盘vivo全新半在线rl仅15k轨迹稳定收敛.md]

- 离线RL：
  用静态数据训练、规避了交互风险，却因只盯着碎片化的“单步转移”而陷入“时序短视”，丢掉了长程规划所需的全局上下文，误差层层累积。 ^[raw/articles/长链路手机ai训练总崩盘vivo全新半在线rl仅15k轨迹稳定收敛.md]

两条路线还共同卡在 信用分配难题（Credit Assignment Problem，CAP） 上：一条长轨迹结束时只有末端一个“成功/失败”的二元信号，无法判断到底是中间哪一步推理立了功、哪一步操作拖了后腿，梯度因此稀疏而嘈杂。我们的思路是：能否既保留离线训练的稳定性，又把通常只有在线交互才具备的轨迹级全局信号补回来？SOLAR-RL正是这一“半在线”范式的具体实现。 ^[raw/articles/长链路手机ai训练总崩盘vivo全新半在线rl仅15k轨迹稳定收敛.md]

△ 三种RL范式对比。离线RL（左上）受限于碎片化的单步数据而“时序短视”；在线RL（右上）能捕捉动态但不稳定且交互成本高；SOLAR-RL（下）通过轨迹重构与回溯性信用分配，把全局轨迹洞察“回填”进离线数据。 ^[raw/articles/长链路手机ai训练总崩盘vivo全新半在线rl仅15k轨迹稳定收敛.md]

## 方法：在静态数据中模拟在线反馈

我们将GUI导航建模为部分可观测马尔可夫决策过程  （POMDP）  ，SOLAR-RL由两个关键组件构成。 ^[raw/articles/长链路手机ai训练总崩盘vivo全新半在线rl仅15k轨迹稳定收敛.md]

- 离线轨迹重构（Offline Trajectory Reconstruction）

对同一任务，我们在每一步并行采样N条候选rollout，再把相同索引的候选首尾相接、拼成N条“重构轨迹”，从而把有限的静态数据扩展成一批多样化的“伪在线”探索数据。其中关键的一点是：每条轨迹都按 逐步有效性（per-step validity） 逐帧核验，一旦某步动作被判无效，轨迹便在这个“首次失败点”被截断、丢弃其后步骤。有效性判定采用基于真值标签的严格协议——坐标类动作用高斯核度量、文本输入用F1分数、应用启动用相似度阈值、系统类动作用精确匹配，既剪掉低质量偏差，又保留探索多样性。 ^[raw/articles/长链路手机ai训练总崩盘vivo全新半在线rl仅15k轨迹稳定收敛.md]

## 深度分析

### 半在线范式的本质：把"在线反馈"变成离线数据的属性而非交互的产物

SOLAR-RL 的"半在线"并不是折中在线与离线的比例，而是重新定义了信息来源：全局轨迹信号不再来自环境的真实交互，而是通过对静态数据的结构化加工"重构"出来。每步并行采样 N 条候选 rollout、再按相同索引拼接成重构轨迹的做法，本质上是把一次静态数据集放大成一批伪在线探索经验——代价只是推理侧的采样算力，而非环境侧的交互成本。这解释了为什么它能在零环境交互的前提下逼近在线 RL 的效果：在线 RL 的价值大头在于"知道整条轨迹哪里开始走偏"，而这个信息可以从离线数据中被算法性地"挤压"出来。^[raw/articles/长链路手机ai训练总崩盘vivo全新半在线rl仅15k轨迹稳定收敛.md:52-56] 值得注意的边界是，这种模拟无法触及分布外的全新状态（未见过的弹窗、延迟引起的界面变化），所以它是"延迟交互"而非"替代交互"。^[raw/articles/长链路手机ai训练总崩盘vivo全新半在线rl仅15k轨迹稳定收敛.md:117-119]

### 15k 轨迹胜过 145k：数据预算问题的正确问法

样本效率的对比是这篇文章最有冲击力的数字：AndroidWorld 上 SOLAR-RL 用 15k 条轨迹（约 94k 步）拿到 33.7% SR，超过了用 145k 轨迹的在线方法 UI-TARS-7B-SFT（33.3%），数据量仅约对手的 10%。在 GUI-Odyssey 上，AgentCPM 的指标虽略高，但用了三倍以上的轨迹（55k+）。这组对比指向一个被普遍忽视的判断：当训练信号足够"精炼"时，原始数据规模不再是决定性变量。这与通用语言模型预训练里"数据质量 > 数据数量"的趋势形成呼应，但在 RL 场景下更极端——因为 RL 的瓶颈往往不是数据量而是信号的方差与稠密度。^[raw/articles/长链路手机ai训练总崩盘vivo全新半在线rl仅15k轨迹稳定收敛.md:79-95] 轨迹感知奖励塑形正是把稀疏的"末端成功/失败"二元信号拆解为步级稠密反馈的关键机制：只有首次失败点之前的有效前缀获得正向奖励，失败步及其后步骤被显式惩罚，再通过长度感知的动态惩罚抑制"奖励刷分"。^[raw/articles/长链路手机ai训练总崩盘vivo全新半在线rl仅15k轨迹稳定收敛.md:58-77]

### On-policy 稳定性 vs Off-policy 效率的第三条路

GRPO 对比实验揭示的失败模式很典型：早期奖励上涨，约 600 步后出现断崖式下滑，智能体陷入无效循环——这是长程 on-policy RL 的经典"策略崩溃"，根源在于稀疏奖励下梯度的方差随轨迹长度放大。SOLAR-RL 的平均动作奖励单调上升并稳定收敛在约 0.75，在 PressBack 这类"何时该后退"的纠错动作上快速收敛到 0.8 以上精度，说明轨迹级信用分配同时解决了稳定性和细粒度行为学习两个问题。^[raw/articles/长链路手机ai训练总崩盘vivo全新半在线rl仅15k轨迹稳定收敛.md:97-103] 换个框架看：传统 on-policy 方法每一步都要为探索付交互代价，传统 off-policy 方法每一步都在为陈旧信号付偏差代价，SOLAR-RL 则把探索"离线化"（重构轨迹替代环境探索）、把信用分配"在线化"（轨迹级信号替代单步转移），两个代价各取其小。

### 长程任务的成功定义：连续纠错而非零失误

论文中 Simple SMS Messenger 的双轨迹案例是全文最有洞察力的部分：两条轨迹起步几乎相同，差别仅在于失败后的策略切换——轨迹一发现"长按已发送消息"无效后，被困在一个看似合理实则走不通的行为模式里；轨迹二则果断放弃长按、改为重新输入并发送。这说明长程 GUI 任务的本质不是"一次都不犯错"，而是"能否一错再纠、连续从次优状态里爬出来"。这个观察对奖励设计有直接指导意义：如果奖励信号只惩罚"犯错"而不奖励"从错误中恢复"，模型会学会回避任何可能失败的操作路径，反而在真实环境中更脆弱。SOLAR-RL 的失败点检测+前缀信用机制恰好给了这种恢复行为正向梯度。^[raw/articles/长链路手机ai训练总崩盘vivo全新半在线rl仅15k轨迹稳定收敛.md:105-113]

## 实践启示

1. **遇到长程 RL 崩溃时，先检查信用分配而非学习率**。GRPO 式断崖下滑的根源是稀疏二元奖励下的高方差梯度，调低学习率只是推迟崩溃；把轨迹级信号拆解为步级稠密奖励才是对症下药。^[raw/articles/长链路手机ai训练总崩盘vivo全新半在线rl仅15k轨迹稳定收敛.md:97-103]

2. **数据预算紧张时，优先投资"信号精炼"而非"数据收集"**。15k 轨迹胜过 145k 的案例说明：与其花成本扩大交互/标注规模，不如把现有数据的每一步都标注出有效性与质量分，性价比可能高一个量级。^[raw/articles/长链路手机ai训练总崩盘vivo全新半在线rl仅15k轨迹稳定收敛.md:79-95]

3. **离线数据可以通过"逐步有效性核验 + 首次失败点截断"变成伪在线探索数据**。即使没有真值标签环境，用严格的分类型有效性协议（坐标用高斯核、文本用 F1、系统动作精确匹配）逐帧核验，就能低成本地为离线 RL 补上全局轨迹信号。^[raw/articles/长链路手机ai训练总崩盘vivo全新半在线rl仅15k轨迹稳定收敛.md:52-56]

4. **奖励设计要奖励"恢复"，而不只惩罚"失败"**。把正向信用限定在首次失败点之前的有效前缀、同时惩罚失败后的无效重复，才能让模型学会放弃无效局部行为并切换策略——这是长程任务真正需要的能力。^[raw/articles/长链路手机ai训练总崩盘vivo全新半在线rl仅15k轨迹稳定收敛.md:58-77]

5. **警惕"模拟在线"的分布外盲区**。半在线方法无法见到离线数据未覆盖的全新状态，若目标环境存在高频 UI 变化（弹窗、动态加载），需要保留一定比例的真实交互数据做兜底，而非全押离线模拟。^[raw/articles/长链路手机ai训练总崩盘vivo全新半在线rl仅15k轨迹稳定收敛.md:117-119]

6. **有效性校验不必永远依赖真值标签**。当前 SOLAR-RL 的逐步有效性判定依赖真值标注，作者指出可替换为学习型验证器或奖励模型——这意味着该范式可以逐步迁移到弱标注、无标注的真实 GUI 数据上，是低成本复现的切入点。^[raw/articles/长链路手机ai训练总崩盘vivo全新半在线rl仅15k轨迹稳定收敛.md:121-123]
