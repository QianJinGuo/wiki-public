## 极致量化压缩，把模型装进手机

量化压缩，简单来说就是把模型里原本用16位数字（16-bit）表示的参数，改用更低位数字储存。^[raw/articles/腾讯混元最新开源440m翻译模型手机离线就能用翻译质量超谷歌.md]

针对不同的手机用户，腾讯特别推出了2-bit与1.25-bit两种极致的量化压缩方案。^[raw/articles/腾讯混元最新开源440m翻译模型手机离线就能用翻译质量超谷歌.md]

## 深度分析

### 三级压缩链：3.3GB → 574MB → 440MB

这条链的关键顺序是先立质量上限、再压体积：1.8B 的 Hy-MT1.5 先在严格评测中做到比肩商业翻译 API 与 235B 级大模型、超越谷歌与百度翻译，压缩才有意义。随后 2-bit（SEQ 加量化感知蒸馏）压至 574MB，1.25-bit（Sherry）进一步压至 440MB，约为原始 FP16 体量（3.3GB）的 1/7.5。^[raw/articles/腾讯混元最新开源440m翻译模型手机离线就能用翻译质量超谷歌.md:40-58]

### 双档位策略与软硬协同

腾讯没有给出单一"最优比特数"，而是按机型分层：2-bit 面向中高端机型（574MB，可借 Arm SME2 提速），1.25-bit 面向全系机型。两条路线最终都落在内核层——STQ 内核适配手机 CPU 的 SIMD 指令集——说明端侧量化的落地门槛在算子实现，而不只在压缩算法本身。^[raw/articles/腾讯混元最新开源440m翻译模型手机离线就能用翻译质量超谷歌.md:54-71]

### Sherry：亚 2-bit 量化的学术化路线

Sherry（稀疏高效三值量化，已被 ACL 2026 录用）的核心是"细粒度稀疏"：每 4 个参数中，3 个最重要的用 1-bit 储存、1 个置零，平均每参数仅 1.25-bit。这与 [[entities/prismml-bonsai-2-27b-ternary-quantization|Bonsai 三值量化]]、[[entities/icml-2026-grace-quantization-aware-distillation|GRACE 量化感知蒸馏]]同属"结构化稀疏 + 蒸馏换保真"的压缩谱系，参见 [[concepts/model-distillation-compression|模型蒸馏与压缩]]。^[raw/articles/腾讯混元最新开源440m翻译模型手机离线就能用翻译质量超谷歌.md:63-67]

### 开源闭环与隐私叙事

开源不止权重：Sherry、AngelSlim、Hy-MT1.5 三篇 arXiv 技术报告、AngelSlim 代码仓库与可直接安装的安卓 Demo APK 一并放出（iOS 待后续版本）。Demo 适配"后台取词"模式，本地看邮件、浏览网页即取即译；全程本地处理、不采集不上传，一次下载永久使用。^[raw/articles/腾讯混元最新开源440m翻译模型手机离线就能用翻译质量超谷歌.md:73-109]
