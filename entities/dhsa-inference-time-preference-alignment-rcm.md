# DHSA：不动基座权重的推理时偏好对齐（RCM+CAST）

## 核心思想

DHSA（直接隐状态对齐，Direct Hidden-State Alignment）由成都大学、北卡罗来纳州立大学、复旦大学、澳大利亚凯斯林大学和澳门大学的研究团队提出，将**承载偏好计算的推理时隐状态作为直接适配空间**，实现不动基座权重的推理时偏好对齐 → [[raw/articles/dhsa-inference-time-preference-alignment-2026-10-12|原文存档]]。 ^[raw/articles/dhsa-inference-time-preference-alignment-2026-10-12.md]

问题动机：RLHF/DPO 通过反馈优化模型权重，但后训练提高单次生成成功率的同时，基座模型多次采样能生成更多样的正确答案——一部分对齐问题其实落在「已有行为如何被稳定表达出来」：支持目标的计算已经存在，是什么阻碍它稳定主导生成，又能否直接纠正？ ^[raw/articles/dhsa-inference-time-preference-alignment-2026-10-12.md]

## 方法

- **残差竞争图（Residual Competition Maps, RCM）**：模型每生成一个词，注意力头、前馈模块等组件都向共享残差流写入更新。仅找对生成「影响大」的组件不够——还要知道它在推动目标还是抵消目标。RCM 将外部指定的偏好映射到内部组件间的竞争结构上，量化偏好相关的内部作用。
- **CAST 隐状态控制器**：基于 RCM 的定位结果，在推理时对隐状态施加直接控制（256-16384 个控制参数），使支持目标的计算稳定主导生成。

## 结果

推理时控制即可达到 **DPO 水准**的偏好对齐效果，且完全不更新基座权重——对齐从「训练期权重改写」扩展到「推理期状态调制」。 ^[raw/articles/dhsa-inference-time-preference-alignment-2026-10-12.md]


## 深度分析

### 对齐问题的重新定位：从「能力缺失」到「表达失败」

RLHF/DPO 的隐含假设是模型「还不会」，所以要把偏好写进权重。DHSA 的出发点正相反：支持目标的计算在推理时已经存在，问题在于它能否稳定主导生成。基座模型多次采样反而能给出更多样正确答案这一现象，与「后训练只提高单次成功率」放在一起看，说明相当一部分对齐缺口不是能力问题而是调控问题。对齐光谱因此多出一档——介于「不动模型」与「改权重」之间的推理时状态调制，[[concepts/activation-engineering|激活工程]]的思路由此获得了因果定位方法的支撑。

### RCM 的方法论要点：归因必须带方向，而不只带权重

常规的可解释性归因回答「哪个组件影响大」，但影响力排序无法指导干预——你不知道该放大它还是压制它。RCM 用对照实验补上了方向：同一输入下比较组件正常写入与置零后的行为差值，若正常写入时目标行为更占优则该组件在支持目标，反之在抵消目标，差值同时给出方向与强度。这把外部偏好映射成了内部组件间的竞争结构，归因输出从「重要性排名」升级为「可操作的干预地图」。「残差竞争」的普遍存在（支持与抵消共存、同一组件随输入换向）进一步说明：归因结果是动态的、输入相关的，不能当成一次性得到的静态指纹反复套用，干预选位需要跟着输入分布走。

### 行为达标不等于机制修复：DPO 之后内部竞争仍然存在

原文最值得警惕的发现是：输出更符合偏好，并不意味着内部作用已经一致。DPO 会显著重组内部作用、削弱部分抵消效应，但抵消效应可能保留。这直接冲击了以胜率、奖励等行为指标收敛为准的对齐评估惯例——行为级指标可能系统性高估内部一致性。一个知识冲突案例很直观：仅将一个注意力头的输出置零，模型就从坚持自身参数知识转向按给定资料回答，输入与权重都未变。行为选择的临界点可以极局部；反过来说，未被处理掉的内部抵消也就随时可能在新分布上重新主导生成，这是「看似对齐好的模型为何偶尔复发」的一种机制解释。

### 局部干预的全局杠杆与 prefill 时机

少量局部状态调整能改变整段回答的内容选择与压缩，说明开放式生成对早期状态的扰动高度敏感——残差流是所有组件的共享总线，早期写入会被后续所有计算放大。干预时机上，部分设置仅在 prefill 阶段介入即可奏效：通过改写提示计算与缓存状态，一次性影响后续全部生成。这与 KV cache 机制天然兼容，解码期几乎零额外开销。对工程部署而言，「早期状态是高杠杆干预点」比「逐 token 控制」实用得多，代价结构完全不同。

### 控制器与权重分离改变了「对齐资产」的形态

256–16384 个控制参数即达到与 DPO 相竞争的水平，且控制器可在推理时启用/移除、叠加到已 DPO 的模型上、SFT 学到的控制器迁移到 DPO 模型只需校准强度。对齐从「写进权重、难以撤销」变成「外挂、可版本化、可按需组合」：按任务换控制器而非重训模型，对齐能力可以像插件一样分发。但硬币的另一面是安全属性的改变——外挂控制器可被绕过或卸载，若安全对齐完全依赖推理时调制而非权重改写，其鲁棒性（对抗提示、微调攻击下的稳定性）是尚未验证的开放问题；权重内的对齐与状态级的对齐在威胁模型上并不可互换。

### 与训练期对齐是互补而非替代

论文自己的扩展方向（PPO、GRPO 等强化学习目标训练控制器、蒸馏方法、动态按输入选择干预位置/时机/强度）表明，这条路线的价值不在「取代 DPO」，而在把对齐问题拆成两层：权重层负责能力塑造，状态层负责表达调控与快速迭代。两层可以叠加实验（控制器叠在 DPO 模型上仍有增益即为证据），迭代周期也从「天级重训」缩短到「训练一个小控制器」。对资源有限的团队，这意味着可以先在推理时验证某个偏好目标是否可引导、定位是否稳定，再决定是否投入昂贵的权重训练——控制器成为低成本的对齐可行性探针。

## 实践启示

- **先判断问题类型再选手段**：若基座模型采样数次已能给出正确答案，说明能力已存在，优先考虑推理时干预或控制器这类低成本的「表达修复」，而非直接进入再训练流程；把再训练预算留给真正的能力缺口。
- **干预选位必须有方向性证据**：不要按「激活强度大/影响大」选组件就动手，先用类似 RCM 的对照（正常写入 vs 置零）确认该位置在推动还是抵消目标——方向搞反会把问题放大；且组件作用随输入变化，选位结论要在目标任务的输入分布上重新验证，不能跨任务直接复用。
- **优先 prefill 阶段干预**：能只在提示处理阶段介入就不要逐 token 控制——改缓存状态即可持续影响整段生成，延迟与算力代价最小，也最容易接入现有推理服务（无需改动解码循环）。
- **把控制器当独立对齐资产管理**：与基座权重分开存放、打版本、按任务组合；从 SFT 场景迁移到 DPO 模型时只需校准强度而非重训，参数量 256 起步意味着单卡可负担，适合快速 A/B。
- **评估加一层机制检查**：行为指标达标后，用竞争图类工具复查抵消作用是否残留，避免「输出合规、内部仍在竞争」的模型进入高风险场景；对安全关键应用，机制层面的抵消残留应视为已知风险项记录在案。
- **RAG 知识冲突可走隐状态路线**：当检索资料与参数知识冲突、模型固执己见时，定位并调制冲突相关组件（原文中单头置零即翻转行为）可能比反复改 prompt 更可控，参见 [[concepts/rag-retrieval-augmented-generation|RAG]] 场景下的冲突处理；这在多跳、多源事实生成任务中尤其值得先试。
