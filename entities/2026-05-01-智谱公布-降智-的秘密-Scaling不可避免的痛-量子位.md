## 定位关键Bug

事情是酱紫的——

自从GLM-5发布以来，智谱通过观察用户的大规模Coding Agent推理过程，发现了三类异常现象： ^[raw/articles/2026-05-01-智谱公布-降智-的秘密-Scaling不可避免的痛-量子位.md]

- 乱码输出
  ：内容杂乱无意义；

- 重复生成
  ：模型不断重复输出相同内容；

- 生僻字
  ：出现异常字符。

这引起了团队工程师的警觉，于是说干就干，先是通过本地回放用户反馈，重复运行相同请求数百次，结果始终无法触发异常。 ^[raw/articles/2026-05-01-智谱公布-降智-的秘密-Scaling不可避免的痛-量子位.md]

换言之，模型本身并非根本原因。

在进一步模拟在线环境后，团队尝试调整PD分离比例并持续提高系统负载，异常现象终于得以复现，在每10000个请求中大约能复现出3-5个异常输出。 ^[raw/articles/2026-05-01-智谱公布-降智-的秘密-Scaling不可避免的痛-量子位.md]

这说明，异常现象很有可能出自 高负载下的推理状态管理 ，指向底层推理链路。^[raw/articles/2026-05-01-智谱公布-降智-的秘密-Scaling不可避免的痛-量子位.md]


但同时也引出了另一个问题，线下的复现率仍低于用户线上反馈的频率，这就意味着现有的检测方法存在遗漏或触发条件尚未完全覆盖。 ^[raw/articles/2026-05-01-智谱公布-降智-的秘密-Scaling不可避免的痛-量子位.md]

于是智谱团队继续对异常输出的检测方法进行优化。他们发现 投机采样  （Speculative Decoding）  指标可作为异常检测的重要参考。 ^[raw/articles/2026-05-01-智谱公布-降智-的秘密-Scaling不可避免的痛-量子位.md]

投机采样原本用于提升模型推理性能，它先由小模型生成草稿  （draft tokens）  ，再由大模型验证是否接受这些token，最终能够在不改变输出分布的情况下提升decode效率。 ^[raw/articles/2026-05-01-智谱公布-降智-的秘密-Scaling不可避免的痛-量子位.md]

而在GLM-5的三类异常中，乱码和生僻字的spec_accept_length非常低，也就是说目标模型的KV缓存状态与草稿模型之间存在明显不匹配。 ^[raw/articles/2026-05-01-智谱公布-降智-的秘密-Scaling不可避免的痛-量子位.md]

复读则拥有过高的spec_accept_length，表明损坏的KV缓存可能导致注意力模式退化，将生成过程推向高置信度的重复循环。 ^[raw/articles/2026-05-01-智谱公布-降智-的秘密-Scaling不可避免的痛-量子位.md]

基于以上观察，智谱总结出了一套 在线异常监控策略 ：^[raw/articles/2026-05-01-智谱公布-降智-的秘密-Scaling不可避免的痛-量子位.md]


当spec_accept_length持续低于1.4且生成长度超过128 token，或者spec_accept_rate超过0.96，系统就会主动中止当前生成，并将请求重新交回给负载均衡器。 ^[raw/articles/2026-05-01-智谱公布-降智-的秘密-Scaling不可避免的痛-量子位.md]

紧接着，智谱开始进一步解析异常原因：
PD分离架构下的KV Cache竞态

团队通过分析请求生命周期和推理引擎中的PD分离执行时序，将问题归因于 请求生命周期与KV Cache回收与复用时序之间的不一致 ，从而引发的KV Cache复用冲突。 ^[raw/articles/2026-05-01-智谱公布-降智-的秘密-Scaling不可避免的痛-量子位.md]

为了消除这类竞态情况，研究人员在推理引擎中引入了更为严格的时序约束，会在请求终止和KV Cache写入完成之间建立 显式同步 。 ^[raw/articles/2026-05-01-智谱公布-降智-的秘密-Scaling不可避免的痛-量子位.md]

具体来说，在发出中止指令后，解码阶段会向预填充阶段发送通知。预填充阶段只有在满足以下任一条件时才会返回安全回收信号：未启动任何RDMA写入，或所有先前发出的写入操作已完全完成。而解码阶段只有在收到此确认后才会回收并重用相应的 KV Cache槽位。 ^[raw/articles/2026-05-01-智谱公布-降智-的秘密-Scaling不可避免的痛-量子位.md]

该机制将确保KV Cache写入不会跨越内存复用边界，从而避免跨请求的KV Cache损坏。^[raw/articles/2026-05-01-智谱公布-降智-的秘密-Scaling不可避免的痛-量子位.md]


最终修复该bug后，异常输出的发生率从约万分之十几下降至万分之三以下。^[raw/articles/2026-05-01-智谱公布-降智-的秘密-Scaling不可避免的痛-量子位.md]

HiCache加载时序缺失

此外，当KV Cache换入与计算重叠时，当前实现未能保证数据在使用前已完成加载，导致可能出现 未就绪KV Cache ^[raw/articles/2026-05-01-智谱公布-降智-的秘密-Scaling不可避免的痛-量子位.md]

## 深度分析

### 模型没错，错的是承载模型的系统

本地完整回放用户请求、重复数百次始终无法触发异常，说明三类"降智"症状与模型权重和输入内容无关，只在真实生产负载下出现。真正的触发条件藏在 PD 分离架构的时序里：请求生命周期与 KV Cache 回收复用的不一致引发竞态，异步的 RDMA 写入跨越内存复用边界，把上一个请求的残留状态混进当前请求的注意力计算。智谱把这类教训称为 Scaling Pain，实质是给 [[concepts/scaling-laws|Scaling Laws]] 补上了系统工程维度：能力增长如果没有等量级的服务基础设施支撑，用户感知到的就是"模型变笨了"。^[raw/articles/2026-05-01-智谱公布-降智-的秘密-Scaling不可避免的痛-量子位.md]

### KV Cache 损坏是一类独立的基础设施故障

乱码和生僻字对应目标模型与草稿模型 KV 状态明显不匹配，表现为 spec_accept_length 异常偏低；复读则是损坏的 KV 使注意力模式退化，被推向高置信度的重复循环，表现为指标异常偏高。同一根因在不同症状上把同一个指标推向相反方向，这类"静默状态损坏"既不是 OOM 也不是延迟毛刺，而是伪装成模型质量回退的存储一致性错误——用户与客服都会把它归因到模型层，而修复点其实在 [[concepts/inference-optimization|推理引擎]]。^[raw/articles/2026-05-01-智谱公布-降智-的秘密-Scaling不可避免的痛-量子位.md]

### 检测难在"万分之一"的稀有度与负载依赖

故障是并发时序竞态，不是确定性输入输出关系，所以可复现测试集天然失灵；必须提高系统负载、调整 PD 分离比例才能以约万分之三到五的频率复现，且线下复现率仍低于线上反馈，说明触发条件未被完全覆盖。智谱的破法是把检测从"构造复现用例"转向"统计在线监控"：把本来为加速 decode 服务的投机采样指标改造成异常信号，设定阈值后主动中止并重新排队，相当于用已有的引擎内部指标做了免费的旁路探测。^[raw/articles/2026-05-01-智谱公布-降智-的秘密-Scaling不可避免的痛-量子位.md]

### 修复在服务栈，能力 SLO 必须覆盖推理链路

最终修复没有动任何模型权重：一处是在请求终止与 KV 写入完成之间建立显式同步、确认后才能回收槽位；另一处是重构 HiCache 读取流程，在加载与计算之间插入同步点消除 read-before-ready。异常率从约万分之十几降到万分之三以下。对服务商的启示是：输出质量需要作为一条独立的 SLO 沿推理栈监控，否则模型迭代的收益会被基础设施的静默损坏吃掉。^[raw/articles/2026-05-01-智谱公布-降智-的秘密-Scaling不可避免的痛-量子位.md]

## 实践启示

1. 遇到"降智"类反馈先回放原始请求排除模型因素，再模拟在线负载（加压、调整 PD 分离比例）去复现，而不是急着回滚模型版本。
2. 把 spec_accept_length、spec_accept_rate 等引擎内部指标接入线上告警：持续偏低指向 KV 不匹配，异常偏高指向复读退化；命中阈值即主动中止生成并把请求交回负载均衡器。
3. 在推理引擎中为"请求终止 → KV 写入完成 → 槽位复用"建立显式同步与确认信号，异步写入（如 RDMA）必须确认全部完成后才允许内存复用。
4. 分层存储/换入换出路径要消除 read-before-ready：在计算启动前插入加载同步点，确保数据就绪后才进入 Forward 计算。
5. 长上下文 Coding Agent 场景应把 Prefill 当作主要瓶颈做容量规划（KV 分层存储、广播与计算重叠等吞吐优化可与质量修复并行推进）。
6. 面向用户建立"宁可重排、不吐乱码"的熔断策略：单请求延迟换输出质量，同时把异常率纳入服务商对外承诺的质量指标。
