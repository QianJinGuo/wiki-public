# 苹果LensVLM：长上下文压缩成图片，模型边看边「放大」

## 核心机制

苹果基础大模型团队与杜克大学提出的 LensVLM 解决长上下文压缩的单行道问题：多数压缩方案在压缩后就无法回头查阅原文，细节一旦被摘要丢掉就找不回来。LensVLM 把「定位证据」与「读取证据」分成两步——模型先浏览覆盖全文的压缩页面（文字渲染成图像，以更少的视觉 token 承载全文），再针对与问题相关的页面调用 `read_page` 展开工具取回原文并加入上下文；证据不足时可继续选下一页，相当于给模型一个可反复使用的「放大镜」。 ^[raw/articles/苹果lensvlm长上下文压缩成图片模型边看边放大.md]

## 关键数据

- 七项文本问答评测：**4.3× 有效压缩**下平均准确率 **68.9%**，接近完整文本参照的 **72.4%**。
- 基线对比：基础模型直接阅读 5× 压缩图像仅 **31.3%** 准确率——证明纯压缩（无展开机制）会被视觉编码器辨识能力卡死，字符压得越小越难辨认。
- 压缩率可通过字号、页面尺寸、文字密度调节，无需重设文本词表。

## 与 DeepSeek-OCR 路线的对比

DeepSeek-OCR 展示了「图像承载文字」的同一大方向，但压缩页面清晰度是瓶颈——压得太狠答案在页面上模型却看不清。LensVLM 的增量在于承认压缩有损，用 agentic 工具调用（选页 → read_page → 继续选页）补回被压缩掉的细节，形成「压缩保全文覆盖 + 展开保细节精度」的双层结构。 ^[raw/articles/苹果lensvlm长上下文压缩成图片模型边看边放大.md]

## Agent 长程任务意义

Agent 执行长程任务时，代码、工具输出和交互记录不断累积，上下文管理面临「压缩省 token vs 丢失后续关键线索」的两难。LensVLM 的选页-展开循环给出一种可迁移模式：压缩层负责广度（全文都在视野内），工具层负责深度（按需取回原文），与 [[concepts/context-management-agent-systems|Agent 上下文管理]] 中的工作集分层思路互补，也为 [[concepts/context-window-economics|上下文窗口经济学]] 提供了新的压缩率-准确率数据点。该工作已被 NeurIPS 2026 接收。 ^[raw/articles/苹果lensvlm长上下文压缩成图片模型边看边放大.md]

## 深度分析

### 压缩成图片的底层机制：用视觉 token 换文本 token

LensVLM 的出发点是一个账本问题：语言模型把文字拆成文本 token，视觉语言模型则由视觉编码器把图像转成视觉 token。当一页图像容纳足够多的文字时，表示它所需的视觉 token 数就可能低于直接输入原文的文本 token 数。压缩率因此成为可调节的渲染参数——字号、页面尺寸、文字密度三者都能改变每页承载的文字量，且全程无需重设文本词表。与「先检索少量片段再阅读」的路线相比，压缩图像的价值在于覆盖全文：分散在不同位置的证据仍有机会进入模型视野，而不是在检索阶段就被过滤掉。

代价同样明确：字符越压越小，可能超出视觉编码器的辨识能力，甚至在像素层面无法区分。基础模型直接阅读 5 倍压缩图像的平均准确率仅 31.3%，说明纯压缩存在一个由视觉编码器决定的辨识上限——压得越狠上限越低，与词表无关。

### 定量结果：从 31.3% 到 68.9% 的三级跳

训练分两段：以 Qwen3.5-9B-Base 为底座，先筛选出它无法直接答对的样本，让 Qwen3.5-397B 根据问题、真实证据和标准答案生成工具使用轨迹，用监督微调学习其中的推理、选页与回答；随后以 DAPO 强化学习优化模型自己生成的轨迹，奖励以答案正确性为依据，只有答对时使用工具才加分。

结果呈三级跳：5 倍初始压缩下，直接读图 31.3% → 监督微调 63.7% → 强化学习 68.9%，有效压缩 4.3 倍，接近完整文本参照的 72.4%。压到 15 倍时基础模型读图跌至 18.1%，LensVLM 仍有 52.1%——选页后展开阅读显著缓解了高压缩下的准确率崩塌。计入展开开销后，5×/10×/15× 三个初始设置对应的有效压缩率分别为 4.3×、7.4×、10.1×。

效率数据同样关键：32K–140K token、15 倍压缩设置下，全文输入端到端延迟 3.62 秒，LensVLM 为 2.83 秒，页面离线预渲染缓存后进一步降至 2.52 秒（约减 30%）；峰值 KV 缓存约为全文输入的十四分之一，饱和并发下预缓存版本吞吐约为全文输入的 3.7 倍，按每 GPU 小时 6 美元估算，每千次请求的 GPU 服务成本降低约 73%。

### 边看边放大：选页-展开-再选页的渐进阅读

LensVLM 把「定位证据」与「读取证据」拆成两个动作：模型先接收问题和全部压缩页面，选择值得细读的页，调用展开工具（纯文本渲染的页面返回对应原文并加入上下文）；读完若证据不足，继续选下一页。Demo 中一道题要求指出电影《Kiss and Tell》中饰演 Corliss Archer 的女性担任过的政府职务，模型面对 15 张压缩页面选中第 10 页、调用 read_page 取回原文，答出「美国礼宾司司长」。「放大镜」的前提是系统必须保留原文或原始图像——压缩页面供浏览全文，展开内容补回细节，缺一不可。而「该选哪页」并不是接上工具就自动具备的能力，它靠上述 SFT+RL 流程训练得到。

### 对 Agent 长上下文工作流的含义

Agent 执行 [[concepts/long-running-agent-architecture|长程任务]] 时，代码、工具输出和交互记录不断累积，压缩省 token 与保留后续关键线索始终是两难。LensVLM 给出的可迁移模式是：压缩层负责广度，工具层负责深度，模型的阅读预算按当前问题动态分配。两点工程约束值得注意：其一，收益要用「有效压缩率」度量——原文 token 除以压缩图像与展开内容合计的输入 token，初始压缩率不计展开开销会系统性高估收益；其二，展开形式要随内容类型选择，原生 PDF 含表格、图形与布局，MMLongBench-Doc 上 15 倍像素缩减下高清页面展开（41.9%，10.3 倍有效压缩）明显优于 OCR 文字展开（32.1%）和直接读压缩页（31.1%）。该方案的优势区间是长文档与可复用页面图像的多次查询，短上下文中直接输入全文仍然更快；作者进一步指出，让模型主动分配阅读预算——先粗看什么、细读什么、何时回头查阅——可能成为与扩展上下文窗口同样重要的研究方向。

## 实践启示

1. 任何上下文压缩方案都应保留「回头路」：压缩层负责全文覆盖（广度），展开层负责按需取回原文（精度），与 [[concepts/working-set-vs-long-term-memory|工作集与长期记忆分层]] 思路一致；把压缩当成单行道，后续步骤需要关键线索时将无法补救。
2. 用 [[concepts/context-window-economics|上下文经济学]] 视角度量压缩收益：「有效压缩率」＝原文 token 数 ÷ 压缩图像与展开内容合计输入 token，不要用初始压缩率自欺——计入展开开销后 15× 初始压缩实际只有 10.1×。
3. 纯压缩存在由视觉编码器决定的天花板：字符压得越小越难辨认，5 倍压缩下直接读图仅 31.3% 准确率；压缩设计必须搭配 agentic 展开机制补偿，否则会被编码器辨识能力卡死。
4. 展开形式按内容类型选择：纯文本页返回原文，表格/图形/布局密集的文档返回高清页面；OCR 不是默认最优（32.1% vs 高清 41.9%）。
5. 收益区间要选对：该方案的优势在长文档与可复用页面图像的多次查询场景——页面图像可离线预渲染缓存，换来约 30% 延迟下降、3.7 倍吞吐与约 73% 成本下降；短上下文直接全文更快。
6. 「该读哪页」是可训练能力：先用强模型根据问题与标准答案生成工具使用轨迹做 SFT，再用答案正确性奖励（DAPO）做 RL，能教会模型分配阅读预算，而不只是给它一个工具。
