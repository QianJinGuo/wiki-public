# ControlFoley：多模态可控视频音效生成（ACM MM 2026，小米）

ControlFoley 是小米集团（共同第一作者杨剑轩、郭新月，通讯作者杨剑轩，武汉大学合作）提出并已被 ACM MM 2026 接收的多模态可控视频音效（Foley）生成模型，论文、代码与模型权重均已开放。它要解决的核心问题不是「视频能不能自动配出声音」，而是「用户不想要这个声音时，能不能告诉模型换一种」——把视频动作、文本提示与参考音频都变成可用的控制条件，让生成音效既跟得上画面，又贴近创作者想要的语义与风格。^[raw/articles/controlfoley-controllable-video-sound-generation-xiaomi-acm-mm-2026.md]

## 控制条件的角色分工

ControlFoley 的关键设计理念是让不同条件「各司其职」，而不是简单拼接：视频主要负责约束动作节奏与发声时刻，文本负责补充或改写声音语义，参考音频负责提供音色与质感，同时抑制其时间结构被一并复制。围绕这一点，模型采用三项关键设计：联合视觉编码（CLIP 对齐语义 + 自研时空音视频编码器 CAV-MAE-ST 强调动作变化与音画时序）以增强视觉语义与时序表征，并缓解文本控制中的视文语义冲突（抑制视觉条件对文本指令的过度主导）；参考音频的时间-音色解耦，保留音色与质感、抑制不应迁移的节奏结构；多模态 Transformer 统一生成与鲁棒训练（随机模态丢弃 + REPA 表征对齐），使同一套模型兼容基础视频配音、文本辅助、文本控制、参考音频控制与纯文本音效生成。^[raw/articles/controlfoley-controllable-video-sound-generation-xiaomi-acm-mm-2026.md]

## 评测：可控性与同步性的取舍

ControlFoley 的评测围绕「声音是否符合语义、是否贴合画面、是否与动作同步、音频质量是否稳定」展开，指标包括 CLAP（音频-文本语义匹配）、DeSync（音画时间偏移，越低越好）、IS（音频质量），参考音频控制任务额外比较音色相似度。在基础视频配音评测中，ControlFoley 在 VGGSound-Test、Kling-Audio-Eval 与 MovieGen-Audio-Bench 三个测试集上相对最佳开源基线同时提升语义对齐、音画同步与音频质量；在可控任务上，当文本与视频冲突增强时仍能更稳定地跟随文本意图，使用参考音频时能迁移声音风格而不照搬其时间节奏。^[raw/articles/controlfoley-controllable-video-sound-generation-xiaomi-acm-mm-2026.md]

## 生态与部署入口

项目的工程化程度较高，覆盖从快速体验、可视化创作到研究复现与本地部署的不同需求：零部署在线体验（项目主页 Demo / Hugging Face Space）、创作者工作流（官方 ComfyUI 节点与全任务工作流）、智能体快捷调用（通过 Skill 接入 Agent 工作流）、开发者本地部署（GitHub + Hugging Face 官方 Python 实现，或社区 audio.cpp 的原生 C++ 推理与 GGUF 模型）。技术报告见 arXiv:2604.15086，代码见 github.com/xiaomi-research/controlfoley。^[raw/articles/controlfoley-controllable-video-sound-generation-xiaomi-acm-mm-2026.md]

## 深度分析

### 条件角色分工：可控生成的真正难点

视频到音频生成从「能不能出声」演进到「能不能听话」，关键瓶颈不在模型容量，而在条件之间的语义协调。ControlFoley 的设计哲学是把三类条件视为互补而非冗余的信息源：视频天然携带事件时序与动作节奏，适合回答「何时发声、发生了什么」；文本擅长表达抽象语义与创作者意图，适合回答「声音应该是什么」；参考音频则承载难以用语言精确描述的音色与质感细节。若把三者简单拼接后送入模型，后果是条件互相干扰——视觉惯性压制文本指令，参考片段的节奏污染输出时序。显式建模每类条件的角色边界，是这类多条件可控系统区别于早期「单条件端到端」工作的核心思路，也解释了为什么同一模型能同时服务五种任务组合。更进一步看，这种角色分工其实回应了一个普遍的工程直觉误区：条件越多越好。事实上，没有边界意识的多条件输入会让模型在训练中学习到错误的因果关联，推理时产生模态之间的「话语权」竞争；而 ControlFoley 把「谁负责什么」写进架构设计，等于把先验知识显式注入模型，降低了学习难度，也让失败更可归因——当输出不符合预期时，可以定位到具体是哪一类条件没有发挥其角色功能。

### 视文冲突与联合视觉编码

文本控制场景存在一个隐蔽的失败模式：当提示词与画面内容冲突（例如安静画面却要求雷击声）时，视觉特征往往在生成过程中占主导，导致文本指令被事实性忽略。ControlFoley 用双路视觉编码缓解该问题——CLIP 提供与文本空间语义对齐的视觉表征，自研的 CAV-MAE-ST 补充动作变化与音画时序信息；在此基础上进一步显式抑制视觉条件对文本指令的过度主导。这一组合让模型既能贴住画面节奏，又能在冲突时服从文本改写声音语义。评测显示随文本-视频冲突增强仍保持更强的文本-音频对齐，说明该设计在分布压力下依然有效，而非只在常规场景占优。值得注意的是，这种「冲突时听谁的」能力对实际创作意义重大：创作者往往正是利用冲突来表达画面之外的意图——无声画面需要想象中的声音、画面情绪需要声音反衬。如果一个模型只能在画面与文本一致时表现良好，它的「可控」只是附属于画面的次要通道；只有当文本成为真正独立的语义控制轴时，创作自由度才发生质变。

### 时间-音色解耦：避免「控制即复制」

参考音频控制最自然的失败方式是把参考片段整段照搬：音色对了，但事件节奏与画面动作错位。ControlFoley 对参考音频做时间-音色解耦，保留音色、质感等可迁移属性，同时抑制节奏、发声时刻等应随视频重算的时间结构。这与视频生成领域「参考图控制外观而非构图」的思路同构，暗示多模态可控生成正在收敛出一条通用方法论：把参考信号分解为「该迁移的」与「该重算的」两个子空间，分别施加不同约束。评测中音色相似度与同步性的双达标，正是这种解耦的直接证据。对下游使用者而言，这意味着选择参考素材的标准从「找一段节奏合适的录音」简化为「找一段音色合适的录音」，素材准备的门槛大幅降低。

### 统一训练与部署生态的工程策略

多任务统一带来两个层面的收益。训练层面，随机模态丢弃让同一模型在任何条件组合（含条件缺失）下都能稳定工作，避免为每种组合单独训练或在推理时切换模型；REPA 表征对齐提升训练效率与中间表征质量。部署层面，项目同时覆盖在线 Demo、Hugging Face Space、官方 ComfyUI 节点、Agent Skill 接入、官方 Python 实现以及社区 audio.cpp 的 C++/GGUF 推理——这种全链路开放策略把学术成果直接转化为创作者可用的工具，GGUF 量化路径更让消费级硬件本地运行成为可能，是开源模型生态运营的可借鉴样本。

## 实践启示

1. 给视频配音前先明确控制意图：只求音画同步就用基础配音；需要改写声音内容再叠加文本控制——文本与画面冲突越强，越考验模型对文本的服从能力。
2. 用参考音频迁移音色时，挑「质感接近、节奏不同」的参考片段即可；模型已解耦时间结构，不必刻意寻找节奏匹配的参考素材。
3. 制作 AI 视频、漫剧或广告时，直接采用官方 ComfyUI 全任务工作流做可视化调音，用文本提示指定魔法、打斗、转场等语义，减少后期返工。
4. 在智能体管线中通过 Skill 接口调用 ControlFoley，可把「生成视频 → 自动配音 → 文本微调」串成无需人工交接的自动化流水线。
5. 本地部署优先考虑 audio.cpp 的 C++/GGUF 路径以在消费级硬件上推理；研究复现与二次开发则走 GitHub/Hugging Face 的官方 Python 实现。
6. 评估可控音效生成时，应同时检查语义匹配（CLAP）、音画偏移（DeSync）与音色相似度三个维度——只看单项会漏掉「可控但不同步」或「同步但被画面主导」的隐性失败。

## 意义

ControlFoley 代表了多模态音视频生成中「从自动补全到可控生成」的一步：把控制条件显式建模为语义/时序/音色三个正交角色，并为参考音频做时间-音色解耦，避免「控制即复制」的常见失败模式。它与音频基础模型 [[entities/cvpr-2026-highlight-清华打破多模态音频生成的通才困境omni2sound-音频基础模型开源|Omni2Sound]] 的「通才化」路线互补，也与 [[entities/ard-agentic-autoregressive-diffusion-for-long-video-consistency|ARD 长视频一致性]] 这类「先保证时序一致、再谈控制」的视频生成工作形成对照：前者解决音频侧可控，后者解决视频侧一致。对实际生产链路（AI 视频、漫剧、游戏与广告）而言，可直接落地的 ComfyUI 工作流与 GGUF 部署路径降低了接入成本。^[raw/articles/controlfoley-controllable-video-sound-generation-xiaomi-acm-mm-2026.md]
