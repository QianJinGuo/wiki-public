本论文从大规模生产实践出发，直面云原生时代本地存储的核心矛盾：一方面要追求更低时延与更高吞吐，另一方面必须满足云上多租户、可运维、可演进、可用性保障等工程要求。论文给出了清晰的技术路线图与可验证的体系化经验总结，也标志着阿里云在存储基础设施“软硬一体化”探索上获得了国际学术界的高度认可。 ^[raw/articles/阿里云联合上海交大荣膺-fast26-最佳论文揭秘云上本地存储的演进与未来发展.md]

论文不仅系统阐述了 阿里云本地盘（Local Storage）技术从纯软件到软硬协同的“三代进化史” （以咖啡浓度由低到高命名：Espresso、Doppio、Ristretto），更提出了一种 前瞻性的端云融合存储架构——Latte 。该架构通过基于机器学习的 IO 调度（ML IO Dispatcher）与cache准入控制技术（Admission Controller），在更轻量的系统开销下实现 更稳定、更接近“极致”的时延与吞吐体验 。在 AI 大模型推理等新兴场景中， Latte 可构建高性能、大容量、高性价比的弹性缓存层 ，有效降低 GPU 等计算资源消耗，提升推理效率与响应速度，为云原生与 AI 负载提供了兼顾性能确定性与资源效率的新工程范式。 ^[raw/articles/阿里云联合上海交大荣膺-fast26-最佳论文揭秘云上本地存储的演进与未来发展.md]

## 深度分析

### 三代本地盘演进：每一次架构调整都是对上一代瓶颈的回答

Espresso→Doppio→Ristretto 的“咖啡浓度”进化史，本质上是一条围绕瓶颈点做架构级调整的取舍链：Espresso 用用户态轮询架构（SPDK）榨干 NVMe 性能，代价是 CPU 效率与裸金属支持；Doppio 借 ASIC DPU 卸载虚拟化，换来隔离性与交付能力，但硬件固化追不上 SSD 的快速迭代，也难以承载复杂云特性；Ristretto 则以 ASIC + ARM SoC 软硬协同收束这条链——数据面保留硬编码的高性能路径，控制面交给可编程的 FTL 与卷管理，既逼近物理盘性能极限，又保住可运维与可演进性。三代演进的深层逻辑是：纯软件方案被硬件卸载取代后，固定硬件又被“硬数据面 + 软控制面”的混合设计取代，每次都是在上代的性能收益与工程代价之间重新划界。 ^[raw/articles/阿里云联合上海交大荣膺-fast26-最佳论文揭秘云上本地存储的演进与未来发展.md]

### Latte 端云融合：本地吸收突发、云端兜底持久

Latte 的架构分工非常明确：本地介质负责“近端、快速、吸收突发与热点”，以 append-only 方式提供微秒级低延迟，规避网络存储的长尾；云端（EBS）负责“持久化、可用性与弹性”，数据最终落在云盘，write-through 模式下即使物理机宕机数据也安全。粘合两者的是两个轻量组件：ML IO Dispatcher 基于 I/O 特征动态预测热点（CPU 开销低于 10%，长尾延迟预测准确率 95.6%，支持在线自适应更新）；缓存管理弃用 LRU、改用对缓存盘写友好（写放大为 1）的 S3-FIFO 淘汰策略，达成约 80% 的读命中。ML 调度 + 准入控制让 Latte 在远低于传统系统开销的前提下拿到确定性的时延表现。 ^[raw/articles/阿里云联合上海交大荣膺-fast26-最佳论文揭秘云上本地存储的演进与未来发展.md]

### 对 AI 推理存储与 KV-cache 分层的启示

大模型推理场景下，KV-cache、模型权重与中间激活对存储的要求正是“低时延 + 大容量 + 高性价比”三者的组合——这与 Latte 的分层设计一一对应：热 KV-cache 留在本地 NVMe（微秒级），冷数据与持久副本下沉到 EBS（弹性 + 高可用），ML IO Dispatcher 预测 decode 阶段的访问热点并提前调度。论文明确指出 Latte 可为 AI 推理构建高性能、大容量、弹性缓存层，降低 GPU 等昂贵计算资源的等待消耗。相比单机堆缓存或纯云端对象存储，端云融合让 GPU 不必为长尾 I/O 买单，这是资源效率层面的结构性收益。 ^[raw/articles/阿里云联合上海交大荣膺-fast26-最佳论文揭秘云上本地存储的演进与未来发展.md]

## 实践启示

1. **架构演进要盯瓶颈点而非追新硬件**：三代本地盘的每次换代都源于上一代的具体短板（CPU 效率 → 硬件固化 → 可编程性缺失），评估新技术时先问它解决了谁的哪个瓶颈。
2. **软硬协同的正确姿势是“硬数据面 + 软控制面”**：性能关键路径固化在 ASIC，变化频繁的策略（FTL、卷管理）留在可编程 SoC——把这两层放错位置，要么性能受损要么迭代停滞。
3. **长尾延迟靠“本地吸收 + 智能分流”而非单纯堆硬件**：ML IO Dispatcher 用低于 10% 的 CPU 开销换来 95.6% 的长尾预测准确率，说明轻量 ML 调度是长尾问题的性价比解法。
4. **缓存淘汰策略要匹配介质特性**：S3-FIFO 相比 LRU 对缓存盘写友好（写放大为 1）且命中率更高，做分层缓存时淘汰算法的选择应考虑底层介质的写放大代价，而不仅是命中率。
5. **本地盘的容量与可用性短板应交给云端兜底**：write-through + EBS 持久化让本地存储获得云级弹性与故障恢复，本地盘不再是“资源孤岛”。
6. **AI 推理基础设施应把存储分层纳入设计**：KV-cache 热/冷分层（本地 NVMe + 云盘）能直接降低 GPU 等待时间，是比单纯扩 GPU 更便宜的推理优化路径。 ^[raw/articles/阿里云联合上海交大荣膺-fast26-最佳论文揭秘云上本地存储的演进与未来发展.md]
