## 摘要

香港大学数据科学实验室（HKUDS）2026 年 2 月开源的 nanobot 在 30 天内收获 28500+ Star、发布 8 次大版本，而核心代码只有 3935 行（对比 LangChain 核心代码 43 万行），文章逐一拆解其设计决策 ^[raw/articles/2026-06-16-4000行代码撑起一个Agent框架-nanobot架构深度解析-高可用架构.md]。整体架构的决定性特征是控制面完全集中在 AgentLoop 的一个 while 循环里（默认 40 次迭代）：没有 Chain/LCEL 编排层、没有 DAG、没有显式 PLAN 步骤，可理解性最大化但定制点有限 ^[raw/articles/2026-06-16-4000行代码撑起一个Agent框架-nanobot架构深度解析-高可用架构.md]。几个有代表性的取舍：错误响应不持久化到 session history 以防"400 中毒循环"、工具结果入历史截断为 500 字符控制上下文增长、错误恢复全部委托给 LLM（只追加一句引导提示）；Skill 系统用 Markdown 文档教 LLM 使用已有 CLI 工具，通过 XML 索引 + read_file 实现文件系统懒加载（确定性、可审计、零额外成本，但 skill 数量极大时有上下文天花板）；记忆系统坚持"grep beats RAG"，只用 MEMORY.md 与 HISTORY.md 两个文件不用向量库 ^[raw/articles/2026-06-16-4000行代码撑起一个Agent框架-nanobot架构深度解析-高可用架构.md]。Subagent 通过消息总线重新注入结果通知（无需结果传递协议），MCP 工具被包装为带命名空间前缀的原生 Tool；文末提炼了五个可迁移架构模式并给出适用/不适用场景 ^[raw/articles/2026-06-16-4000行代码撑起一个Agent框架-nanobot架构深度解析-高可用架构.md]。

## 关键要点

- 核心极简：ReAct 循环约 20 行——调 LLM、有 tool_calls 就执行并把结果 append 回 messages、无 tool_calls 即为最终答案 break，所有决策路径穿过同一个 while 循环；Tool 接口最小约束是 execute 返回值强制为 str，接口绝对统一，代价是结构化数据要内部序列化、JSON Schema 需手写（LangChain 的 @tool 装饰器可从类型注解自动生成）
- Skill 分工原则：需要执行 Python 逻辑/直接调 API 用 Tool；包装已有 CLI 工具（如 gh CLI）、无 Python 经验扩展能力用 Skill；skill frontmatter 的 metadata.bins 通过 shutil.which 检查依赖是否存在
- 记忆整合：unconsolidated_messages 达到 100 时异步触发（独立 asyncio.Task 不阻塞主流程），由 LLM 决定写什么进 MEMORY.md（长期事实，每次注入 system prompt）和 HISTORY.md（对话摘要，LLM 用 exec grep 按需搜索）
- Subagent 能力约束：没有 message 工具、没有 spawn 工具（防递归）、最多 15 次迭代（主 agent 40 次）、无 memory/history；结果以 InboundMessage 形式重新注入消息总线
- 适用场景：个人自托管 AI 助手接入多聊天平台（支持 13 个 channel）、快速原型、学习 agent 框架最小实现；不适合精确多 agent 协调、大规模历史记忆、生产环境安全隔离（exec 工具黑名单不够）
