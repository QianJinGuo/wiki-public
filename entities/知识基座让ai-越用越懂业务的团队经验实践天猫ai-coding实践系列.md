## 深度分析

### 什么是"知识基座"：从超级个体到超级团队

文章的出发点是：AI Coding 工具催生了大量 5X-10X 效率的"超级个体"，但他们的方法论、工作流和 Skills 沉淀锁在个人本地配置里，无法复制给团队。天猫三个业务域的"后端全栈"试点中，同样的问题有人 5 分钟解决、有人花 2 小时——差距不在能力而在经验是否被沉淀。Cursor/Claude 的 Memory 解决的是"个人上次说过什么"，团队需要的是"团队积累了哪些经验"。文章的公式：超级团队 = 超级个体 × 知识共享 × 智能沉淀，这与 [[concepts/ai-team-knowledge-harness|团队知识基座]] 的思路一致——把 harness 从个人工具升级为团队基础设施。

### 信号驱动沉淀：只捕获 1% 的"踩坑现场"

核心洞察是反直觉的：99% 的会话是简单问答没有沉淀价值，真正的知识藏在 1% "出了问题"的会话里。系统通过关键词信号（报错、否定表达）和行为信号（反复编辑同一文件、工具调用密集、读后搜索）识别踩坑现场，定时任务按仓库+分支聚合候选会话，再由 LLM 提取三类知识：pitfall（踩坑修复）、decision（方案选型）、faq（高频问答），并带五维质量评分——高分直接入库、低分深度审核。单月自动沉淀近 150 条有效经验，pitfall 占 51%。真正的隐性经验有明确边界：特定场景 + 边缘情况 + 官方文档不会涵盖——组件基础用法被反复问到，说明该补组件文档，而不是往经验库堆。

### 云端统一下发与业务域隔离：配置跟仓库走

区别于本地工具的核心基建是云端配置下发：通过仓库的 Git Group/Repo 自动匹配业务域，下发 agent.md、mcp.json、domain.yaml 和 Skills 技能包，打开仓库即自动拉取，初次配置从约 30 分钟变为 0。知识存储按业务域物理隔离，避免不同技术栈业务线之间的知识污染；加载策略分层：基础知识全局加载，专项知识通过 MCP Server 按需语义检索，避免上下文污染。这个"配置跟仓库走、不跟人走"的设计与 [[concepts/model-context-protocol-mcp|MCP]] 生态的标准化思路互为补充。

### 多来源汇聚、分层架构与召回演进

知识获取不只靠自动沉淀，文章提出"知识的源头在哪里，就从哪里获取"：基建知识通过 MCP Server 对接内部资产中心，由组件负责方官方维护，避免各业务域重复建设导致版本冲突；缺文档的历史组件用 LLM 从源码自动提取文档。知识分三层管理——组件/平台知识（平台对接）、业务领域知识（人工编写）、实践经验知识（AI 捕获+人工 review），经验库不应充斥本该属于官方文档的内容。召回侧当前用关键词检索，正向 [[concepts/rag-retrieval-augmented-generation|RAG 向量检索]] 迁移——知识沉淀的价值随规模加速释放，量变带来质变。运营理念随消费者而变：从面向人（精挑细选）转向面向 AI（大量沉淀、召回时自动筛选），先看"量"再优化"准"。这正是 [[concepts/knowledge-base-output-flywheel|知识库输出飞轮]] 的工程化实例。

## 实践启示

1. **只沉淀关键事件，不做全量记忆**：99% 的会话没有沉淀价值，用信号识别（报错、否定、多轮调试）锁定 1% 的踩坑现场，用 1% 的会话提炼 90% 的价值。
2. **知识库的消费者变了，运营策略要跟着变**：面向 AI 的知识库不需要人工精选的精简，可以大量沉淀、靠召回时自动筛选，再用评测机制验证召回有效率——先有量，再优化准。
3. **配置必须跟仓库走，而不是跟人走**：按 Git Group/Repo 自动匹配业务域下发配置，配合业务域物理隔离，才能在碎片化仓库生态中做到零配置开箱即用、避免知识污染。
4. **知识的源头在哪里，就从哪里获取**：基建知识对接平台方维护（自动随版本更新），业务知识由业务域负责人维护，实践经验靠 AI 自动捕获——别把所有知识塞进一份会过时的人工文档。
5. **经验库要有清晰的边界和反馈闭环**：官方文档该覆盖的不进经验库；某类问题在经验库反复出现，本身就是上游文档或规范需要完善的信号。
6. **知识沉淀的速度必须匹配代码生产的速度**：90%+ 代码由 AI 生成而知识库仍靠人工维护——AI 写代码快 10 倍、废弃也快 10 倍，终极方向是让 AI 不仅生成代码，也自动沉淀和路由知识。
