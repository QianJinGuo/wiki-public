# 大模型的下一个阶段，不是让模型“想得更久”，而是让模型“为了行动而思考”

林俊旸（Junyang Lin）新的文章：大模型的下一个阶段，不是让模型“想得更久”，而是让模型“为了行动而思考”。 ^[raw/articles/大模型的下一个阶段不是让模型想得更久而是让模型为了行动而思考.md]

林俊旸是阿里通义千问（Qwen）团队前技术负责人。2026 年 3 月刚刚离职。他直接领导了 Qwen3 的开发，经历了推理模型融合的实际困难，离开之后发了一篇长推文回顾这段历程，标题叫《从“推理”思维到“智能体”思维》。 ^[raw/articles/大模型的下一个阶段不是让模型想得更久而是让模型为了行动而思考.md]

【1】o1 和 R1 到底教了我们什么

第一波推理模型教会了一件事：如果要在语言模型上做强化学习（RL），就需要确定性强、稳定可扩展的反馈信号。数学、代码、逻辑这些可验证领域变成了核心阵地，因为奖励信号比通用偏好标注强得多。RL 可以针对“正确性”优化，而不是优化“听起来是不是合理”。 ^[raw/articles/大模型的下一个阶段不是让模型想得更久而是让模型为了行动而思考.md]

基础设施也变成了核心问题。一旦模型被训练去做长链条推理，RL 就不再是微调之后的轻量附加步骤，而是一个系统工程问题：大规模采样（rollout）、高吞吐验证器、稳定策略更新、高效调度。OpenAI 把 o1 定义为用 RL 训练的推理模型，DeepSeek R1 进一步证明了推理式 RL 对基础设施的要求有多高。 ^[raw/articles/大模型的下一个阶段不是让模型想得更久而是让模型为了行动而思考.md]

他的总结：第一个大转变是从扩大预训练，到扩大后训练的推理能力。^[raw/articles/大模型的下一个阶段不是让模型想得更久而是让模型为了行动而思考.md]


【2】真正的难题：合并 thinking 和 instruct^[raw/articles/大模型的下一个阶段不是让模型想得更久而是让模型为了行动而思考.md]


2025 年初，Qwen 团队的图景很完美：理想系统应该统一 thinking 和 instruct 模式，支持可调节的推理力度，甚至让模型自动判断需要多少推理量。 ^[raw/articles/大模型的下一个阶段不是让模型想得更久而是让模型为了行动而思考.md]

Qwen3 是最清晰的公开尝试。它引入了“混合思维模式”，在同一模型家族里同时支持思考和非思考行为，强调可控的思维预算，后训练流水线明确包括“思维模式融合”阶段。 ^[raw/articles/大模型的下一个阶段不是让模型想得更久而是让模型为了行动而思考.md]

但合并比描述起来难得多。难点在数据。

两种模式的数据分布和行为目标差异很大。强 instruct 模型被奖励为直接、简洁、低延迟，高效处理标注、客服、结构化提取这类企业任务。强 thinking 模型被奖励为在困难问题上花更多 token、维持连贯的中间推理、探索替代路径。两个行为画像互相拉扯。合并数据如果不精心筛选，结果是两头都不行：thinking 变得臃肿不够果断，instruct 变得不够干脆还更贵。 ^[raw/articles/大模型的下一个阶段不是让模型想得更久而是让模型为了行动而思考.md]

【注：Qwen3 发布时主打“混合思维模式”，但后续的 2507 更新却把 instruct 和 thinking 拆成了独立模型（包括 30B 和 235B 两个规格）。不是不想合并，是合并之后两头都做不好。这种一手经验在公开文章里非常少见。】 ^[raw/articles/大模型的下一个阶段不是让模型想得更久而是让模型为了行动而思考.md]

在商业部署中，大量客户仍然要高吞吐、低成本的 instruct 行为来跑批处理。分开两条线让团队能更干净地解决各自的数据和训练问题。 ^[raw/articles/大模型的下一个阶段不是让模型想得更久而是让模型为了行动而思考.md]

不过其他实验室选了相反的路。Anthropic 明确支持集成模型理念，Claude 3.7 Sonnet 作为混合推理模型推出，用户可以选择普通响应或扩展思考，API 用户可设定思考预算。GLM-4.5 也定位为混合推理模型，同时支持 thinking 和 non-thinking 模式；DeepSeek V3.1 走了类似方向。 ^[raw/articles/大模型的下一个阶段不是让模型想得更久而是让模型为了行动而思考.md]

林俊旸认为关键在于合并是否有机。如果两种模式只是被塞进同一个权重文件，行为上还是两个生硬缝合的人格，产品体验就不自然。真正成功的合并需要一个平滑的推 ^[raw/articles/大模型的下一个阶段不是让模型想得更久而是让模型为了行动而思考.md]

## 深度分析

### 从扩大预训练到扩大后训练：推理式 RL 改写了游戏规则

o1 与 R1 这波推理模型的真正遗产，是确立了"可验证反馈"在 RL 训练中的核心地位（参见 [[concepts/rlvr-reinforcement-learning-verified-reasoning|RLVR]]）。数学、代码、逻辑之所以成为主战场，不是因为它天然重要，而是因为只有这些领域能提供确定性强、稳定可扩展的奖励信号，让 RL 能针对"正确性"而不是"听起来合理"去优化。更深一层的影响在基础设施：长链条推理一旦成为训练目标，RL 就从微调后的轻量附加步骤，升级为需要大规模 rollout 采样、高吞吐验证器和稳定策略更新的系统工程问题。这意味着竞争壁垒从数据规模部分转移到了工程能力。^[raw/articles/大模型的下一个阶段不是让模型想得更久而是让模型为了行动而思考.md]

### 合并 thinking 与 instruct：不是路线之争，而是数据拉扯的结果

Qwen3 的"混合思维模式"是最清晰的公开尝试，但后续 2507 更新又把两种模式拆回独立模型——这背后的真实原因不是缺技术，而是数据：强 instruct 模式被奖励为直接、简洁、低延迟，强 thinking 模式被奖励为花更多 token、探索替代路径，两种行为画像在同一权重里互相拉扯，合并数据筛选不当就会两头都不行。Anthropic 的 Claude 3.7、GLM-4.5、DeepSeek V3.1 走了相反的集成路线，作者认为关键在于合并是否"有机"——真正成功的形态应该是一个平滑的推理力度光谱，模型自适应地在不同层次间滑动，而不是在二值开关间硬切。这一分歧至今没有定论：集成路线体验好但训练难，分离路线工程干净但把选择成本抛给了用户。^[raw/articles/大模型的下一个阶段不是让模型想得更久而是让模型为了行动而思考.md]

### 思考由任务塑造：更长的推理链不等于更聪明

从 Anthropic 的路线中可以提炼出一个纪律性原则：如果模型对所有问题都用同样冗长的方式推理，问题出在优先级判断——它不知道该何时停下来行动。有效的思考应该由目标任务塑造：做编程时思考服务于代码导航与错误恢复，做智能体工作流时思考服务于长期执行质量，而不是产出漂亮的中间文本。这直接推翻了"堆更多思考 token"的朴素scaling叙事，也解释了为什么 GPT-5 系列激进押注 agentic 能力后，写作质量明显下滑——instruct 与 thinking 的资源拉扯在产品层面留下了代价。这一"边想边做"的思路与 [[concepts/tool-use-reasoning|Tool Use Reasoning]] 一脉相承，也标志着 [[concepts/agentic-engineering-paradigm|Agentic Engineering Paradigm]] 的正式登场。^[raw/articles/大模型的下一个阶段不是让模型想得更久而是让模型为了行动而思考.md]

### 智能体 RL 的瓶颈：环境成为一级研究对象

目标从"解基准测试"变成"解交互式任务"后，RL 技术栈需要大换血。推理 RL 的采样是自包含轨迹、验证器干净；智能体 RL 中策略被嵌入由工具服务器、浏览器、执行沙箱、记忆系统构成的庞大系统，环境本身就是训练系统的一部分。训练与推理必须彻底解耦，否则代码智能体等测试反馈时，推理端卡住、训练端挨饿、GPU 利用率崩塌。更重要的是，环境构建从副业升级为核心竞争力：SFT 时代痴迷数据多样性，智能体时代应该痴迷环境的真实性、覆盖度、反馈丰富度和抗利用性——而 reward hacking 是最难的坎，一旦模型有了工具访问权，它可以在训练中直接查答案、滥用日志、利用环境漏洞，看起来超强实际在学作弊。^[raw/articles/大模型的下一个阶段不是让模型想得更久而是让模型为了行动而思考.md]

## 实践启示

1. 评估模型能力时，不要只看推理链长度或基准分数，要考察它能否判断"何时停止思考、何时开始行动"——过长且均匀分布的推理往往意味着优先级判断有问题。
2. 设计混合推理产品时，优先考虑连续的"推理力度光谱"（用户可设思考预算），而不是简单的开/关二值切换；若工程上难以有机合并，分离式模型是诚实且可行的折中。
3. 做智能体训练或评测时，把环境质量当作与数据质量同等重要的一级投入：检查环境的真实性、覆盖度、反馈丰富程度和抗利用性，有隐藏漏洞的环境会系统性奖励作弊行为。
4. 搭建智能体 RL 基础设施时，从一开始就把训练端与推理端（执行环境）解耦设计，避免"推理端等工具反馈卡住、训练端无完整轨迹可用"的吞吐崩塌。
5. 对有工具访问权的模型保持反作弊警惕：搜索能力可能变成训练中直接查答案，代码智能体可能滥用仓库信息或日志——评估器鲁棒性和反作弊协议是下一个研究瓶颈。
6. 关注架构演进方向：核心智能可能越来越多来自多智能体的组织方式——编排器负责规划路由、专业智能体提供领域深度、子智能体执行窄任务并控制上下文，能力建设从"训练模型"走向"训练系统"（参见 [[concepts/orchestrator-worker-architecture|Orchestrator-Worker 架构]] 与 [[concepts/multi-agent-collaboration-patterns|多智能体协作模式]]）。
