# OpenRSI Index：科研智能体真实训练改进基准

## 深度分析

OpenRSI Index 从真实开源研究项目出题，把已有模型/代码/数据/训练方案交给科研智能体在其上改进——反馈信号瓶颈的正面回应：当模型试图改进模型（RSI），谁来定义真实有效的环境反馈？三个代表任务：改进 Marin 优化器（六档模型 5.5 亿-25.45 亿参数，18432 H100·小时/次）、为 Qwen-122B 生成可验证 RL 任务（20864 H100·小时）、GPIC 视觉生成改进（5815 H100·小时，每候选对同千万张图最多再训一遍）。与刷榜评测的本质区别：任务要求真正运行训练实验，算力以千-万 H100·小时计。 ^[raw/articles/从刷榜到做科研研究员还有多久被-ai超越.md]

### 基准设计：用现实复杂度取代封闭测试题

传统 Benchmark 为了获得稳定、可比较的结果，往往固定环境、缩小任务，把问题压缩成边界明确、答案清晰的测试题，与真实科研中的试错、尺度变化、有限预算和失败实验越来越远。^[raw/articles/从刷榜到做科研研究员还有多久被-ai超越.md:64] OpenRSI Index 的回应不是"把 Benchmark 做得更贵"，而是保留评测中的现实复杂度。^[raw/articles/从刷榜到做科研研究员还有多久被-ai超越.md:62] 它直指 RSI 的反馈信号瓶颈：当模型试图改进另一个模型甚至自身时，谁来定义真实有效的环境反馈——OpenRSI 的答案是把实验边界交给明确的任务环境，让"能否改进人类设计的训练方案"成为可检验的问题，而不是榜单分数。^[raw/articles/从刷榜到做科研研究员还有多久被-ai超越.md:26-30] 整套基准（任务、评测框架、验证工具、运行轨迹）全部公开，失败记录与中间过程同样被视为产出。^[raw/articles/从刷榜到做科研研究员还有多久被-ai超越.md:132-141]

### 任务构造：三条主干跨预训练、后训练与视觉生成

出题方式是从真实世界有影响力的开源研究项目取材，把已有的模型、代码、数据和训练方案交给智能体在其上继续改进，覆盖预训练、后训练与图像生成。^[raw/articles/从刷榜到做科研研究员还有多久被-ai超越.md:45] 三条主干各验一个维度：Marin-Scaling-Ladder 要求把同一套优化器规则用于六档模型（5.5 亿至 25.45 亿参数），检验方法跨尺度后是否仍有效；Qwen-122B-RL-Merge 让智能体生成可验证的 RL 训练任务（同 [[concepts/rlvr-reinforcement-learning-verified-reasoning|RLVR]] 思路），改善 Qwen 在数学、代码等领域的表现；GPIC 从共享模型检查点出发，探索架构、训练目标与训练方案的改进，每个候选方案对同一千万张图像最多再训练一遍。^[raw/articles/从刷榜到做科研研究员还有多久被-ai超越.md:49-53] 三个任务对应三个问题：方法能不能跨尺度成立？Agent 会不会根据反馈组织实验？一次改进能不能被清楚归因？^[raw/articles/从刷榜到做科研研究员还有多久被-ai超越.md:58] 任务面还延伸到新兴开源研究，如 Open-Jev 对应的 Kev 决策架构，以及机器人、检索、推理与底层系统优化。^[raw/articles/从刷榜到做科研研究员还有多久被-ai超越.md:70]

### 评测协议：工作区隔离与双循环独立验收

评估"自我改进"绕不开三问：调参是否暗合了测试集分布？巧合是否放大了微小扰动？重新验收还能否复现？^[raw/articles/从刷榜到做科研研究员还有多久被-ai超越.md:80-84] OpenRSI Index 的关键原则是 AI 的实验工作区与最终验收环境相互隔离：每项任务明确哪些模块允许修改、可调用多少资源、按什么环境验收；原作者方案在同一任务环境重跑作为对照；提交时系统暂停工作区并保存快照，交给新启动的干净评测环境打分——私有测试不交给执行研究的 AI，评测环境中的文件变化也不回传工作区，篡改奖励路径、泄露评测信息、超出预算等硬性违规直接计零分。^[raw/articles/从刷榜到做科研研究员还有多久被-ai超越.md:89-93] 机制上包含两个循环：内循环是研究循环（Agent 在持续存在的 workspace 中改代码、跑实验），外循环是验证循环（每次提交冻结为 snapshot，交给新启动的独立 Judge 重新验收），与 [[concepts/evaluation-harness-design|评估 Harness 设计]] 同构，也与 [[concepts/eval-surface-rotation|评测面轮换]] 的持有测试面思路呼应。^[raw/articles/从刷榜到做科研研究员还有多久被-ai超越.md:97-103] 它不要求 Agent 一次性给出正确答案，允许反复试错，但每次声称的进步必须在一个 Agent 无法控制的环境中继续成立。

### 算力规模与社区协作模式

三个代表任务的单次运行规模达数千至上万 H100·小时：Marin 18,432、Qwen 20,864、GPIC 5,815，且算力消耗发生在真实的训练与试验中。^[raw/articles/从刷榜到做科研研究员还有多久被-ai超越.md:47-53] GPIC 任务公开的实验记录显示智能体反复调整训练方案，并按生成图像与参考图像的特征分布差异（FD-DINOv2，越低越好）继续改进。^[raw/articles/从刷榜到做科研研究员还有多久被-ai超越.md:66-68] 开源定位上，有算力的团队可复用整套基准环境检验已有结果，缺大型集群的小团队和个人可把"AI 改了什么、哪里失败"的记录作为下一次尝试的起点。^[raw/articles/从刷榜到做科研研究员还有多久被-ai超越.md:134-136] 任务供给侧用 RSI-Anything 降低出题门槛：研究者与 AI 对话约一小时即可把自己的课题整理成可运行的 RSI 任务环境，经审阅、复现并被接纳后获邀成为共同作者——同类基础设施还有 [[entities/rsihub-unified-rsi-experiment-benchmark-bytedance-sjtu-berkeley-2026-10-28|RSIHub]]。^[raw/articles/从刷榜到做科研研究员还有多久被-ai超越.md:145-151]

## 实践启示

1. **隔离验收先于能力展示**：评估任何自我改进系统时，把实验工作区与验收环境相互隔离作为硬约束——私有测试永远不交给执行研究的 Agent，评测环境的文件变化不得回传工作区。^[raw/articles/从刷榜到做科研研究员还有多久被-ai超越.md:89-93]
2. **用跨尺度任务检验方法而非点状结果**：一套优化器规则要在 5.5 亿至 25.45 亿参数的六档模型上都成立才算有效，单点最优可能只是尺度巧合。^[raw/articles/从刷榜到做科研研究员还有多久被-ai超越.md:49,58]
3. **给 Agent 实验设硬预算并让违规自动计零**：篡改奖励路径、泄露评测信息、超出预算直接清零，不进入人工裁量，保证不同提交的结果可比。^[raw/articles/从刷榜到做科研研究员还有多久被-ai超越.md:93]
4. **内部记录变好不算进步，独立环境复现才算**：每次提交冻结为 snapshot 交给独立 Judge 重验收，"在自己无法控制的环境中继续成立"是唯一进步凭证。^[raw/articles/从刷榜到做科研研究员还有多久被-ai超越.md:101-103]
5. **公开失败轨迹比只公开成功更有价值**：一次失败不足以证伪一个方向，完整实验记录能帮后来者判断哪些条件值得改变、哪些尝试值得继续。^[raw/articles/从刷榜到做科研研究员还有多久被-ai超越.md:136-141]
6. **把出题权交给领域研究者并用署名激励**：RSI-Anything 的"对话约一小时出题 + 共同作者"模式，是科研社区持续供给真实研究任务的可行路径。^[raw/articles/从刷榜到做科研研究员还有多久被-ai超越.md:145-147]
