# 人形之外：擎羽把“身体”变成具身智能的新变量

> [!contradiction] 参见 [[entities/20种机器人本体通吃蚂蚁新一代vla具身大脑刚刚开源了|蚂蚁 VLA 具身大脑]] 持互补路线——蚂蚁走"通用本体通吃"的 VLA 路线，擎羽走"跨本体基础模型 + 身体参数入上下文"的柔性路线；两派共识是"智能应跨身体复用"，分歧在实现方式（VLA 大模型统一 vs 身体参数化适配）。

## 摘要

量子位 2026-08-12 报道：擎羽科技（FEAGINE，港大机器人学博士彭锐创立）发布 A01/A02/A03 三款绳驱柔性机器人及第一代跨本体基础模型 Fi0。核心主张是 **通用机器人不一定需要通用身体**——人形复用的是人类已建好的物理基础设施，任务边界明确时最高效的身体形态可能完全不同，正如李飞飞「爬树」类比：只面对爬树这一任务的生物，身体形态不会与人类相同。^[raw/articles/人形之外擎羽把身体变成具身智能的新变量.md]

该路线把「身体」提升为可设计的变量：任务意图、物体关系、接触逻辑与目标状态跨身体延续，随身体重组的只是行动；三款本体的长度、节段与自由度递进，被用作可反复验证的 embodiment variation 数据源。^[raw/articles/人形之外擎羽把身体变成具身智能的新变量.md]

## 核心要点

- **柔性具身智能定义**：以可连续形变、可顺应接触的本体为物理基础，把身体的结构参数、实时形态、感知与驱动能力纳入模型上下文，使任务与世界知识跨身体复用、由模型为当前身体生成行动。
- **Fi0 的跨本体主张**：任务意图、物体关系、接触逻辑与目标状态可跨身体复用，只有可达空间、动作维度、路径、构型与动力学结果需随身体重组。
- **三款产品即数据源**：A01 一段 2 自由度／750g／负载 200g；A02 两段 4 自由度／30cm／400g／0.78 m/s；A03 三段 6+1 自由度／50cm／600g／1.17 m/s。同一任务在不同长度与节段下产生不同路径与接触方式。
- **推理时演示学习**：面对训练覆盖之外的任务，人类用 Ego 头环做一次 demonstration，模型将其作为推理时的 skill context 理解对象、任务顺序、关键接触与目标状态，无需重训参数。
- **表示链路与本体建模**：Skill Encoder 把示范转为技能上下文，Cross-view World Encoder 学习跨视角共享世界表示，Embodiment Graph 生成 Body Tokens 描述当前身体（而非用 Robot ID 区分型号），World Dynamics Model 与 MAWA 预测并评估候选未来。
- **工程落地条件**：三款均支持 ROS 1／ROS 2／Python／C++，A02 与 A03 另配套 GUI、MuJoCo 与 SAPIEN。

## 深度分析

### 一、把身体从常量变成变量：适配从训练期搬到推理期

多数具身系统把本体当作先验常量：形态一改就要重新采数、重训练、重部署。擎羽的做法在架构上等价于把适配从训练期搬到推理期——身体参数不学进权重，而是每次前向都能读取的输入条件。代价是需要更强的条件化结构（Embodiment Graph／Body Tokens），收益是新身体不必再付一遍数据与训练成本。柔性本体在此不只是产品特色，而是方法论上的必要装置：只有长度、节段、形态可连续变化，模型看到的才是参数化身体空间而非孤立样本点。^[raw/articles/人形之外擎羽把身体变成具身智能的新变量.md]

### 二、知识分层与它的可检验性

Fi0 的切分很干净：任务与世界的知识可复用，行动随身体变化，这同时给出可检验判据。同一段 skill context 作用在 A01 与 A03 上，模型应保持「方块已被抓住」「任务进入释放阶段」这类物理状态判断一致，差异只出现在轨迹形态、构型与接触时机。跨本体迁移最典型的失败模式，恰是本体条件被忽略、模型退回单一本体先验，表现为可达空间误判或接触力度失控。因此跨视角世界表示与显式本体表示是一件事的两半：前者让经验不绑定相机视角，后者让它不被绑定到某副身体。^[raw/articles/人形之外擎羽把身体变成具身智能的新变量.md]

### 三、柔性本体迫使模型建立「自我状态」维度

刚性机器人可把机械结构视为单次执行中的稳定常量，柔性本体则随动作、负载与接触持续形变，身体状态本身成为世界状态的一部分。于是模型不仅要理解外部环境，还要理解自身此刻正在如何变化。因此行动链路不能只做动作生成：同一目标往往对应对种几何可达但后果不同的构型，需先预测候选动作未来，再按任务进展、成功概率、物理风险与不确定性打分（MAWA）后选动作。柔顺性把「后果评估」从可选模块升级为必要模块。^[raw/articles/人形之外擎羽把身体变成具身智能的新变量.md]

### 四、本体维度可能是一条独立的 Scaling 轴

把本体变化当作系统性数据增广：数据规模、参数规模之外，本体多样性构成一条正交的第三轴，每种长度、节段与组合都是新观测点，用来回答身体变化如何改变行动。其复利效应体现在资产形态：擎羽积累的不是三个 SKU，而是任务、身体与物理世界之间不断扩大的映射关系。边界同样明确：本体越多映射越稀疏，Embodiment Graph 的表达力实际决定跨本体泛化上限；推理时上下文学习承接长尾需求，但不替代训练期的规模化能力建设。^[raw/articles/人形之外擎羽把身体变成具身智能的新变量.md]

## 实践启示

1. **把本体参数做成显式输入，而非隐式部署假设**：跨硬件复用的系统应把拓扑、尺度、自由度、驱动能力与实时形态作为条件化输入，而非用型号标签切换策略。
2. **用「同一任务 × 多种本体」构造评测集**：关键指标不是单一本体成功率，而是同一技能在不同本体上是否保持任务阶段与接触语义一致。
3. **长尾适配前移到推理期，但保留训练期通道**：一次示范即用的上下文学习适合现场长尾任务，前提是基础模型已有足够世界知识。
4. **连续形变本体必须配自状态估计**：身体随负载与接触持续形变时，需把自身形态纳入状态表示，否则后果预测会偏乐观。
5. **人类示范应按「技能载体」而非「轨迹来源」设计**：抽取任务结构、阶段划分、接触事件与目标状态，再由各本体决定如何行动。
6. **警惕单一厂商发布的证据强度**：产品参数与「全球首个量产」等表述来自厂商口径，宜作工程参考而非独立结论。
