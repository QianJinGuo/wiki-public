# SHE 与 SafeEvolve：Agent 安全 Harness–Policy 协同进化

> **Background**：本文档基于上海人工智能实验室联合复旦、上交、港科大、浙大团队先后提出的 SHE（arXiv 2608.09885）与 SafeEvolve（arXiv 2609.02786）两项工作的微信公众号解读整理，聚焦"Agent 安全机制如何从执行失败中持续学习"这一技术路线。

## 核心问题：从静态规则到可进化安全机制

传统 Agent Harness 的安全配置（System Prompt、拦截规则、工具权限）是部署前一次性人工设计，进入开放环境后无法覆盖新网页、新文件、新工具组合暴露的风险；而一次安全失败往往是模型、Harness、工具、记忆与外部环境共同作用的结果，整体改 Prompt 难以定位修复效果、堆拒答规则损害任务能力、重训模型又难以及时进入运行时控制。SHE 与 SafeEvolve 分别从 Harness 与 Policy 两层给出持续改进路径。→ [[raw/articles/上海ai-lab连发两项研究agent安全也能自我进化|原文存档]] ^[raw/articles/上海ai-lab连发两项研究agent安全也能自我进化.md]

## SHE：轨迹驱动的安全 Harness 演化（arXiv 2608.09885）

- **四类可编辑安全组件**：System Prompt（全局安全行为）/ Rule Bank（结构化可复用规则）/ Safety Memory（反复出现但未解决的经验）/ Tool Policy（工具权限与执行边界）——组件化解决安全功能耦合，不同失败路由到不同组件，局部修复不重写整个机制。
- **归因引导的局部演化**：每轮收集完整执行轨迹（上下文、模型响应、工具调用、环境反馈、任务结果），从危害领域、攻击面、失败模式三角度结构化诊断"风险在哪一步出现 / 哪个组件负责 / 如何修改"，只对相关组件局部更新；每个候选更新需通过有效性检查与安全—效用验证，禁止用无差别拒绝换表面安全。
- **细粒度安全边界示例**：应用推荐场景不禁止所有应用任务，而是提炼为"可介绍比较、可给官方下载指引、缺授权不做设备级安装、不把未完成操作说成已完成"。
- **实验**：对比静态 SafeHarness，平均攻击成功率 17.1%→5.5%（约 1/3），攻击条件任务可用性 31.6%→47.6%，未参与演化的 AgentHarm 上危害得分 19.8%→9.8%；学到的安全边界可跨 Agent 模型迁移，无需逐模型重新演化。→ [[raw/articles/上海ai-lab连发两项研究agent安全也能自我进化|原文存档]]

## SafeEvolve：Harness–Policy 协同进化（arXiv 2609.02786）

- **Harness 侧**：从轨迹提炼 Safety Prompt + 分层 SkillBank（通用安全原则 + 任务/工具/失败模式相关的安全操作流程）。
- **Policy 侧两阶段 SFT–RL**：第一阶段 Harness-use SFT 冷启动——在进化 Harness 指导下筛选同时通过安全性与效用验证的成功样本，让模型学会"何时调用哪个安全 Skill、识别不可信内容、区分用户目标与外部诱导、权限不明时暂停确认"；第二阶段 Harness-augmented RL——Verifier 分别检查任务完成、危险行为、工具调用有效性，训练目标是情境化行动（正常任务继续完成 / 有害请求安全拒绝 / 环境注入忽略恶意内容继续原目标 / 权限不明先确认）。
- **闭环结构**：Rollout 产生经验 → Harness 外化经验（可审计、可修改、可回滚的资产）→ SFT 帮 Policy 使用经验 → RL 推动内化 → 新 Policy 产生 On-policy 轨迹反哺 Harness 发现覆盖盲区。
- **实验**：Qwen3.5-4B 上 AgentDojo 攻击成功率 2.37%→0.79%、干净任务效用 59.79%→61.86%；AgentHarm 危害得分 56.45→12.27、安全拒答率 28.98%→83.83%；Qwen3-4B 上 AgentDojo 攻击成功率 13.38%→2.42%、任务效用 44.33%→60.82%。→ [[raw/articles/上海ai-lab连发两项研究agent安全也能自我进化|原文存档]]

## 深度分析

### 安全 Harness 为何必须拆成可编辑组件集

把安全策略写进一段 System Prompt，等于把四类性质不同的约束（价值取向、可复用规则、未定型的经验、能力边界）压进同一个文本载体，代价在第一次要改时就暴露：一段措辞同时牵动全局行为、规则命中与工具可用性，说不清收益来处，也难只回滚其中一项。SHE 的四组件划分不是为了分类整齐，而是给演化循环四个带类型、可单独 diff 的写入口：全局原则缓慢漂移，规则精确增删，记忆承载尚未定型的假设，工具策略直接收缩能力面。缺了第四项最危险——最强的杠杆（工具能否被调用）留在可编辑空间外，模型只能用文本拒答补偿本应由权限阻断的动作，这正是"越改越不敢做事"的结构性来源。 ^[raw/articles/上海ai-lab连发两项研究agent安全也能自我进化.md]

### 归因才是瓶颈：把系统级事故降解为组件级责任

团队往往不缺轨迹，缺的是把轨迹变成责任归属。一次泄露通常由几步串联：外部内容诱导、指令优先级误判、调用权限过大的工具、把未完成状态报成已完成。只看最终回答，任何修改都是猜测。SHE 的诊断把它拆成三个问题——风险出现在哪一步、哪个组件负责、怎样改才降风险且不伤能力——并用危害领域、攻击面、失败模式三个正交维度打标。据此可得判定顺序：模型是否已有足以判断的信息（否则改 Prompt 无用）、规则是否覆盖（否则进 Rule Bank）、该工具是否本不该被允许（否则改 Tool Policy）、失败是否尚未稳定复现（否则先进 Memory）。归因错误比不归因更糟：它会以"已验证"之名把噪声写进资产，故候选更新须绑定来源轨迹 ID 与验证结果。→ [[concepts/ai-safety]] ^[raw/articles/上海ai-lab连发两项研究agent安全也能自我进化.md]

### 效用—安全的真实权衡：全拒最省事也最差

只看攻击成功率，无差别拒绝总能赢；把攻击条件下的任务可用性并列，代价立刻显形——SHE 将这对指标同时从 17.1%/31.6% 推到 5.5%/47.6%，说明原静态配置自身就在损耗正常执行，而不只是"防不住"。应用推荐的四条边界：可介绍比较、可给官方下载指引、缺授权不做设备级安装、不把未完成说成完成。前两条是允许，第三条把禁止面精确收缩到设备级写入这一个动作，第四条与权限无关，管的是陈述真实性——安全边界不只关于能不能做，也关于能不能这样说。这也是 SafeEvolve 显式设四类动作（正常完成、明确拒绝、忽略注入继续原目标、权限不明先确认）的意义：只有做/不做两类动作的系统，遇到"环境注入但目标合法"时只能二选一出错。四类中"先确认"最易被忽略，却正是把不确定性处置权交还用户的出口。 ^[raw/articles/上海ai-lab连发两项研究agent安全也能自我进化.md]

### 外化与内化：可审计资产与不透明策略的分工

外化为 Harness 资产的优点是治理属性：可读、可 diff、可灰度、可回滚，新风险从发现到生效以小时计，且不依赖训练资源。短板同样明确：约束停在模型外部时，模型不理解规则背后的理由，长程任务里常见前几步守边界、后几次调用逐渐漂移，对未覆盖的新型风险也无从判断。Policy 内化的收益是可泛化、能在多步执行中主动维持边界，代价是慢、受训练分布约束、过程不透明。SafeEvolve 先 SFT 冷启动再 RL，顺序不宜颠倒：SFT 让模型获得"有哪些安全 Skill、何时调用"的词汇与格式，RL 才有可探索的策略空间；Verifier 分项检查任务完成、危险行为、工具调用有效性，使奖励落在"该继续时继续"而不只是"该拒绝时拒绝"。其隐含假设是内化会固化边界，但固化的是训练分布内的判断力，分布外风险仍须由外部资产先承接。→ [[concepts/verifier-driven-development]] ^[raw/articles/上海ai-lab连发两项研究agent安全也能自我进化.md]

### 迁移性声明及其边界

"边界可跨 Agent 模型迁移、无需逐模型重演化"是最易被过度引用的结论。其成立有结构性原因：Rule Bank 与 Safety Memory 是自然语言资产、Tool Policy 是配置，载体与权重无关；边界描述的是行为类别而非特定激活。但效果取决于接收方是否有指令遵循能力与相近工具面：同一份 Tool Policy 交给不解析结构化参数的模型等于没写。更实质的限制是环境事实不可迁移——应用商店规则、企业权限模型、敏感字段划分都随部署变化，必须重新归因。合理用法是把迁移当热启动：先搬通用边界，再用新模型自己的 on-policy 轨迹跑一轮归因，专找它独有的漂移模式。→ [[concepts/harness-engineering-framework]] ^[raw/articles/上海ai-lab连发两项研究agent安全也能自我进化.md]

## 实践启示

1. **把 Rule Bank 当代码库管理。** 每条规则独立成条、带 ID、带来源轨迹与验证记录，改动走 review 与 diff；这样才答得出"这条规则为何存在、何时可删"，回归时也能定位是哪次演化引入退化；规则间须标注优先级与冲突顺序。
2. **Safety Memory 做成有人复核的队列，而非自动生效的规则。** 其正确语义是"待定型的假设"：记录复现次数、涉及工具、触发上下文，并设定提升为规则的阈值与过期时间。无人复核的记忆会累积成矛盾先例，污染归因证据。
3. **全轨迹留痕是可归因的前提。** 至少保存上下文摘要、模型响应、工具调用的参数与返回、环境反馈、最终结果，用同一 trace ID 串起。缺任一段，归因就退化为对最终回答的猜测，而回答本身几乎从不包含失败发生的位置。
4. **把"权限或意图不明"定义成一等的系统行为。** 不要留给模型在 allow/deny 间自行权衡：显式实现"暂停并请求确认"，给出待确认动作与影响范围，设定超时后默认拒绝。这一条同时覆盖长程漂移与越权安装。
5. **分离两道验证闸门，并保留 held-out 危害集。** 第一道问"是否真降低了该类失败"（用产生它的轨迹重放验证），第二道问"干净任务是否退化"（效用不得下降）。再留一个未参与演化的外部集监测过拟合，否则演化只会收敛成已知攻击的补丁集。
6. **小步演化：一次一个组件、一次一个候选，可灰度可回滚。** 记录改动前后的指标对，再用新 Policy 的 on-policy 轨迹回灌找覆盖盲区。能力收缩（删工具、降权限）应作最后手段，它用任务成功换安全，代价常被低估。 ^[raw/articles/上海ai-lab连发两项研究agent安全也能自我进化.md]
