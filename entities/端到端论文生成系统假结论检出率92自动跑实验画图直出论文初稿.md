# 端到端论文生成系统 Spark-to-Paper：假结论检出率 92%，自动跑实验、画图、直出论文初稿

Spark-to-Paper 是一套端到端研究论文生成系统，以 13 个可组合技能形式运行在现有编程助手（Claude Code / Codex）内部，**无需单独部署智能体平台或外部编排服务**。从一句研究想法出发，自动完成文献检索、实验设计、实验执行、论文写作、证据驱动结论修订、可编辑论文图生成，直至输出可直接编译的完整 LaTeX 项目。^[raw/articles/端到端论文生成系统假结论检出率92自动跑实验画图直出论文初稿.md]

核心数据：8 个受控课题上引文有效率 99.5%，图形可编辑率 96.4%；对 36 条人为注入假结论，检出率从单遍 14% 提升至 92%，对抗式评审精确率 74%。平均每篇论文 11.9M token、成本 8.1 美元、耗时 3.2 小时。论文 arXiv 2608.11924，已被 Hugging Face Papers 标记为当日第一。^[raw/articles/端到端论文生成系统假结论检出率92自动跑实验画图直出论文初稿.md]

## 要解决的痛点

**工具碎片化**：文献阅读、假设提出、代码编写、实验试错、参数调优散落多平台，各环节产物难衔接，即使使用编程助手也缺少把"从想法到论文"完整串起来的端到端流程。^[raw/articles/端到端论文生成系统假结论检出率92自动跑实验画图直出论文初稿.md]

**科研幻觉**：大模型固有幻觉在复杂长链条科研任务中放大——引用查不到、数字没出处、实验结果与结论相悖时"假装无事发生"，破坏可复现性与严谨性。^[raw/articles/端到端论文生成系统假结论检出率92自动跑实验画图直出论文初稿.md]

## 设计：复用编程助手能力，而非再造平台

直接复用编程助手已有的读文件、代码执行、信息搜索与工具调用能力，把科研过程拆成 **13 个可组合技能**。每个技能只规定任务目标、约束条件、可用工具与交付标准，执行由编程助手根据项目状态自主完成；一条轻量级流水线指定任务顺序。全部技能共享同一项目目录，通过文件化产物协作，前一步输出即后一步输入。**任何一步出问题都可从对应产物继续修改，而非整篇重生成**。^[raw/articles/端到端论文生成系统假结论检出率92自动跑实验画图直出论文初稿.md]

流程：短想法 → 结构化研究提案 → 规划/引文/写作/修订/评审/画图/组装 → 完整 LaTeX 项目（手稿+参考文献+图表+模板配置），可直接编译。组装按目标会议/期刊模板处理章节顺序、引用格式与文档结构，编译后确定性检查确保无未解析引用与 LaTeX 错误。^[raw/articles/端到端论文生成系统假结论检出率92自动跑实验画图直出论文初稿.md]

**实验环节自动完成**：规划阶段预先确定数据集、基线、指标、消融与结果表格结构（数值留空），形成流程内轻量级预注册；写作完成后从论文主张反推缺失证据，在代码与数据可用时自动运行最小实验集，记录日志/指标/表格/图，用实测结果回填正文、重绘结果图，联动修订摘要/引言/结果/结论。^[raw/articles/端到端论文生成系统假结论检出率92自动跑实验画图直出论文初稿.md]

## 核心技术

### 基于技能的模块化流水线

13 技能由输入路由与八阶段组织。输入判断起点并选择结果完整性模式：无实测结果 → 提案模式（数字必须留空）；有实测数据 → 数据感知模式（定量结论须有结果支撑）。**模型负责需要理解与判断的决策，可核验操作由确定性程序完成，各司其职**。^[raw/articles/端到端论文生成系统假结论检出率92自动跑实验画图直出论文初稿.md]

### 预注册式实验设计与证据驱动修订

实验规划与实验报告严格分离：观测前固定数据集/基线/指标/消融/表格结构；实验阶段按需执行最小证据集，昂贵计算或外部数据获取须由具体主张与资源可用性背书。实验后依据实测证据复审手稿，把论点分类为支持/部分支持/未支持/被反驳/需进一步确认，相应保留/弱化/删除/移入局限性/触发补充实验。**阴性、无效或不显著结果予以保留而非省略**，摘要/引言/结果/结论联动更新，确保全文与最终证据一致。^[raw/articles/端到端论文生成系统假结论检出率92自动跑实验画图直出论文初稿.md]

### 完整性检查、长程自省与失败边界

**确定性 Gate**：蓝图结构、引用一致性、记法统一、图文件齐备、LaTeX 编译成功、提案模式下"未观测结果必须留白"等，全部程序判断非模型判断。^[raw/articles/端到端论文生成系统假结论检出率92自动跑实验画图直出论文初稿.md]

**两级模型自省**：自我审查（每次编辑后局部检查论点漂移与一致性）+ 对抗式评审（从理论正确性/实验设计/系统有效性多轮独立审查，每条意见须引用具体段落，从"问题是否真实/是否已别处回答/是否超范围"三维核验，无法反驳才进修订，持续到一轮内无新问题）。^[raw/articles/端到端论文生成系统假结论检出率92自动跑实验画图直出论文初稿.md]

**自我反驳循环**：实验—批评—修订循环上限 7 轮；超过仍无法支撑核心目标则终止轨迹并生成失败报告（记录原始想法/试过方法/实测结果/证据不足原因），从新想法重来。**失败轨迹保留为研究产出，但不包装成成功论文**。^[raw/articles/端到端论文生成系统假结论检出率92自动跑实验画图直出论文初稿.md]

### 可编辑图生成（双路径）

实验结果图读取实测输出、由绘图程序生成原生矢量 PDF，数值与实验结果严格绑定；方法图/解释性图先由图像模型生成视觉草图，再以草图作视觉规范由 Coding Agent 以 HTML 重建文字/形状/连线/布局，渲染对比迭代校准后导出矢量 PDF，重建不可靠时回退栅格图。**生成式模型负责视觉设计，实验结果图完全由数据决定，最终产物保持可编辑**。^[raw/articles/端到端论文生成系统假结论检出率92自动跑实验画图直出论文初稿.md]

## 深度分析

### 复用宿主而非自建平台：能力与约束分层

科研自动化的瓶颈往往不在编排逻辑，而在"能不能真的动文件、跑代码、看结果"——这恰是编程助手已付过代价的部分。于是 13 个技能只写"目标 + 约束 + 可用工具 + 交付标准"，执行权留给宿主，框架只保留顺序与验收。^[raw/articles/端到端论文生成系统假结论检出率92自动跑实验画图直出论文初稿.md:43] 换宿主不必重写流程，只需工具面同构；代价是控制权外移，且上限被宿主工具面钉死——宿主没有的能力，技能写得再细也变不出来。这与 [[entities/thin-harness-fat-skills|Thin Harness, Fat Skills]] 同一取向：编排层薄，能力沉进可独立演进的技能。

### 文件系统当总线：可恢复性来自产物，而非对话

所有技能共享一个项目目录，前一步产物即后一步输入，文献、蓝图、代码、结果、图、修改记录全部落盘。^[raw/articles/端到端论文生成系统假结论检出率92自动跑实验画图直出论文初稿.md:43] 这买到三样东西：任意粒度的重入（只重跑坏掉的那步）、可检查性（Gate 读的是文件，能比对记法与引用、能跑编译，不必相信模型的自我陈述）、可归因（能定位从哪个产物开始偏离）。成本是纪律：稳定命名与结构、上游改动后的失效传播，以及产物全塞进窗口带来的注意力稀释。原文只写到"共享目录"这一层，版本与失效传播未展开，正是复刻时最先踩的坑。

### 预注册把"诚实"降级成可判定的结构约束

防幻觉最有效的动作不是让模型更努力自查，而是把"不许编"翻译成"编了会被脚本发现"。规划阶段先钉死数据集、基线、指标、消融与结果表格结构、数值留空；提案模式下"未观测结果必须留白"由程序判定。^[raw/articles/端到端论文生成系统假结论检出率92自动跑实验画图直出论文初稿.md:61] 机制核心是可检测性的不对称：空单元格脚本能抓，像样的假数字不能——除非真去跑实验。把数字合法性从语义判断降级为结构完整性判断，等于把最难验证的幻觉挪到最易验证的位置。边界也明显：预注册的表格形状可能与真实产出对不上；留白 Gate 只测"没有数字"，测不出"提升显著"这类不带数的定性断言。

### 消融曲线的归因：便宜的部分贡献了大部分

14% → 69% → 81% → 92% 拆开看：确定性 Gate +55pp，自我审查 +12pp，对抗式评审 +11pp。^[raw/articles/端到端论文生成系统假结论检出率92自动跑实验画图直出论文初稿.md:85] 六成以上收益来自不用模型的程序检查，最贵的两层只补尾巴；而 Gate 的失败模式（规则写漏了）可预测、可回归，评审的失败模式是概率性的。另一面是 8pp 残余漏检与 74% 评审精确率：约四分之一意见是噪声，杀伤不在被看到，而在触发无谓修订把对的改错，故需"真实／已答／超范围"三重核验加"无法反驳才修订"——本质是校准服从倾向。还有一项没被测量：误杀。检出率只算抓到多少假结论，不算错杀多少真结论；语义评审的误杀表现为把有效论点移进局限性，指标上看不见。

### 自省的盲区与失败出口

自我审查是编辑后的局部漂移检查，对抗式评审是全局审查且每条意见须锚定具体段落——锚不住的意见多半是通用套话，这是廉价的诚实性过滤器。^[raw/articles/端到端论文生成系统假结论检出率92自动跑实验画图直出论文初稿.md:65-67] 但审查者与被审者是同一基座模型，盲区相关：两边都觉得合理的编造会顺利通过。系统的应对不是让评审更聪明，而是让可核验事实不进入语义争论——结果由代码产出、图由数据绘制、引用由检索校验。分界线由此清晰：能被程序验证的，绝不交给模型投票。7 轮上限与失败报告处理另一类失败——不是"写错"，而是"方向不成立"；失败轨迹留作研究产出而非包装成论文，^[raw/articles/端到端论文生成系统假结论检出率92自动跑实验画图直出论文初稿.md:69] 等于承认"无结论"是合法输出，而这比提高检出率更难，因为它对抗的是产出激励。

## 实践启示

1. **先把判定规则从提示词里搬出来。** 任何能写成"文件存在／字段非空／引用可解析／编译通过"的规则都该做成脚本。提示词里的"不要编造数字"是建议，Gate 里的"未观测单元格必须为空"才是约束。
2. **用产物做接口，让每个阶段可单独重跑。** 一个项目目录、稳定命名的中间产物、每步幂等；并在产物里记录依赖的上游版本，否则上游改了数、下游图还是旧的，全文"一致"地错。
3. **生成前冻结骨架。** 凡要产出主张的任务，先写空槽的表结构与指标定义再让模型填：空槽可检测、编造不可检测，这是把诚实问题工程化的最低成本路径。
4. **评审必须锚定证据，否则先测它的精确率。** 要求逐条引用段落，显式核验"是否真实／是否已答／是否超范围"，并把"无法反驳才修订"设为默认。精确率不到七成的评审层，只会带来改动量与回归风险。
5. **给循环设上限，并定义失败的合法出口。** 迭代封顶，超限输出失败报告（想法／试过什么／实测结果／为何不够）。没有失败出口的系统，一定会制造成功。
6. **按错误代价分层付费。** 单遍基线 token 少约 108 倍、成本与耗时各低约 12 倍 ^[raw/articles/端到端论文生成系统假结论检出率92自动跑实验画图直出论文初稿.md:87]，适合探索期；完整栈留给"这句话会被别人引用"的时刻。token 与美元不成比例，说明预算大头在可缓存、低单价环节——要省就省那一层，别先砍评审轮次。

## 评测结果

受控 8 课题对比：引文有效率 99.5% vs 人类预印本 97.8%、AI Scientist 93%、AI Scientist-v2 91%、Agent Laboratory 96%、单遍基线 81%。图形可编辑率 96.4% vs 人类 58%、AI Scientist 与 Agent Laboratory 为 0%。^[raw/articles/端到端论文生成系统假结论检出率92自动跑实验画图直出论文初稿.md]
