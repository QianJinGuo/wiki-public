## 深度分析

### 确定性工程：把 AI 的"不确定性"关进牢笼

文章最有洞察力的部分，是把 AI 工程的核心矛盾定义在"确定性"上。团队认为 AI 天然存在不确定性，上下文工程本质上是一个信息熵减过程——需要更精确、描述更精准的信息，并把确定性的流程和方案工程化，才能避免模型"灵光一现"式的自由发挥。他们给出的解法分为四个维度：优化上下文信息结构与密度、通过前端框架约束运行时提升代码语意确定性、用工程能力和 workflow 固化执行流程、以及通过高度抽象的统一解决方案约束 AI Coding 的策略空间。这比泛泛谈 prompt 工程更系统，把"AI 结果不可控"拆解成了可逐一治理的工程问题。^[raw/articles/淘宝跨端体验优化-ai-演进之路.md]

### 领域语意缺失是通用 AI 做垂直优化的根本短板

团队用 Cursor + Opus 4.5 实测淘内 C 端应用后，总结出通用 AI 做体验优化的五个失效点：无法理解 SSR 及端边云分工（优化方案停留在 CSR 八股文）、不懂手淘领域知识（网络优化如何申明）、感知不到业务语意（分不清主请求与首屏元素）、只能静态分析无法真机 trace 调试、也无法操作平台配置与发布。这说明对于深度绑定特定基建与业务语意的垂直场景，"更强的通用模型"并不能自动解决，必须靠领域基建向 AI 输送结构化的上下文。^[raw/articles/淘宝跨端体验优化-ai-演进之路.md]

### 基建即上下文：端边云基建的"无感注入"是差异化护城河

体验优化 Agent 的设计亮点在于让 ICE 框架、高性能解决方案、跨端研发平台、前端源站与边缘应用 ER 无感注入到开发者页面中，全流程采集信息，再配合 RAG、workflow 与代码语意做上下文调优。文中一个关键对比是：spec 在 AI Coding 前已有规范标准，而体验优化在 Coding 前只是一堆"FCP 长、要优化首帧"的杂乱结果——因此团队用解决方案中心沉淀标准化的开箱即用方案，让 AI 优先召回标准方案而非自由重写。基建沉淀的深度直接决定了 AI 上下文的质量，这构成通用 AI 产品难以复制的壁垒。^[raw/articles/淘宝跨端体验优化-ai-演进之路.md]

### 从五阶段演进看"AI 自驱"的路径依赖

文章将手淘体验优化方式划分为五个阶段：架构师本地诊断 → 标准化框架交付 → AI 辅助诊断出报告 → AI 分析与 Coding 一站式交付 → 自进化 Agent。前三个阶段的痛点（架构师成为中心化瓶颈、AI 只能静态分析）正好解释了为什么必须走向 Skills 化的 Agent——只有让 AI 能调度云真机、操作平台、执行云端沙箱 Coding，才能突破"分析报告仍需人工执行"的天花板。这个演进序列对其他团队有参考价值：没有前期的标准化与基建沉淀，直接跳到 Agent 阶段会缺地基。^[raw/articles/淘宝跨端体验优化-ai-演进之路.md]

## 实践启示

1. **先做工程预处理，再让模型出手。** 能用确定性工程实现的流程绝不交给模型：聚类分析、workflow 固化、长尾特征的多维度分析引擎等前置工程能有效抑制幻觉。原则是"1+1=2"的部分用工程，需要泛化的部分才用模型。^[raw/articles/淘宝跨端体验优化-ai-演进之路.md]
2. **为 AI 建统一解决方案库，而非放任自由编码。** 让 AI 召回沉淀在解决方案中心的标准方案（如端快照能力），而不是让它凭"挥发"重写一个 Snapshot——把 AI Coding 从无序发挥收敛到标准能力交付。可对照 [[concepts/context-engineering|上下文工程]] 的方法论落地。^[raw/articles/淘宝跨端体验优化-ai-演进之路.md]
3. **用评测集与 Trace 持续校准 Agent 准确率。** 体验优化 Agent 通过 Zata 建设 Trace 与评测体系，用评测集迭代准确率、用 Trace 排查异常返回。任何 Agent 产品化都应把评测当一等公民，而非上线后靠用户反馈兜底。^[raw/articles/淘宝跨端体验优化-ai-演进之路.md]
4. **让 Agent 嵌入研发全流程实现"问题左移"。** 本地编码（IDE MCP 接入）、预发发布（AI CR/Lint）、提测阶段（云真机跑分）、线上运维（工单自动触发分析并产出 PR）四个阶段各有产品侵入点——问题发现越早，解决成本越低。Agent 离开产品触达就只是无法被使用的代码块。^[raw/articles/淘宝跨端体验优化-ai-演进之路.md]
5. **长尾问题要靠线上数据回溯而非线下复现。** 千人千面的业务形态导致 P95 长尾线下难以复现，团队通过模型抽象线上 Log、记录设备/服务端环境与用户行为回溯来获取关键分析信息。面向 AI 的采集设计（如负向采集 SDK）应把"AI 可分析性"作为一等需求。^[raw/articles/淘宝跨端体验优化-ai-演进之路.md]
6. **自进化路径靠知识萃取而非单纯堆算力。** 下一阶段的规划是从文档、群聊、问题排查记录中萃取统一解决方案与规则，配合思维链学习，让 Agent 成为"每个跨端同学最懂手淘体验的 AI 架构师"。组织知识的结构化沉淀是 Agent 进化的燃料，可与 [[concepts/rag-retrieval-augmented-generation|RAG]] 实践结合。^[raw/articles/淘宝跨端体验优化-ai-演进之路.md]
