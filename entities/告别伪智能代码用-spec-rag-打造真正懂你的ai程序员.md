——知识库的深度建设

## 深度分析

### “能写”≠“写得对”：幻觉的根源是上下文而非能力

文章的核心诊断是：AI 编程的失败大多不是模型能力不足，而是上下文缺失。在强业务耦合、高频迭代的场景中，模型凭统计模式与风格模仿“猜”代码，必然产生幻觉、遗漏边界条件、违背团队工程惯例。作者由此把问题重新定义为“认知基础设施”建设——与其追求更强的生成模型，不如系统性地让 AI 看得见项目的技术契约、业务语义和历史方案。这一视角与 [[concepts/context-engineering|上下文工程]] 的思路一致：上下文质量优先于模型选型。 ^[raw/articles/告别伪智能代码用-spec-rag-打造真正懂你的ai程序员.md]

### Spec 硬规则 × RAG 软上下文：约束与弹性的分层协同

文章最有价值的抽象是把项目知识切成两层：Spec 知识库承载“硬规则”——接口定义、数据格式、异常处理、兜底策略等确定性契约，直接嵌入 IDE 上下文作为系统级约束实时生效；RAG 知识库承载“软上下文”——业务术语、历史技术方案、跨团队协作背景等非结构化知识，通过 MCP 按需召回。这种分层避免了两种极端：全靠 Spec 会让规范文档无限膨胀、维护成本失控；全靠 RAG 则让确定性规则失去强制力。它也解释了 Spec Coding 与 Vibe Coding 的分野——后者快但不可预测，前者初期投入大但行为可验证、可审计，适合企业级场景。 ^[raw/articles/告别伪智能代码用-spec-rag-打造真正懂你的ai程序员.md]

### RAG 的工程质量决定“懂不懂业务”：分块、混合检索与重排序

文章没有停留在概念层面，而是系统梳理了 RAG 落地的四个技术杠杆：分块策略上，固定大小、语义、递归、文档结构、LLM 五种切法各有取舍，对结构清晰的技术文档而言基于结构分块效果最佳；检索上，单一方法无法兼顾精确匹配与语义理解，全文检索 + 稠密/稀疏向量 + 图检索的混合召回已成为业界标准实践；查询转换（重写、子查询拆解、回退提问）负责弥合用户口语与技术术语之间的语义鸿沟；Cross-Encoder 重排序则在送入 LLM 前过滤“表面相关但语义不匹配”的内容，只保留 Top-N 高质量片段。这四层共同决定了 AI 是“检索到了”还是“检索对了”。 ^[raw/articles/告别伪智能代码用-spec-rag-打造真正懂你的ai程序员.md]

### MCP：把知识检索变成可插拔的基础设施

架构上，文章用 MCP（Model Context Protocol）把 RAG 检索能力封装为标准化工具，类比“AI 时代的 Type-C 接口”。其能力交换 + 运行时调用两阶段协议让 agent 平台无需硬编码接口细节即可动态发现并调用知识库服务，且原始数据保留在检索层、通过权限控制保障安全。文章采取“本地试点 → 云端迁移”的渐进式部署策略：先用“一句话生成 MCP 服务”快速验证，稳定后再迁云端——这是典型的降低落地风险的工程节奏。 ^[raw/articles/告别伪智能代码用-spec-rag-打造真正懂你的ai程序员.md]

## 实践启示

1. **先给项目知识分层，再谈 AI 编程提效**：把“必须遵守的确定性规则”（接口契约、编码规范、兜底策略）与“弹性辅助知识”（业务背景、历史方案、最佳实践）分开，前者进 Spec 知识库，后者进 RAG，混在一起只会两头都做不好。 ^[raw/articles/告别伪智能代码用-spec-rag-打造真正懂你的ai程序员.md]

2. **Spec 直接嵌 IDE 上下文，RAG 走 MCP 按需检索**：硬规则作为系统级约束实时生效、无需检索；软上下文按需召回，避免把全部文档塞进 prompt 导致上下文过载。可参考 [[concepts/context-window-economics|上下文窗口经济学]] 的成本视角。 ^[raw/articles/告别伪智能代码用-spec-rag-打造真正懂你的ai程序员.md]

3. **用 .spec/ 目录把规范工程化**：参照文中猫超导购的实践，为每个 Solution 和通用组件配套 `.spec/` 目录，明确输入输出、实验开关、兜底逻辑，让 agent 在代码生成前自动加载——规范不工程化就等于不存在。 ^[raw/articles/告别伪智能代码用-spec-rag-打造真正懂你的ai程序员.md]

4. **分块按文档结构选型，检索用混合召回 + 重排序**：技术文档优先用基于结构的分块；检索层组合关键词与向量召回，再用 Cross-Encoder 重排，只把 Top-N 最相关片段送入模型——这是文中给出的最低成本、高收益组合。 ^[raw/articles/告别伪智能代码用-spec-rag-打造真正懂你的ai程序员.md]

5. **警惕“规范滞后于代码”**：Spec 的最大长期风险是与实现脱节。文中规划的方向值得跟进——通过代码变更感知建立规范自动保鲜机制，确保 Spec 与代码同步演进。 ^[raw/articles/告别伪智能代码用-spec-rag-打造真正懂你的ai程序员.md]

6. **渐进式部署降低验证成本**：RAG + MCP 集成先在“需求澄清、错误诊断、方案参考”等低风险场景本地试点，验证检索质量后再迁云端扩大范围，不要一步到位重构整个知识体系。 ^[raw/articles/告别伪智能代码用-spec-rag-打造真正懂你的ai程序员.md]
