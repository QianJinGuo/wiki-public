## 深度分析

### 无状态 API 与"数组即记忆"：被刷新的认知

原文最有价值的部分不是那 80 行代码本身，而是一个反直觉的事实：Claude API（以及所有主流 LLM API）在两次调用之间完全无状态，模型自身不具备任何记忆。所谓的"对话记忆"，只是一个由开发者亲手维护、每次请求时整体发送的 `{ role, content }` 对象数组。作者坦言自己学到这一点时"认知被刷新了"——多数初学者默认模型"记得"之前说过什么，而真相是每一轮对话都是把完整历史重新推送给一个失忆的服务。理解这一点，上下文窗口长度为何是硬约束、长对话为何越来越贵、遗忘为何必须显式设计，就都有了物理直觉。^[raw/articles/如何手搓一个-cli只需-80-行代码彻底看清-ai-的底层逻辑.md]

### 单文件标本：框架封装之前的基线

这个项目刻意采用"一个 index.js、约 80 行、无框架无抽象层"的形态。依赖只有三样：dotenv 读环境变量、Node 内置 readline 处理终端输入输出、Anthropic SDK 做 HTTP 客户端。作者反对的正是大多数教程"还没讲清底层逻辑就先扔一个 LangChain"的做法——从原始 API 调用开始，才能看清框架到底在封装什么。这份标本的意义在于给出一个可对照的基线：当你后来在框架里遇到"会话管理""消息历史""提示词模板"这些概念时，能立刻还原成"一个数组、一个字符串字段"，而不是把框架术语当作黑魔法。这也解释了这类 CLI 为何运行得快——没有中间抽象层，路径就是 API 调用本身。^[raw/articles/如何手搓一个-cli只需-80-行代码彻底看清-ai-的底层逻辑.md]

### 流式输出与递归循环：体验层和工程层的最小实现

工程上有两处值得注意的设计。其一，AI 调用使用 `client.messages.stream()` 而非 `create()`：前者在每个 token 生成时触发事件、立即打印，用户无需等待整段响应，这是"逐字输出"体验的全部来源。其二，输入循环是一个递归异步函数——提示输入、等待输入、调用 chat()、再调用自己，并用 `/quit` 和 `/history` 两个斜杠命令分别处理安全退出和原始 JSON 上下文查看。`/history` 尤其有教学价值：它把"记忆就是数组"这个抽象说法变成了肉眼可见的 JSON，学习者随时可以检查模型每一轮究竟"看到"了什么。两者合起来说明：一个可用的 AI 交互界面，其核心工程量并不大。^[raw/articles/如何手搓一个-cli只需-80-行代码彻底看清-ai-的底层逻辑.md]

### 系统提示词：一个独立字段，一种"性格接口"

系统提示词在 API 中是独立于 messages[] 数组的单独字段，它决定模型的全局行为——换掉它就能彻底改变 AI 的"性格"。作者把自己的偏好写了进去，因为受不了默认回答客套话过多，改成了"你是一个简洁的 CLI 助手。直接、准确、别废话，实话实说"。这个细节把一个常见的模糊印象具体化了：人格、语气、约束不是模型内在属性，而是每次请求都可以替换的一段配置。对后续理解 agent 的行为塑形、提示词工程乃至安全对齐，这是一个恰当的起点。^[raw/articles/如何手搓一个-cli只需-80-行代码彻底看清-ai-的底层逻辑.md]

## 实践启示

1. **先跑通裸 API，再上框架。** 用一个单文件脚本（原生 SDK + readline）搭一个最小聊天 CLI，亲手维护对话历史数组，之后再学 LangChain 等框架时，每层封装都能对应到你写过的某几行代码，学习曲线会平缓得多。^[raw/articles/如何手搓一个-cli只需-80-行代码彻底看清-ai-的底层逻辑.md]
2. **把"记忆"实现一次，胜过读十篇上下文管理文章。** 在自己的代码里维护 `{ role, content }` 数组并每轮整体发送，你会自然理解上下文窗口长度、token 成本与长对话劣化的来源；需要 [[concepts/agent-memory-architecture|Agent 记忆架构]] 的更复杂设计时，这个数组就是它的最小原型。^[raw/articles/如何手搓一个-cli只需-80-行代码彻底看清-ai-的底层逻辑.md]
3. **给 CLI 加一条 `/history` 命令。** 用 JSON 打印完整对话上下文，让"模型看到了什么"变成可检查的事实；调试任何 agent 应用时，第一件事都应该是查看发出去的真实 payload，而不是猜。^[raw/articles/如何手搓一个-cli只需-80-行代码彻底看清-ai-的底层逻辑.md]
4. **优先用 `stream()` 而非 `create()`。** 流式输出对感知延迟的改善远大于对真实延迟的改善，但在交互式产品里，"逐字出现"的体验往往就是用户判断快慢的全部依据；对速度敏感的场景（如 [[concepts/context-window-economics|上下文经济学]] 讨论的 agent 商业决策），这是零成本的体验优化。^[raw/articles/如何手搓一个-cli只需-80-行代码彻底看清-ai-的底层逻辑.md]
5. **把系统提示词当作可替换的性格接口来设计。** 不要忍受默认模型不合用的语气——它是独立字段，改一句话就能全局生效；为自己的使用场景显式写清"直接、准确、别废话"级别的约束。^[raw/articles/如何手搓一个-cli只需-80-行代码彻底看清-ai-的底层逻辑.md]
6. **密钥放环境变量，不进代码。** 跟随示例的做法：API key 存 `.env`（并让 `.env` 留在版本库之外），SDK 通过 `ANTHROPIC_API_KEY` 自动读取，缺失即报错——这是所有 AI 应用都该遵守的最低安全基线。^[raw/articles/如何手搓一个-cli只需-80-行代码彻底看清-ai-的底层逻辑.md]
