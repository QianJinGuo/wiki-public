# Autoresearch也会无效加班？微软试了试「一键清空对话」

## 核心论点：长程 Agent 会困进「思路盆地」

微软研究院对长程 autoresearch Agent（一次任务连续跑几十小时~数天）的分析发现：跑得越久未必想得越多。同一算法优化题、相同配置从同一起点独立跑 8 次，最好 100 分、最差 68.3 分——落后者仍在改代码、提分数，却始终没追上。研究团队把这个过程类比为**梯度下降（Idea Descent）**：分数可微改进，但解法空间可能早已局部收敛（论文：Fork-and-Flush: Escaping Idea Basins in Autoresearch Agents, arXiv:2610.07447）^[raw/articles/autoresearch也会无效加班微软试了试一键清空对话.md]。

## 解法空间可视化：3 万次 LLM 比较定义 Idea Basins

仅看分数无法判断 Agent 是否真正换过解法。团队对提交程序去重、抽样后让 LLM 生成统一功能规格说明（保留算法/数据结构/关键参数，滤掉代码风格），再做 3 万余次 A/B/C 相似度判断，把方案映射到二维空间——不同运行的提交聚类在少数**Idea Basins**区域附近，后续提交停留在各自区域。二维映射与留验 LLM 相似度判断平均一致率 **85%**（随机基线 50%），换嵌入方法聚类现象仍在 ^[raw/articles/autoresearch也会无效加班微软试了试一键清空对话.md]。

## Fork-and-Flush 机制

运行到预定节点：**复制当前工作空间 → 启动多个新分支**（继承代码、实验文件、历史最佳结果）→ **清空对话上下文** → 各分支独立探索 → 择优继续 → 下个节点重复。要点：

- 分叉时机按**固定预算节点**（开局 4 分支择优，预算 1/3、2/3 处再分叉）——按"成绩停滞"触发的 25 次早期测试中 15 次从未触发：小幅提分会不断重置停滞计时，判断"卡住"不可靠 ^[raw/articles/autoresearch也会无效加班微软试了试一键清空对话.md]。
- 调度由 Agent Harness 完成，**无需修改模型权重**；提示词直接提醒"换个思路"在本组实验中没有显著效果 ^[raw/articles/autoresearch也会无效加班微软试了试一键清空对话.md]。
- 与"全部预算给一个 Agent"（单盆地内打磨）和"4 个独立 Agent 从零跑"（每条轨迹预算 1/4）相比，Fork-and-Flush 兼顾两者：不丢已验证成果，又强制多方向探索 ^[raw/articles/autoresearch也会无效加班微软试了试一键清空对话.md]。

## 实测

13 项长程任务。Polyomino 任务中一次中途分叉出现明显分化：4 分支继承相同工作空间、全部清空历史对话，只有 1 个分支在首次提交就跳入新解法区域（跳转距离达单次运行相邻提交位移中位数的 **43 倍**），最终 93.9 分 vs 单次运行基线中位 84.6 分。作者强调：清空上下文不保证换思路，价值在于让多分支各自尝试、把后续预算交给更有希望的方向 ^[raw/articles/autoresearch也会无效加班微软试了试一键清空对话.md]。

## Wiki 视角

这是 harness 层反"上下文惯性"的结构化方案：与 context 压缩（对话历史定期压缩仍无法逃离早期算法选择）互补——压缩保留连续性，Fork-and-Flush 主动制造断裂。对探索机制设计（何时分叉、预算分配、分支选择）是可复用的实证参照 ^[raw/articles/autoresearch也会无效加班微软试了试一键清空对话.md]。

## 深度分析

### 思路盆地与 exploitation 陷阱的相似性

把 Idea Descent 类比梯度下降展开，Idea Basin 与优化里的局部最优/exploitation 陷阱有清晰的同构：都存在一个"改进信号仍在为正、但解法空间已停止扩张"的区域；小幅提分会作为正反馈不断强化当前方向，让偏离的成本显得越来越高。停滞检测之所以失效（25 次早期测试 15 次从未触发分叉），本质是 exploit 噪声——盆地内的打磨偶尔还会涨分，把"卡住"的信号不断重置。

但两者有一个关键差异：梯度下降的盆地由任务损失面的几何结构决定，而 Idea Basin 很大程度上是**历史依赖**而非任务内在的——同一任务、同一起点的 8 次独立运行聚在 5 个不同盆地，说明盆地是"跑出来的"，不是"题目里自带的"。更危险的是，经典 exploitation 中智能体多少知道自己在保守；而这里的 Agent 分数还在上涨，**从内部信号完全无法察觉自己已经收敛**。最贵的无效加班，恰恰是看起来还在进步的那种。

### Fork-and-Flush vs 上下文压缩/总结的机制差异

两者都"丢信息"，但丢的东西恰好互补，可以用三个维度区分：

1. **保留什么**。上下文压缩（摘要、compaction）保留的是叙事连续性——"我们为什么走到这一步"，丢弃的是细节；Fork-and-Flush 保留的是 artifact——代码、实验文件、历史最佳结果，丢弃的恰恰是叙事。而路径依赖正藏在叙事里：早期"就用 X 方法吧"的决策被后续每轮对话复述、强化，artifact 本身不携带"当初为什么这么选"的锚。
2. **目的**。压缩服务于连贯性和 token 预算，默认假设"接着想"是正确的；flush 服务于策略多样性，主动接受各分支重复探索的成本，赌注是"换一个起点重新想"的期望收益更大。
3. **作用位置**。压缩在单个对话窗口内部操作，不改变 Agent 下一轮的思考惯性（何况长上下文还有 [[concepts/lost-in-the-middle|lost in the middle]] 式的注意力衰减问题）；flush 在运行拓扑层面操作——复制工作空间、并行分支、择优——改变的是搜索过程的树结构，而不是某一条分支的记忆管理。TACO 这类"学会丢掉无用上下文"的工作（[[entities/taco-terminal-agent-context-compression|TACO 终端 Agent 上下文压缩]]）属于前者，Fork-and-Flush 属于后者，二者是互补而非替代。

### 为什么清空反而提升多样性

直觉上清空历史应该让 Agent "忘掉成果"，但实测三种策略归一化平均分 0.47（单次）/ 0.54（4 独立）/ 0.78（Fork-and-Flush），消融实验给出更细的分解：只清空 0.55、只分叉 0.57、两者结合 0.71——各自有效，组合超加性。机制上可以拆成三点：

- **路径依赖存储在对话里，不在代码里**。清空把 Agent 的先验从"完整对话史"重置为"任务描述 + artifact"，artifact 回答"现在有什么"，对话史回答"曾经怎么想"，后者才是把提交序列锚在旧盆地内的信息。
- **清空是去锚定，不是注入创意**。Polyomino 那次分叉，4 个分支同样清空，只有 1 个在首次提交就跳出（位移达相邻提交中位数的 43 倍）。清空只是移除了锚，让"换思路"从几乎不可能变成有一定概率；多样性最终靠多分支平行采样来兑现——这也是择优机制是必要组件而非可选优化的原因。
- **预算结构决定了它优于"全部押一条轨迹"和"全部从零并行"**。前者困在单盆地打磨，后者每条轨迹只有 1/4 预算；Fork-and-Flush 让已验证成果被所有分支继承（不重复付费），同时用重置的先验让各分支的采样去相关。

### 对本 wiki 自身 context-management 实践的映射

这篇论文对一个知识 wiki 的运行方式有直接的映照：

- **wiki 本身就是长程 Agent 的工作空间**。每次会话加载的 entity 摘要 + working set 相当于"继承的工作空间"，而延续昨天的聊天记录继续干活，就对应单次长程运行——理论上也会形成流程层面的思路盆地（比如总用同样的检索路径、同样的评分权重处理新文章）。cron 驱动的独立任务、新会话冷启动从 wiki 而非从对话史出发，正是 harness 层的 "flush"。
- **wiki 的过期与衰减机制对应主动丢弃叙事**。与 [[concepts/memory-consolidation-decay|记忆固化与衰减]] 的思路一致：让旧决策不至于永久锚定后续处理，低价值 entity 定期退役，等价于周期性地减小"历史对话"对新分支的引力。
- **可检验的推论**：如果 wiki 流水线的每个环节都"接着上次的队列跑"，即使每次输入不同，处理方式也会趋同；对照做法是定期从 raw/ 全量重扫出发，允许与既有队列结论冲突的路径。
- **边界条件必须先回答**：Fork-and-Flush 依赖可验证的评分机制来择优。wiki 的知识整理任务没有客观分数，"多分支择优"会退化为主观判断甚至多数暴政——在给 wiki 工作流引入分叉机制前，先得造出 verifier，否则只应借用"定期冷启动"这一半。

## 实践启示

1. **别用"还在提分"判断没卡住**。分数是盆地内的 exploitation 信号；判断是否真换了思路要看解法空间的结构变化（如功能规格相似度），而不是分数曲线的斜率。
2. **压缩上下文 ≠ 逃逸盆地**。压缩保留叙事连续性，也就保留了路径依赖；需要多样性时，丢叙事、留 artifact——继承成果，但不继承"当初为什么这么想"。
3. **分叉时机用固定预算节点，不要用停滞检测**。小幅提分会不断重置停滞计时器（实测 25 次中 15 次从未触发），把调度交给预算而非"成绩停滞"这种被噪声污染的信号。
4. **清空是去锚定不是注入创意，必须配并行分支 + 择优**。4 个清空分支只有 1 个真正跳出旧区域；单一 flush 的期望收益有限，价值在"多买彩票后选最好的那张"。
5. **在能力边界附近的任务上启用，收益最大**。运行间差异呈倒 U 形：任务太简单或远超能力时多分支是浪费预算；优先投给"有时能成、有时不能"的中间地带。
6. **没有可靠 verifier 就别学整套机制**。择优继续依赖可验证评分；LWE-rec 上完整 Fork-and-Flush 反而输给单次运行，且分叉本身消耗预算——评分模糊的任务里，先借用"定期冷启动"，后考虑分叉。
