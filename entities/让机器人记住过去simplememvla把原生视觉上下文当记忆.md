# SimpleMemVLA：原生视觉上下文当记忆

## 深度分析

### 可行性来自 token 经济学，而非新算法

SimpleMemVLA 的核心赌注其实是一笔算术账：60 秒历史折合约 5.6k token，而主干模型支持 262k 上下文——分钟级视觉历史可以原封不动塞进模型，无需先压缩成另一套记忆表示。这意味着这条路线的门槛不在算法创新，而在主干上下文窗口是否跨过了某个临界规模。近年长上下文主干的快速进步，让"直接读原生历史"第一次变得工程上便宜。相关取舍可对照 [[concepts/context-window-economics|Context 窗口经济学]]。

### 「写入时承诺」：记忆架构的分水岭

论文最有概念价值的判断是：任何在写入阶段就做筛选、压缩或覆盖的记忆机制，都必须提前决定"什么信息未来有用"——而一个细节是否重要，往往要到后续任务才知道。这种限制被作者称为"写入时承诺"。SimpleMemVLA 把保留决策整体推迟到读取时：历史画面沿用 VLM 预训练的视频格式、按时间顺序排列、附明文时间戳，模型在理解当前任务时一并理解过去。这与 [[entities/admem-memory-policy-selective-memory-sjtu-tencent-2026|AdMem 选择性记忆]] 代表的"精心挑选该记什么"路线形成了方向性对立。消融显示，历史信息主要通过生成子任务时形成的上下文隐藏状态影响动作头，而非子任务的字面文字——说明记忆真正起作用的位置在表征层，不是提示词层。

### 能力边界：消融实验划出了三个必要条件

对照实验固定数据、主干、监督和优化器，只替换记忆机制，结果支持"读取时可读的历史优于提前压缩"。消融进一步划出三个缺一不可的条件：关键画面必须在窗口内（RMBench 盖积木任务中，30 秒窗口含遮盖过程则成功，缩到 15 秒关键画面移出即失败）；帧顺序必须保留（打乱即失败）；时间戳与时间顺序对区分重复事件不可少。换言之，原生上下文不是免费午餐——它只是把"取舍决策"从设计者转移到上下文长度与推理成本上。注意所有结论均限于论文所测基准范围。

### 涌现的上下文学习与流式推理的算力账

两个延伸发现让这条路线更有分量。其一，视觉上下文学习：把另一条轨迹的片段拼进历史（换遮挡位置、换颜色提示、换演示开头），模型在零参数更新下跟随新上下文调整行为，且遮蔽关键历史会改变决策、遮蔽等长无关片段则不影响——行为变化是定向的，不是噪声。其二，延迟账：精确 KV 缓存复用把 60 秒历史的决策延迟从 1.02 秒降到 0.68 秒（单张 H100、bf16），低于 0.96 秒实时预算；45 分钟历史（245k token）从 32.1 秒全量重算降到 1.18 秒流式。这提示"上下文即记忆"的实时性瓶颈主要由推理侧计算复用解决，而非记忆结构本身。 ^[raw/articles/让机器人记住过去simplememvla把原生视觉上下文当记忆.md]

## 实践启示

1. **先算 token 账，再设计记忆模块。** 在动手写记忆系统前，先确认：原始数据全量放上下文要多少 token？主干窗口够吗？只有当原生数据确实装不下时，压缩/摘要型记忆才有正当性——否则就是在为不存在的问题引入结构。
2. **对"写入时做取舍"保持警惕。** 若你的记忆管道在写入时做筛选或摘要，问一句：这个取舍依据的信息，写入时真的具备吗？SimpleMemVLA 的证据表明，能推迟到读取时的决策应尽量推迟。
3. **记忆效果的验证要控制变量。** 该论文只换记忆机制、固定其余一切的对照设计值得复用：否则很容易把主干变强误记成"记忆设计好"。
4. **消融顺序本身是信息量。** 窗口长度→帧顺序→时间戳的逐项消融告诉我们，时序保真是这类记忆的底线，比"多塞几帧"更优先。
5. **实时系统的答案是缓存复用，不是裁剪历史。** KV 前缀缓存 + 后台预填充把长历史的成本摊到动作执行间隙；当被迫"为省算力砍历史"之前，先检查推理侧还有多少计算复用空间。
6. **上下文记忆可能带来免费的泛化。** 拼接新历史即可改写行为且定向生效，提示"从示范中学习"可以先从上下文拼接开始探索，而不必先走微调路线。
