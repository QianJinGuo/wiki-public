# 让生成式模型「画」出空间智能，而非强迫LLM输出「坐标」! 浙大提出Agentic空间认知评估框架

> WeChat-机器之心 | 发布于 2026-08-09 | 评分入库 v×c≥49

## 核心内容

机器之心 2026-08-09 18:04 新加坡 Show, Don't tell. 如果你问一个人 “杯子在哪？”，他通常会直接用手指给你看，而不是面无表情地回答：“目标位于屏幕横坐标 345 至 412、纵坐标 512 至 600 的边界框内”。然而，在现有空间认知评测中，我们却一直在强迫 AI 用这种 “反直觉” 的坐标方式来证明自己的空间认知能力。 空间判断本来就活在连续的视觉场景里，但现有 benchmark 几乎都要求模型用坐标、选项或文字作答。这对文本 VLM 已不够自然，天然工作在像素空间、本可直接 “画” 出答案的图像生成模型更是被挡在门外。 生成式模型会不会是承载空间认知更自然的载体？ 如果让模型直接把答案 “画” 出来，怎样让它把空间判断表达清楚？在不依赖人工的情况下，如何准确判断它画得对不对？进一步看，生成式模型与文本输出 VLM 在不同空间任务上的能力差异究竟在哪里？ 近日，浙江大学 OmniAI 团队在 《Show, Don’t Tell: Evaluating Spatial Cognition in Generative Pixels Rather Than LLM Text》 中提出 ProVisE，让图像生成模型直接在图中回答空间问题，并将视觉答案还原为原 benchmark 可以评分的结构化预测。 论文链接：<https://arxiv.org/abs/2607.21072 项目地址：<https://zju-omniai.github.io/ProVisE/ Github 链接：<https://github.com/ZJU-OmniA。^[raw/articles/让生成式模型画出空间智能而非强迫llm输出坐标-浙大提出agentic空间认知评估框架.md]

## 深度分析

### 表征错配是空间评测的第一性问题

文章最锋利的洞见不是某个模型分数，而是指出整个空间评测范式存在「表征错配」：空间判断天然栖息在连续的视觉场景中，评测却要求模型以坐标数字、选择题或文字描述作答^[raw/articles/让生成式模型画出空间智能而非强迫llm输出坐标-浙大提出agentic空间认知评估框架.md:16-18]。这种错配对文本 VLM 已经是别扭的——模型先在内部完成视觉理解，再被迫把连续空间关系压扁成离散 token；对图像生成模型则是彻底的排斥——它们本来就在像素空间里工作，却因为不会输出 JSON 边界框而被排除在几乎所有 benchmark 之外^[raw/articles/让生成式模型画出空间智能而非强迫llm输出坐标-浙大提出agentic空间认知评估框架.md:18-20]。ProVisE 的解法是把「回答方式」从评分标准中剥离出来：模型用自己擅长的方式作答（点目标、涂区域、画深度图、补全缺失物体），评测器再把视觉答案翻译回原 benchmark 能打分的结构化预测^[raw/articles/让生成式模型画出空间智能而非强迫llm输出坐标-浙大提出agentic空间认知评估框架.md:37-43]。这本质上是评测协议层面的一次解耦——与 [[concepts/evaluation-harness-design]] 中「评测接口与被评对象解耦」的思路一脉相承，只是把接口从文本约定换成了视觉约定。

### 视觉协议：用「生成-解析」对子替代人工标注

ProVisE 的基本单元是视觉协议，每个协议是一对共生组件：guidance prompt 规定模型如何作答，parser 负责把生成图像中的颜色、位置、区域还原为结构化标签、点、掩码或轨迹^[raw/articles/让生成式模型画出空间智能而非强迫llm输出坐标-浙大提出agentic空间认知评估框架.md:39-41]。这套设计的高明之处在于打分闭环完全确定性：不是让另一个 VLM 当裁判主观打分，而是把像素答案机器化解析后接入原有 benchmark 的评分逻辑^[raw/articles/让生成式模型画出空间智能而非强迫llm输出坐标-浙大提出agentic空间认知评估框架.md:41-43]。例子也很直观：问「缆车上还能否再坐一人」，模型直接把第二位乘客画上座椅，空间是否够一目了然；判断两点远近则生成深度图^[raw/articles/让生成式模型画出空间智能而非强迫llm输出坐标-浙大提出agentic空间认知评估框架.md:64-66]。这绕开了 llm-as-judge 的噪声问题，代价是协议设计必须足够约束生成行为——这正是协议需要「验证后冻结」的原因^[raw/articles/让生成式模型画出空间智能而非强迫llm输出坐标-浙大提出agentic空间认知评估框架.md:62]。

### Agentic Builder：把协议构建本身交给 Agent

面对形式各异的空间 benchmark，手工为每个任务设计协议不可扩展，于是团队把协议构建做成了 Agentic 流程^[raw/articles/让生成式模型画出空间智能而非强迫llm输出坐标-浙大提出agentic空间认知评估框架.md:45-47]。Builder 逐任务扫描数据、输入形式、答案结构与评分规则，统一为任务规范，然后在三条路径中选择：Reuse 直接复用兼容协议、Build 用已注册的确定性解析组件组装新协议、Fallback 在确定性组件覆盖不了时才让辅助 VLM 介入解析^[raw/articles/让生成式模型画出空间智能而非强迫llm输出坐标-浙大提出agentic空间认知评估框架.md:51-58]。这个三级降级结构体现了一种成熟的工程直觉：LLM 只处理确定性组件无法覆盖的长尾，主路径尽量走可复用、可验证的确定性组合——与 [[concepts/agent-orchestration-patterns]] 中「确定性优先、模型兜底」的编排原则一致。协议构建完成后还要经过「能生成、能解析、能接入原指标」的验证，通过即冻结供所有模型使用，保证评测的公平与可复现^[raw/articles/让生成式模型画出空间智能而非强迫llm输出坐标-浙大提出agentic空间认知评估框架.md:62]。

### 生成与理解是互补的两半，而非替代关系

SpatialGen-Bench 用感知、理解、推理、交互四层级组织 14 项子任务，从计数、相对深度一路延伸到导航与轨迹规划^[raw/articles/让生成式模型画出空间智能而非强迫llm输出坐标-浙大提出agentic空间认知评估框架.md:68-83]。在这个基准上对 20 个文本 VLM 与 11 个图像生成模型的对比给出了三个反直觉信号^[raw/articles/让生成式模型画出空间智能而非强迫llm输出坐标-浙大提出agentic空间认知评估框架.md:91-101]。其一，生成模型有更直接的「空间直觉」：在深度图、空间标记这类可直接画出的任务上竞争力强，因为像素作答避免了连续空间→文字的有损转换^[raw/articles/让生成式模型画出空间智能而非强迫llm输出坐标-浙大提出agentic空间认知评估框架.md:93]。其二，互补性极强：GPT-5.4 做错的题里 GPT Image 2 做对了 37%，且两者做对的题集并不重合^[raw/articles/让生成式模型画出空间智能而非强迫llm输出坐标-浙大提出agentic空间认知评估框架.md:97]。其三，VLM 仍在抽象推理层占优，空间推理层级组平均领先 17.6 个百分点——计数、尺寸比较、状态预测需要统计、比较与组合推演，这是文本符号处理的传统强项^[raw/articles/让生成式模型画出空间智能而非强迫llm输出坐标-浙大提出agentic空间认知评估框架.md:99]。最值得注意的是失败归因：88.03% 的失败样本并非生成或解析失败，而是图像已成功产出、预测已成功还原，只是画出来的空间状态本身错了^[raw/articles/让生成式模型画出空间智能而非强迫llm输出坐标-浙大提出agentic空间认知评估框架.md:101]。也就是说，评测管线已经把「表达能力」这个混杂变量剥离干净了，剩下的差距是纯粹的空间认知差距。作者的结论是把两者组合起来：文本/latent 表示负责约束规划与组合推理，视觉生成负责呈现空间状态，确定性工具负责验证——理解、生成与验证的协同可能比单点扩规模更接近通用空间智能^[raw/articles/让生成式模型画出空间智能而非强迫llm输出坐标-浙大提出agentic空间认知评估框架.md:105]。

## 实践启示

1. 评测的答案格式不是中立的：强迫模型用坐标/选项作答会系统性低估在像素空间工作的模型，设计 benchmark 时应先问「每种模型最自然的表达方式是什么」，而不是默认文本输出。若无法支持多模态作答，至少要在结论中声明这一表征偏差。
2. 「guidance prompt + 确定性 parser」是比 llm-as-judge 更可靠的开放性任务评分模式：让模型按约定格式生成，再用确定性的解析器还原为可打分结构，既保留生成自由度，又把评分噪声降到零。可迁移到图表理解、UI 操作等评测场景。
3. 协议/工具的自动化构建可按 Reuse → Build → Fallback 三级组织：先复用兼容资产，再用已注册的确定性组件组装，最后才让 LLM 兜底长尾——这比「全靠 LLM 生成」的方案可复现、可审计得多。
4. Agent 自动产出的资产（协议、规则、数据）上线前必须有机器化验证门（能生成、能解析、能接入原指标），验证通过即冻结，防止静默漂移污染后续所有评测结果的横向可比性。
5. 模型选型别只看总分：文末 37% 的互补率说明文本 VLM 与生成模型做对的题集显著不重叠，涉及空间理解的系统应考虑两条管线各答一遍再合并，或按任务层级（感知/理解/推理/交互）路由到不同模型。
6. 「生成成功 ≠ 答案正确」：88.03% 的失败发生在成功解析之后，提醒我们评价生成式系统时必须把「能否产出」与「产出是否正确」分开归因，否则会把认知缺陷误诊为工程缺陷。
