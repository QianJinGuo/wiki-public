# MTFM：美团统一推荐基座大模型在外卖多业务场景的落地实践

## 核心事实

美团在 MTGR（2025 年提出的生成式精排框架）基础上提出统一推荐基座大模型 MTFM，首次实现外卖多个主要业务（外卖首页、拼好饭等）的统一精排模型，相关工作已被 KDD 2026 收录^[raw/articles/mtfm美团统一推荐基座大模型在外卖多业务场景的落地实践-送中秋礼盒.md]。

**业务效果**：美团外卖多个业务订单量提升 2.06%~6.68%，推理成本降低 24%^[raw/articles/mtfm美团统一推荐基座大模型在外卖多业务场景的落地实践-送中秋礼盒.md]。

## 三大挑战与技术方案

围绕规模可扩展性、场景可延展性与架构高效性三大挑战：

- **多场景特征免对齐**：以异构 Tokenizer 与动态掩码实现多场景特征统一表示，避免跨场景特征对齐工程^[raw/articles/mtfm美团统一推荐基座大模型在外卖多业务场景的落地实践-送中秋礼盒.md]
- **Scaling 能力**：通过混合注意力与 Target Scale-Up 提升模型 Scaling 能力^[raw/articles/mtfm美团统一推荐基座大模型在外卖多业务场景的落地实践-送中秋礼盒.md]
- **深层网络训练**：借鉴 LLM 优化实践（业界已验证的基座模型路径：Foundation Model 统一处理多领域任务、异构信息表示为 Token 序列端到端学习）提升深层网络训练效果^[raw/articles/mtfm美团统一推荐基座大模型在外卖多业务场景的落地实践-送中秋礼盒.md]
- **系统开销可控**：User-Level 训练范式与定制算子保证训练/推理系统开销可控^[raw/articles/mtfm美团统一推荐基座大模型在外卖多业务场景的落地实践-送中秋礼盒.md]

## 背景：从 MTGR 到 MTFM

MTGR（2025）在美团外卖推荐场景验证了推荐领域 Scaling Law 的有效性并取得显著业务收益，但探索局限于单场景内部——模型被限制在单场景孤岛中，跨场景的数据、算力和架构无法充分复用。美团推荐覆盖外卖首页、拼好饭等多个业务场景，各场景长期独立建模。LLM 领域已验证的路径（基座模型统一处理多领域任务、端到端学习强泛化性）启发团队将下一阶段关键定位为打通跨场景异构性，即建设统一推荐基座大模型^[raw/articles/mtfm美团统一推荐基座大模型在外卖多业务场景的落地实践-送中秋礼盒.md]。

## 技术要点

- **统一样本与行为序列**：多业务场景样本与行为序列统一处理
- **训练策略**：User-Level 训练范式
- **训推性能**：定制算子 + 推理成本降低 24%
- **模型效果**：多业务订单量 2.06%~6.68% 提升，KDD 2026 收录

## 深度分析

### 异构 Tokenizer + 动态掩码：特征免对齐的工程解法

MTFM 把多业务输入统一为三类 Token：H-Token（跨业务历史行为序列，含商家/商品统一序列）、R-Token（近实时行为序列，按时间戳排序）、T-Token（待预估目标，含上下文/候选/交叉特征）。H、R 全业务共享，T 各业务独立维护；每类序列用独立 Tokenizer 编码后堆叠进共享 Attention Backbone，从而无需显式对齐跨业务特征体系。可见性由动态掩码控制：H 全局可见，R 内部因果掩码且 Target 只能看到曝光前行为，T 只见自身、同请求候选互不感知^[raw/articles/mtfm美团统一推荐基座大模型在外卖多业务场景的落地实践-送中秋礼盒.md:93-113]。这条路径与 LFM4Ads、ExFM 等"基座+专家"蒸馏范式的根本区别在于端到端——后者非端到端建模，被认为限制了能力上限^[raw/articles/mtfm美团统一推荐基座大模型在外卖多业务场景的落地实践-送中秋礼盒.md:70]。

### 混合注意力与 Target Scale-Up：把算力花在 Target 上

统一模型含多条千级长度序列，Full Attention 平方复杂度不可接受。MTFM V1 借鉴 Qwen3-Next、MiMo-V2-Flash 的混合架构，以 Target:Full=3:1 交错堆叠 16 层：T-Token 仅以全序列为 K/V 做 Target Attention、不参与全序列自注意力，消融显示该配置 GAUC 最优，显存下降使 batch size 扩大 1.7 倍、样本吞吐达全 Full Attention 的 2.9 倍^[raw/articles/mtfm美团统一推荐基座大模型在外卖多业务场景的落地实践-送中秋礼盒.md:120-130]。V2 的关键洞察是信息密度分配不均：单个 Target Token 携带的特征远多于单个 User Token，却被压成同维度单 Token。Target Scale-Up 用 AutoSplit 将每个 Target 拆成 4 个 Token Embedding，配独立 Q Projection/SwiGLU FFN，并用 RankMixer 式零参数 Mixing 防止拆分后各 Token 在相同 KV 下学出冗余表征（表征坍缩）^[raw/articles/mtfm美团统一推荐基座大模型在外卖多业务场景的落地实践-送中秋礼盒.md:132-150]。

### User-Level 样本范式与跨场景迁移收益

训练按 User-Level 聚合——同一用户当日全场景曝光 Target 聚成 1 条样本、共享最耗算力的长序列 Attention 计算；推理按业务 Request-Level 聚合候选，线上只保留共享序列基座+独享 Task Tower，实现"统一训练、多业务部署"。跨场景迁移对数据稀疏业务收益最大：小流量业务显著提升 0.60~0.93pp，中流量 0.25pp，大流量持平微正^[raw/articles/mtfm美团统一推荐基座大模型在外卖多业务场景的落地实践-送中秋礼盒.md:152-170]。行为序列也统一为商家/商品长序列并构建通用 SideInfo（覆盖质、价、品、情景化信息），解决了各业务数据链路重复建设与跨场景行为缺失，这对小流量业务尤为关键^[raw/articles/mtfm美团统一推荐基座大模型在外卖多业务场景的落地实践-送中秋礼盒.md:172-178]。

### 深层网络训练稳定性：从 0.4pp 波动到 0.1pp

多业务联合训练叠加网络加深后，随机重复实验离线指标波动一度超过 0.4pp，迭代基准失去置信度。团队通过监控中间层激活/参数/梯度定位到局部梯度衰减与参数退化，两招解决：一是深度感知初始化——借鉴 GPT-2 策略对 HSTU 每个 Block 输出投影按深度缩放标准差，使残差分支累积方差保持稳定；二是优化器升级——将部分 Dense 参数切到 Muon（Newton-Schulz 正交化），借鉴月之暗面实践增加 Weight Decay 与 Update RMS Scale，且仅在 HSTU 的 UQKV 投影与 Output Projection 上应用以平衡速度效果。叠加后波动从 0.4pp 降至 0.1pp^[raw/articles/mtfm美团统一推荐基座大模型在外卖多业务场景的落地实践-送中秋礼盒.md:186-215]。联合训练侧另有动态归一化（损失按 batch 内业务 PV 占比动态加权，等价于全局归一）与稀疏更新改进（跳过零梯度 Weight Decay、批量同步零梯度检测、步长 2 的梯度累积）^[raw/articles/mtfm美团统一推荐基座大模型在外卖多业务场景的落地实践-送中秋礼盒.md:217-226]。

### Scaling Law 验证与算子级性能工程

MTFM 在三个维度验证了 Scaling：层数增加各业务离线效果稳步增长；Token Dim 192~768 显著提升；序列长度 400~2000 内 GAUC 稳定提升。单样本计算量达 192 GFLOPs，较传统 DLRM 增长数百倍，性能工程成为落地前提：FA2 重构动态 Attention（jagged mask 入 Share Memory、Triton Kernel 替代 for-loop，22ms→1ms，前向 +128%/反向 +152%）、GLN 算子融合（带宽利用率 30%→60%+，提速 30%+）、Muon 批量化（小矩阵堆叠为 (B,M,N) 批量张量做 NS 正交化，阶段加速 241%、端到端 +19%）、消除 D2H 阻塞（训练整体 +15%）、特征精简（Agent Auto Research 驱动删 500 个特征 GAUC 无损，吞吐 +6%）；推理侧查表合并使显存 22GB→5.9GB，Mask 规则跳算使单算子延迟降 50%^[raw/articles/mtfm美团统一推荐基座大模型在外卖多业务场景的落地实践-送中秋礼盒.md:228-250]。

## 实践启示

1. **多场景统一的正确起点是 Token 表示而非特征模板**：固定模板强制对齐是 DLRM 时代多场景方案的根本约束，异构 Tokenizer + 动态掩码证明可以用表示层统一替代特征工程对齐，且不引入信息泄漏^[raw/articles/mtfm美团统一推荐基座大模型在外卖多业务场景的落地实践-送中秋礼盒.md:93-113]。
2. **Scaling 红利优先分配给信息密度最高处**：Target 侧特征密度远高于 User 侧，Target Scale-Up 的本质是按信息密度而非均匀地分配模型容量——这与 LLM 侧"激活参数花在刀刃上"的稀疏思路同构^[raw/articles/mtfm美团统一推荐基座大模型在外卖多业务场景的落地实践-送中秋礼盒.md:132-150]。
3. **训练稳定性是小流量业务的隐形门槛**：0.4pp 的实验波动足以让小流量业务的收益不可判别；深度缩放初始化 + 选择性 Muon 覆盖 + 全局归一化损失是可复用的组合拳^[raw/articles/mtfm美团统一推荐基座大模型在外卖多业务场景的落地实践-送中秋礼盒.md:186-226]。
4. **跨场景迁移收益与数据稀疏度正相关**：小流量业务 +0.60~0.93pp、大流量持平，说明统一基座的价值主要是给长尾场景"借"数据，而非提升头部场景上限——评估统一建模 ROI 时应按业务流量分层预期^[raw/articles/mtfm美团统一推荐基座大模型在外卖多业务场景的落地实践-送中秋礼盒.md:152-170]。
5. **算法-系统 Co-Design 是推荐基座落地的必要条件**：数百倍于 DLRM 的计算量意味着没有算子级优化（FA 重构、GLN 融合、Muon 批量化、消除 D2H 阻塞）一切模型收益都无法上线；未来方向也明确指向 Scaling 与 Infra 协同、参数量再升 1-2 个数量级^[raw/articles/mtfm美团统一推荐基座大模型在外卖多业务场景的落地实践-送中秋礼盒.md:228-262]。
