# 长文档视觉问答：把「读懂了」重述为「证据够不够」

## 一句话结论

把几百页报告交给多模态模型，难的往往不是认出文字，而是**在有限预算下找到足够证据、读对图表细节、组合跨页信息，并确认答案确实被支持**。这篇由浙大等单位完成的综述（arXiv 2610.31385，26 页，分析 150+ 篇）把长文档 VQA 拆成**文档解析 / 证据组织与检索 / 生成与学习 / 评估**四个互相作用的组件，核心判断是两句：**局部相关不等于证据充分；答案正确不等于过程可信**。^[raw/articles/long-document-visual-qa-task-centric-survey-zju-2026-11-01.md]

## 任务本身：为什么长文档特别难

输入是问题 + 候选视觉文档，系统在**上下文、计算、工具调用等预算约束**下输出答案，并**可以返回证据来源**。封闭域（问题指定文档）与开放域（从共享文档库识别来源）的搜索规模不可混同。困难可归为三类：**输入与搜索规模**（全量阅读昂贵，转文本丢图表与版式，缩图损坏细字）、**视觉复杂性**（表格、图表、表单、注释）、**证据分散与依赖**（条件、表头、数值与注释分布在不同页甚至不同文档）。^[raw/articles/long-document-visual-qa-task-centric-survey-zju-2026-11-01.md]

**两条路线的澄清**：直接阅读用给定文档表示（层次编码、跨页融合、压缩），显式检索先选文档/页面/元素再交给生成器。**直接阅读不等于毫无选择，显式检索也不一定只返回原始页面**；显式检索约占所考察方法的 **80%**（这是综述样本比例，不是行业部署份额）。^[raw/articles/long-document-visual-qa-task-centric-survey-zju-2026-11-01.md]

**三个易混边界**（这条区分极实用）：**多智能体**描述运行时角色协作；**多步推理**描述中间结果反馈是否修订判断；**迭代获取**描述是否在反馈下取得当前集合之外的**新证据**。因此固定多智能体流水线仍可能是单遍推理；对同一批页面反复检查可以是多步推理，但仍属一次性获取。^[raw/articles/long-document-visual-qa-task-centric-survey-zju-2026-11-01.md]

## 组件一：文档解析——两条独立轴，别把"有图"当深度解析

综述明确区分**外部文字提取**（OCR、PDF 文字抽取、VLM 转录或描述）与**深度解析**（摘要、章节树、关系图等语义概览与显式结构）两条独立轴：**仅把一个图表描述为文字，不自动算深度解析**。依赖提取便于建文本索引，但可能在识别与线性化时丢布局、图文对应与表格关系；直接编码页面减少文本化损失，仍受分辨率与视觉阅读能力限制；**混合方案同时用提取文字与页面图像，不能因保留图像就标为"不依赖提取"**。^[raw/articles/long-document-visual-qa-task-centric-survey-zju-2026-11-01.md]

演进主线：2021–2023 可读内容 + 版式视觉 → 2024 显式检索推原页面保真（DSE、ColPali、VisRAG）→ 2025 摘要/树/图让关系可导航（SimpleDoc、DocAgent）→ 2026 **问题与过程指导的按需解析**（AgenticOCR 按相关区域调解析工具）。关键提醒：**解析不是越丰富越好**——预建全文图谱有离线成本，按需解析也可能误判重要区域，价值应以**证据完整度、答案质量与总成本**衡量，而不是转录准确率或结构复杂度。^[raw/articles/long-document-visual-qa-task-centric-survey-zju-2026-11-01.md]

## 组件二：证据组织与检索——粒度、机制、时序

四个比较维度：**模态**（文字/视觉/混合）、**粒度**（文档/页面/元素）、**机制**（词法、向量、多模态匹配、LLM 选择与重排、区域细化）、**获取方式**（固定过程 vs 反馈驱动扩展）。^[raw/articles/long-document-visual-qa-task-centric-survey-zju-2026-11-01.md]

**粒度与上下文的张力**：整页保留背景却带噪声，细粒度区域突出细节却切断语义；**表格单元格没有表头、单位与统计时期时，往往"相关但不充分"**；检索命中的形式还可能不同于生成输入（文字块匹配后映射回源页面供视觉阅读）。^[raw/articles/long-document-visual-qa-task-centric-survey-zju-2026-11-01.md]

**机制与时序**：固定多阶段检索、重排、已有区域细化，**不因步骤多就成为迭代获取**——必须有生成或控制反馈推动**新增证据**。演进：早期预测答案所在页 → 2024 视觉索引缓解页面过多 → 2025 结构/区域/反馈扩展弥补孤立匹配的遗漏 → 2026 关注跨页上下文、证据状态与**继续搜索的边际价值**（DocMemo 维护页面信念与问题记忆，预算分配方法估计不同子问题继续获取的收益）。终点的判据是**问题所需支持足够**，不是达到固定页数或最高相似度。^[raw/articles/long-document-visual-qa-task-centric-survey-zju-2026-11-01.md]

## 组件三：生成与学习——两条正交维度，加一条"证据记忆"

**单智能体 vs 多角色协作**是组织维度；**单遍 vs 反馈循环**是推理维度，两者要分别描述：一条长思维链、结构化输出或固定多角色链条仍可属单遍流程；**只有中间观察、工具或验证不断修订判断与动作，才符合多步推理**。重读与核验同一组证据可以产生反馈，**不必每次新增检索**。^[raw/articles/long-document-visual-qa-task-centric-survey-zju-2026-11-01.md]

学习目标分三层：预训练培养文档表示与模态对齐；监督微调用答案、来源或动作示范；强化学习用答案、证据或过程奖励。**某系统采用 RL 不意味着所有模块一起更新**——原文附录明确区分检索、控制、工具与最终回答器的训练范围。演进：2021–2023 建立文档技能 → 2024 跨页通信、压缩与检索后阅读 → 2025 学习证据使用、重读与工具动作（VRAG-RL、SCORE）→ 2026 跨轮状态，减轻上下文累积与遗忘。^[raw/articles/long-document-visual-qa-task-centric-survey-zju-2026-11-01.md]

**证据记忆要点**：应记录**读到了什么、还有什么缺口、判断来自哪里**。压缩摘要便于持续推理，却可能**固定早期误读**——必要时应回到源页，而不是让多个智能体围绕同一份错误摘要反复确认。^[raw/articles/long-document-visual-qa-task-centric-survey-zju-2026-11-01.md]

## 组件四：评估——把错误来源隔离出来

五个评估面：答案正确性、检索召回与排序、空间定位、效率（解析+索引+在线推理）、鲁棒性（视觉退化与干扰）。基准演进：DocVQA/InfographicVQA/ChartQA（单页视觉理解）→ MP-DocVQA/SlideVQA/DUDE（多页定位、整合、不可回答）→ MMLongBench-Doc/M-LongDoc（长输入压力）→ ViDoRe/MMDocIR（检索定位）→ DocScope（页/区域/事实/答案分层 + 受控条件诊断）。^[raw/articles/long-document-visual-qa-task-centric-survey-zju-2026-11-01.md]

三条评估纪律：①**单个平均答案分可能掩盖错误来源**——正确答案可能来自先验、猜测或不完整证据，良好检索也可能被后续误读抵消；②要**联合报告答案与证据**，并用已知正确证据、缺失证据、干扰页面对照，隔离解析/检索/推理瓶颈；③跨方法比较须**固定候选文档、输入条件、预算与评测口径**——开放域全库页数与指定单文档平均页数不在同一尺度，单页证据任务不能替代跨页整合测试。^[raw/articles/long-document-visual-qa-task-centric-survey-zju-2026-11-01.md]

## 演进不是替代，而是"重点扩展"

作者反对"文字路线 → 视觉路线 → 智能体"的替代叙事，更准确的描述是**优先事项不断扩展**：先读懂内容，再从大范围获取高保真充分证据，最后持续维护与核验这些证据；旧方法可与新机制共存。**组件瓶颈会互相传播**：检索减少输入但带来遗漏 → 推动结构感知获取与局部解析 → 反馈让解析与检索成为可调度动作 → 要求生成器维护状态并决定是否重读/补查/停止 → 评估要追踪这些动作是否真的提高答案支持与质量—成本权衡。^[raw/articles/long-document-visual-qa-task-centric-survey-zju-2026-11-01.md]

一个典型的失败链条（作者注：用于解释组件依赖，非新增实验）：**局部转录漏掉单位 → 摘要把数值写进记忆 → 后续检索依据错误摘要选页 → 生成器给出貌似合理的比较**。此时"只把检索器或回答模型换大"未必能修复，因为错误发生在前端。^[raw/articles/long-document-visual-qa-task-centric-survey-zju-2026-11-01.md]

## 五个未来方向

1. **从局部相关到证据充分**：围绕问题列出必需事实、比较对象、计算条件与依赖，区分"帮助定位的背景"与"直接支持答案的证据"（财报比较不只要两个数值，还要列名、单位、期间、口径与注释）；训练与测试要加入完整/部分缺失/高相关但不充分的证据集合，检查系统能否**说清缺什么**并转化为下一步搜索目标。^[raw/articles/long-document-visual-qa-task-centric-survey-zju-2026-11-01.md]
2. **从正确答案到可纠正证据链**：证据记忆保留源文档、页面、区域、版本与依赖；发现冲突时**重读、撤回错误记录并更新下游判断**，而不是只改最后一句。受控删除/替换关键证据检验支持缺失或事实改变，改变无关证据则应保持答案稳定——**来源引用准确、事实读取准确、证据足以支持结论是三种不同检查**。^[raw/articles/long-document-visual-qa-task-centric-survey-zju-2026-11-01.md]
3. **从局部加速到预算感知联合协调**：小区域解析、少量检索或视觉压缩省下的资源，可能被辅助模型调用、交互轮次与状态维护抵消；应把搜索、细读、重解析、核验、停止放在**同一质量—成本目标**下决策，估计一次额外动作的**边际收益**，并判断"直接阅读"何时优于"先建索引"。^[raw/articles/long-document-visual-qa-task-centric-survey-zju-2026-11-01.md]
4. **跨问题记忆复用**：连续追问常复用表格位置、统计约定与已核验结果；用户纠正、文档版本变化或条件切换后要检查历史记忆是否仍适用并修订依赖。^[raw/articles/long-document-visual-qa-task-centric-survey-zju-2026-11-01.md]
5. **跨任务策略改进**：记住某页在哪里 ≠ 学会更好的检索/阅读/核验流程；受 RSI 启发，从成功、失败与反馈中提炼策略，先在独立任务验证再更新技能库或控制程序（例如"比较财务数值前检查单位与报告期间"）。**这是未来方向，不是本文已展示的通用自我改进系统**。^[raw/articles/long-document-visual-qa-task-centric-survey-zju-2026-11-01.md]

## 深度分析

### 这篇的价值在于把"RAG 直觉"逐条证伪

"更多页面、更强生成器、更高检索分数，都不自动保证可靠"——三个常见直觉被逐一拆掉：整页保留背景却带噪声（粒度问题）、单元格缺表头就"相关但不充分"（上下文问题）、检索分高但被后续误读抵消（链路问题）。**它给出的不是新模型，而是一套判断"哪里可能坏"的坐标系。**^[raw/articles/long-document-visual-qa-task-centric-survey-zju-2026-11-01.md]

### "三个易混边界"应成为文档处理的通用词汇

多智能体 / 多步推理 / 迭代获取这三者被大量产品文档混用，导致"我们做了多 Agent 循环"被当成"系统会持续补证据"。这篇给出可操作的判据：**看中间结果是否修订判断（多步推理），看是否取得当前集合之外的新证据（迭代获取）**。有了这两条，架构评审时就能问出"你这套循环到底在补证据还是在重读"。^[raw/articles/long-document-visual-qa-task-centric-survey-zju-2026-11-01.md]

### 证据记忆的"错误固化"是最容易被忽视的失效模式

压缩摘要让长程推理可行，但也把早期误读变成后续所有推理的前提。作者的办法很硬：**必要时回到源页**，并让记忆记录"读到什么/缺什么/判断来自哪"。这与 agent 记忆系统的通行教训一致——**摘要是有损压缩，检索是纠错手段，两者不能相互替代**。^[raw/articles/long-document-visual-qa-task-centric-survey-zju-2026-11-01.md]

### 评估设计比指标更重要

"正确答案可能来自先验、猜测或不完整证据"这句话，直接否定了单一准确率的解释力。它给出的替代方案是**受控对照**（已知正确证据 / 缺失证据 / 干扰页面）与**分层基准**（页→区域→事实→答案），本质上是把"答案对不对"换成"支持够不够"。^[raw/articles/long-document-visual-qa-task-centric-survey-zju-2026-11-01.md]

### 边界声明值得学习

作者反复标注"原文为综述，没有新增统一性能实验""图表分类与阶段是分析框架，不代表所有方法沿同一条路线替代演进""显式检索 80% 是综述样本比例，不是行业部署份额""这个失败例子用于解释组件依赖，不是新增实验"。**该说的不确定都说了**，读者才能正确使用这套框架。^[raw/articles/long-document-visual-qa-task-centric-survey-zju-2026-11-01.md]

## 实践启示

1. **评审长文档系统先问四个组件**：解析保真、检索充分、生成核验、评估隔离——瓶颈常在前端而不是生成器。

2. **区分"提取"与"深度解析"**：有页面图像不等于有结构；有图表文字描述不等于有可导航关系。

3. **用三条边界自检**：多智能体（角色）/ 多步推理（判断是否被修订）/ 迭代获取（是否拿到新证据）——三者不能互相代替。

4. **检索终点是"支持足够"**：不是固定页数，也不是最高相似度；表格类证据必须带上表头、单位与期间。

5. **证据记忆要记录缺口**：读到什么、缺什么、判断来自哪；摘要可能固化早期误读，必要时回源页。

6. **评估要能隔离错误来源**：受控删除/替换关键证据；改变无关证据答案应稳定。

7. **预算要联合优化**：把搜索、细读、重解析、核验、停止放进同一目标，报告预处理/索引/辅助模型/在线推理的全成本曲线。

8. **别把"重复使用同一文档信息"当成学习**：策略改进需要适用条件、迁移收益与独立验证。
