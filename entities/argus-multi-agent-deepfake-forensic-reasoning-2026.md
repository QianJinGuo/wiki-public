# ARGUS：多智能体取证推理的泛化 Deepfake 视频检测

北京交通大学、清华大学与蚂蚁集团提出的多智能体协作视频鉴伪框架（arXiv:2608.06865），核心范式转换：**从"看结果"到"找证据"**——检测过程留下可检查的中间观察，将"看到了什么"与"因此如何判断"明确分开。^[raw/articles/北交清华等提出argus多智能体协同断案给视频鉴伪补上证据链.md]

## 架构：独立观察者 + 裁判

传统鉴伪器直接把视频映射为 Real/Fake，无法回答异常来自皮肤纹理、光照还是跨帧运动；且多个模型沿同一错误直觉连续推理时，只会把初始误判包装得更完整。ARGUS 的关键设计是让证据收集**彼此独立**——观察智能体在观察阶段不输出最终真假结论：^[raw/articles/北交清华等提出argus多智能体协同断案给视频鉴伪补上证据链.md]

- **纹理观察者**：皮肤、头发、背景的细节/平滑度/融合痕迹；
- **光照观察者**：高光、阴影、物体间照明一致性；
- **运动观察者**：面部/头发/背景/物体的时间变化比较；
- **物理观察者**：人体生理、几何关系、物体运动规律的不协调。

裁判智能体接收各观察报告（可结合抽取的视频帧），权衡相互印证或冲突的证据，输出二元预测 + 取证解释。^[raw/articles/北交清华等提出argus多智能体协同断案给视频鉴伪补上证据链.md]

## FaceVid-Forensics-100K 数据集

100,000 段视频（21,075 真实 / 78,925 伪造），覆盖人脸替换、人脸重演、整脸生成，纳入 Seedance 2.0 等近期生成方法，共 33 种合成方法。重点是**更细粒度的文本监督**：多模型聚合与冲突消解流程生成视觉观察标签 + 与 verdict 一致的取证解释标签。^[raw/articles/北交清华等提出argus多智能体协同断案给视频鉴伪补上证据链.md]

## 训练：先观察后裁判（SFT + GRPO）

基座 Qwen2.5-VL-7B，两阶段：①SFT 分别训练观察智能体与裁判；②冻结观察者，仅用 GRPO 优化裁判——奖励依据最终判断正确性，KL 约束限制相对 SFT 策略偏移（优化分类决策，不直接等于每条解释更准确）。角色分工减少观察阶段过早下结论的影响。^[raw/articles/北交清华等提出argus多智能体协同断案给视频鉴伪补上证据链.md]

## 结果：OOD 泛化

域外测试集 7,636 段视频（5,716 真实 / 1,920 伪造，伪造来自 20 个训练未用生成器）：裁判同时接收观察报告+视频帧时，Accuracy 69.87% / Recall 81.82% / F1 53.28%，均为主表最高——超越小型视觉模型、开源多模态大模型及前沿闭源模型（GPT-4o、Gemini 3.5-Flash）。专门考察未见生成器/身份的泛化。^[raw/articles/北交清华等提出argus多智能体协同断案给视频鉴伪补上证据链.md]

## 方法论意义

这是"分工观察 + 证据裁决"的多智能体模式在鉴伪任务上的系统化应用，与 [[entities/让gui-agent不再边做边忘快手浙大提出memgui-agent攻克长程gui任务|MemGUI-Agent]] 的"分工+裁决"多智能体思路同构：观察者不越权下结论、裁决者面对冲突证据做权衡——可迁移到任何需要可解释证据链的判断型 Agent 系统。

## 深度分析

### 证据独立性与"错误直觉级联"的关系

传统单模型鉴伪的本质缺陷不是准确率低，而是**错误不可拆解**：一次前向传播把感知、推理、判断压缩成一个输出，出了错无法定位是哪一环。ARGUS 把这条隐式流水线显式拆成四个独立观察维度，其更深层的动机是阻断"错误直觉级联"——当多个模型沿同一错误直觉连续推理时，后续步骤只会把初始误判包装得更完整。各观察者在观察阶段被禁止输出真假结论，等于用角色约束强制切断了早期判断对后续感知的污染路径。这与"先假设后求证"的司法取证逻辑同构：证人不该替法官下判决。

### "裁判输入"消融揭示的模态互补性

消融数据里藏着一个容易被忽略的信号：裁判仅看文本观察报告时 F1 为 51.01%，加入原始视频帧后提升 2.27 个百分点。这说明文本化的观察标签本质上是**有损压缩**——观察者报告遗漏的线索仍存在于原始像素中。原始视觉信息与文本观察是互补而非替代关系：前者兜住后者遗漏的证据，后者提供前者不具备的结构化归纳。值得注意的是，两种骨干（Qwen2.5-VL-7B 与 InternVL3.5-8B）的最佳裁判输入并不相同，"多给裁判看帧是否更好"没有普适答案，需要按基座实测。

### GRPO 的收益与代价不对称

训练消融呈现明显的指标取舍：未训练系统 F1 仅 30.07%，联合 SFT 后升至 50.49%，加 GRPO 后到 53.28%——但 Recall 同时从 87.76% 降到 81.82%。GRPO 以最终判断正确性为奖励，天然倾向于压低误报（把真实视频误判为伪造），代价是放过更多伪造样本；在伪造样本占少数的 OOD 测试集（1,920 伪 vs 5,716 真）上，这种偏移会直接反映在召回率上。这提示：用 RL 优化分类决策时，奖励信号里没有"解释质量"这一项，判断变准不等于证据链变好。

### 数据集监督粒度作为被低估的杠杆

FaceVid-Forensics-100K 的价值不在 10 万段的规模，而在监督信号的形态：用多模型聚合与冲突消解流程生成观察标签 + 与 verdict 一致的取证解释标签，等于把"证据链"本身做成了训练目标。33 种合成方法、纳入 Seedance 2.0 等近期生成器、并按"见过/未见来源"划分评测协议，是直接对着泛化短板设计的数据工程。这与 [[entities/seedance-25-zero-frame-video-generation-2026|Seedance 2.5 视频生成]] 所代表的生成器快速迭代形成攻防两面——鉴伪数据集必须持续吞入新生成方法才不会过期。

## 实践启示

1. **判断型 Agent 应把"感知"与"裁决"拆给不同角色，并在角色间设置禁止越权的硬约束**：观察者只报告证据、不下结论，能阻断错误假设沿流水线传播。可迁移到风控审核、医疗分诊、代码评审等任何需要可检查判断链的场景。
2. **用 RL 优化判断决策时，显式接受指标间的取舍**：ARGUS 的 GRPO 换来 F1 提升 2.79 个百分点但 Recall 下降 5.94 个百分点。上线前先想清楚业务上误报和漏报哪个更贵，再决定是否值得 RL 这一档，必要时在奖励中加入召回相关的约束。
3. **给裁判/汇总者同时喂"结构化摘要 + 原始输入"**：纯文本观察是有损压缩——原始信息能补回 2+ 个百分点的判别力，但补益幅度依基座模型而异——两种骨干的最佳输入配置不同，应做消融而非照搬。
4. **训练可解释系统时把解释质量与判断正确性分开评估**：奖励只看 verdict 正确并不保证每条解释更准确；若业务需要可信证据链（如司法、内容审核存证），需要单独的解释评测集。
5. **数据集的评测协议设计比规模更重要**：按"训练见过/未见生成器与身份"切分 OOD 测试，是度量泛化的正确姿势。自建评测集时应模仿这种划分，而不是在混合分布上刷总分。
6. **对抗性任务（鉴伪、攻击检测）的数据集需要持续纳入最新对手**：33 种合成方法、含最新生成器的覆盖，正是 ARGUS 能在未见生成器上领先 GPT-4o 等闭源模型的基础。
