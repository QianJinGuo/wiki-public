## 摘要

文章基于 Rahul 的 Claude Code 27 条技巧长帖重新组织为一条"从个人使用走向团队工作流"的升级路径，分为三组各 9 条：第一组让 Claude Code 少猜（/init 生成 60 行左右的入口卡、复杂任务先计划、描述问题而非下命令、开始前先列澄清问题、把验证写进 Todo）；第二组让过程可控（Subagents 的底层价值是隔离而非并行、重复提示沉淀为 Skills、模型规格匹配任务、CLAUDE.md 持续但克制地维护、跑偏时先停下来重新对齐、UI 任务必须看截图和控制台等真实运行时证据）；第三组谈自动化与长期运行（DevTools 直观运行现场、resume 后先重述边界、worktrees 隔离文件碰撞、API 直连与 MCP 的取舍、Loop 先做只读小闭环、自然语言查数据库先限定只读 SELECT、高思考预算留给疑难问题）。^[raw/articles/2026-06-29-Claude-Code-27-条实用技巧-快速升级-架构师.md]

核心观点是：Claude Code 已经是会进仓库读文件、跑命令、改代码的"执行体"，不能只靠一句提示词，而要给它上下文、边界、验证和停止条件。作者给出具体的上手路径——个人第一周练四个动作（/init、先计划、自检进 Todo、压缩前输出目标/证据/边界），团队第一个月沉淀三件东西（一份短而准的 CLAUDE.md、一个常用 Skill、一个只读验证闭环）；衡量真实收益的信号是返工率下降、任务中断后能接手、验证证据更完整、高风险动作被系统挡住，而非"效率提升多少倍"。^[raw/articles/2026-06-29-Claude-Code-27-条实用技巧-快速升级-架构师.md]

## 关键要点

- CLAUDE.md 维护要有分层判断：每次启动都要知道的放入口文件，某类目录才需要的放局部规则，某个流程才需要的做成 Skill，漏掉会出事故的交给 Hook/权限/CI——自然语言提醒不是安全边界。
- /compact 前让 Claude Code 先输出四件事：当前目标、已验证证据、未完成项、不能碰的边界，避免压缩丢掉关键限制。
- 同一任务用 /compact、换无关任务用 /clear；/context 用于清理前的上下文负担检查。
- Loop 适合重复、可验证、低风险的只读小闭环（CI 失败归类、文档失效链接检查、PR 断言核来源），生产配置和敏感数据不适合一开始就自动化。
- 入口越方便权限边界越要清楚：手机远程控制适合启动构建、拉只读报告等低风险触发，写入、部署、删除、账单要回完整操作环境确认。
