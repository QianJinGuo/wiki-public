# 高德 Push 发送门控 Agent 感知投放：三代架构与约束工程（Harness Engineering）

> 高德技术（信息业务中心）第一方实践：把消息触达系统发送门控的"收/放"交给 LLM Agent——大模型承担态势理解与方向性决策，确定性代码承担数值计算与安全约束。三代架构演进（v1→v2→v3）及工程方法论。^[raw/articles/gaode-push-agent-gate-control-harness-engineering-2026.md]

## 问题：发送门控（Whether 决策）
端外通知决策通常拆成 Who/When/What，之上还有更底层的 **Whether（要不要发）**——发送门控，本质是资源约束下的价值最大化（有限曝光资源，透支损害长期触达能力），与广告 Pacing & Budget Control、推荐 Exposure Allocation 同类。难点在序列性与动态性：每次收/放改变后续资源状态，环境非平稳（流量/消息质量/用户活跃随节假日天气波动），离线定型策略难长期有效。工业界主流"离线建模+在线规则执行"根本假设是环境平稳，传统"人盯+人调"把自适应留给人类。^[raw/articles/gaode-push-agent-gate-control-harness-engineering-2026.md]

## 理论支撑：序列决策与 LLM 生成相通
**Decision Transformer**（Chen et al., NeurIPS 2021）证明把 (状态, 动作, 回报) 编码为 token 序列、自回归建模 P(action | desired_return, state_history) 可直接输出策略，无需估值函数和 Bellman 收敛；序列决策最优解与条件概率生成数学上相通。广告自动出价 AIGB（KDD 2024）已把此思想大规模商用。但发送门控状态空间/奖励信号还在早期、缺高质量 [state,action,reward] 数据，当前阶段走演进第一步——让 Agent 具备环境感知与简单调控（看实时状态、基于规则做收/放、从结果拿反馈），跨过"从完全静态离线门控到在线自适应"。^[raw/articles/gaode-push-agent-gate-control-harness-engineering-2026.md]

## 三代架构演进
**v1 单 Agent 会话**：持久会话+定时任务让 Agent"聊天式"决策。做对了：验证大模型能理解流量调控语义（约束优化直觉）。失败：无状态管理/无安全边界/无容错/不可审计——概念验证，无工程可靠性。^[raw/articles/gaode-push-agent-gate-control-harness-engineering-2026.md]

**v2 多 Agent 协作**：主 Agent+子 Agent 专职分工，共享状态板、决策规范注入。做对了：状态持久化/职责分离/实验框架/自进化机制。两周后策略震荡被停用——五个系统级问题：①多 Agent 错误放大效应（残缺数据不被质疑、链路无纠错，Google DeepMind 证实错误可放大一个数量级）；②会话死锁（接口超时会话锁不释放）；③幻觉驱动"自我说服"（把样本噪声当规律、用推理"论证"例外去修正规则）；④通信成本挤占推理空间（频繁 Agent 沟通降低整体效果）；⑤单 Agent 够用后堆 Agent 边际递减甚至为负（真正瓶颈不是推理不够强，而是推理结果没有被约束）。^[raw/articles/gaode-push-agent-gate-control-harness-engineering-2026.md]

**v3 单 Agent + 约束工程（Harness Engineering）**：设计哲学"Agent 做指挥官（选策略），代码做计算器（算数值）"。五阶段流水线（Observe→Think→Guard→Apply→Log）只有推理用大模型；常驻调度器发起全新无状态请求（消灭会话死锁）。**离散策略空间（6 选 1）**：HOLD/TIGHTEN_SMALL/LARGE/LOOSEN_SMALL/LARGE/EMERGENCY_RECOVER，动作空间降维，数值由代码按固定步长算并钳位回安全工作区间。**9 项硬检查约束**：普通代码检查，Agent 输出必须全部通过才能执行——从失败里长出来的免疫系统；渐进信任（试运行第一周只小步、第二周大步、正式维持大步上限，类比金融新交易员限额）。**状态管理（文件是记忆不是会话）**：状态快照/决策日志/参数配置/共享状态板/日终蒸馏报告，进度持久化在文件系统而非上下文窗口。**交易日制度（开盘/交易/收盘）**：固定时刻多轮，延迟保护（上轮刚调本轮强制 HOLD）解决 v2"刚调完就看数误以为调整没用"的震荡。**蒸馏闭环**：独立蒸馏 Agent 收盘把当天决策日志蒸馏成报告，通过检索渐进式披露注入次日推理（不是把整个知识库塞进提示词）。^[raw/articles/gaode-push-agent-gate-control-harness-engineering-2026.md]

## 核心工程洞察
1. **约束工程 > 提示工程**：提示工程可靠性上界是模型注意力极限（概率性），约束工程上界是代码正确性（确定性）。Agent 价值不在遵守规则（代码做得比它好一万倍），而在理解复杂局势、权衡多维信号、做方向性判断。**系统可靠性 = 模型推理能力 × 代码约束能力**。
2. **文件是记忆，会话是幻觉**：状态应活在文件里而非会话里（会话会断/溢出/死锁，文件持久/可审计/可恢复）。v3 每轮无状态：读快照恢复上下文、调用模型拿决策、写回文件，进程可随时杀死重启不丢状态。
3. **渐进式能力披露（Agent Skills）**：把领域知识封装成独立技能文件，主 Agent 运行中缺什么读什么（先目录概览定位、缺知识再加载下一块）。从多 Agent"分而治之"到 Agent Skills"聚而用之"：上下文割裂/有损传输→全局一致；高维护成本→低；复用性重新构建→跨任务即插即用。
4. **信任像贷款一样渐进释放**：初始权限严格限制，靠持续稳定运行"赚取"更大操作空间（等同 RL 探索/利用权衡）。^[raw/articles/gaode-push-agent-gate-control-harness-engineering-2026.md]

## 深度分析
### 一、门控决策是"是否"问题，不是"生成"问题
生成式决策的输出是内容，正确性由偏好或下游指标事后判定，单次错误的代价通常落在"这一次输出不够好"的局部，可以被重试消费掉。门控决策的输出是资源分配动作，它改变的是后续所有轮次可用的状态——剩余配额、通道疲劳度、用户容忍度。这意味着一次判断的误差不是被消费，而是被写进环境里继续生效；下一轮读到的是被上一轮污染过的状态，并把它当成新证据。v2 的策略震荡正是这个闭环的产物：刚调完就看数，看到的是旧门控的效果，误以为调整没用又调回去。

更难的是反馈的时间结构。生成任务能在同一轮内自检或让评估器打分；门控的因果归因必须跨过一整个观察窗口——门控从决策到生效有分钟级延迟，而配额消耗与点击率变化要到当天晚些才可读。所以"我刚调完就看到指标变差"这句话本身没有信息量。文章用交易日制度把这件事变成制度约束：固定决策时刻让"现在看到的数据对应哪次门控"可判定，延迟保护（上轮刚调本轮强制 HOLD）让两次调整之间至少隔一个完整窗口。^[raw/articles/gaode-push-agent-gate-control-harness-engineering-2026.md:59] 这不是流程美学，而是把一个不可分辨的因果窗口强行切成可分辨的。

由此可以定出 LLM 的可用边界。模型的强项在语义态势理解：给它实验组/对照组的发送量、点击量、点击率，它能读出"增量点击率跌破效益底线应收紧"这类判断，这是预训练里已有的约束优化直觉，v1 已经验证过。它不可靠的地方是把判断落到数值——连续门控值的动作空间近乎无限，幻觉不需要编造一个荒谬的数，只需输出一个"看起来合理但越界"的数。所以 v3 的选择不是提高模型精度，而是把不可穷尽的空间换成可穷尽的空间：6 个枚举动作加代码按固定步长算值并钳位。本质是把生成降级为分类，让错误分布从连续区间收敛到有限集合。

### 二、三代架构的强制约束：每一代放弃了什么
把 v1→v2→v3 读成"越来越好"会漏掉关键结构：每一代都在做明确交换。v1 用工程可靠性换验证速度——持久会话加定时任务几乎零成本地回答了"模型能否理解流量调控语义"这个问题，而且答案是有价值的（能）。它放弃的是状态管理、安全边界、容错、审计，这四项恰好构成线上系统的全部。

v2 的交换更隐蔽：它用中心化纠错能力换取职责分离。共享状态板、实验组/对照组评估体系、日终总结这些组件确实被 v3 继承，但多 Agent 拓扑同时引入了不可修的缺陷——取数角色返回残缺数据时无人质疑，执行角色忠实写入线上，链路里没有任何环节有纠错的授权；持久会话在接口超时时锁不释放，连续多轮停摆只能人工重启；固定上下文预算被 Agent 间指令与回传吃掉后推理空间被挤压。^[raw/articles/gaode-push-agent-gate-control-harness-engineering-2026.md:43-47] 后两个问题（幻觉自我说服、堆 Agent 边际为负）指向同一个诊断：瓶颈不在推理能力不够强，而在推理结果没有被约束。

因此 v3 也放弃了三样东西，且都是有代价的：放弃窗口内的自适应（强制 HOLD 意味着系统在最想知道效果的时候必须不动）、放弃表达精度（6 个动作无法表达"只放 3%"）、放弃参数级学习（知识只以检索文本形式积累，不进权重）。它买回的是确定性与可审计性。判断这笔交换是否划算的标准不是"v3 更强"，而是"这个场景的损失函数是否容忍粒度损失"——发送门控每天重开一次、配额按日恢复、收盘回到默认值，粒度损失可以在次日修正，这才是它能成立的前提条件。

### 三、五项机制互相咬合，而不是五条最佳实践
把 9 项硬检查、离散动作空间、无状态调度、渐进信任、蒸馏闭环当成分立的实践清单，会低估这套设计。它们各自封的是别人封不住的口子。离散化不是为了"简单"，而是让约束检查在数学上可穷尽：v2 的连续值空间里任何不合理点都可能被生成，检查只能抽样；压到 6 个动作后，"输出必须通过全部 9 项检查"才成为一个可枚举的判定。反过来看，若动作空间不离散，9 项检查就退化成阈值告警——它仍然会响，但拦不住。

无状态调度保证的是"检查是模型输出到线上的唯一通路"。会话复用的风险不只是死锁，还有上下文里残留的"上次为什么可以例外"——v2 的幻觉自我说服正是靠这条通道复活的。每轮发起全新请求、状态从文件快照重建，等于强制模型每一轮都面对当前事实，而不是面对自己上一轮的论证。这也是"文件是记忆"的技术含义：记忆不可被模型在推理中悄悄改写。

渐进信任改变的则是检查需要保证的东西。第一周只允许小步，意味着即使 9 项检查全部失效，最大损失仍被步长锁住；第二周放开大步，是把"模型在真实分布上稳定"这一经验证据兑换成权限。^[raw/articles/gaode-push-agent-gate-control-harness-engineering-2026.md:55] 它与 RL 的探索/利用权衡同构，但落点是工程纪律而非算法。蒸馏闭环补的则是无状态扔掉的东西：学习能力。关键细节是蒸馏由独立 Agent 执行而非主 Agent 自评——这条职责分离把 v2 的自我说服从记忆入口挡掉了，否则当天被"论证"出来的例外会以"已验证规则"的身份污染次日推理；知识库从空开始、只收多日数据支撑的规则、按当前状态检索注入，等于给记忆同时加了样本量门槛和带宽上限。

### 四、失效边界：这套模式在哪里不成立
可迁移性由三个量决定：错误代价是否有界、决策是否高频、状态是否可逆。发送门控三项都占——单次误判的损失被步长与配额上限夹住，一天多轮所以总有下一次修正机会，收盘恢复默认值所以最坏情况有一个 floor。9 项检查、强制 HOLD、渐进信任之所以负担得起，是因为它们是在一个本来就容错的环境里加保险，而不是在替环境承担风险。

换成低频、高代价、不可逆的决策——定价条款、授信额度、一次性合约、删除类操作——同一套机制会失效在根上：没有下一轮可以用来学习，步长无法把损失夹住，"先小步试运行"这个动作本身就不存在。这类场景里约束只能从动作空间上移到人工审批，Agent 的角色退化为推荐者；硬套 6 选 1 只会让人误以为风险已被管住。这也是 [[concepts/when-not-to-harness-engineering|何时不该做 Harness 工程]] 的核心判据：harness 的建造成本只有在错误能被反复、廉价地试探时才收得回来。

还有两个更细的失效点。其一是奖励信号的可观测性：如果推送疲劳对长期留存的影响落在观察窗口之外，蒸馏闭环会把表观指标当真值，学出"白天把门控放低"这类局部最优规则。文章自己承认状态空间与奖励信号仍处早期^[raw/articles/gaode-push-agent-gate-control-harness-engineering-2026.md:31]，所以那些蒸馏出的规则是对指标的假设，不是对目标的证明。其二是 9 项检查的性质：它们是结构与数值检查，能拦住越界和非法枚举，拦不住"数据本身是残缺的"。v2 的第一个事故——取数超时返回不完整数据被当成暴跌证据——在 v3 里依然可能发生，只是后果被步长限制、被 HOLD 延迟放大。要真正闭合，Observe 阶段需要独立的数据完备性断言，而不是指望 Guard 阶段发现语义问题。

## 实践启示
1. **先问动作空间能不能枚举**：如果无法把合法动作压到 10 个以内、且每个动作的数值能由代码算出并钳位，就不要让 Agent 直接写参数，那还是在做 v2。同时确认存在一个代码可直接写入的默认安全值（对应 EMERGENCY_RECOVER），没有 floor 的系统不要交给 Agent。
2. **每条约束都要能追溯到一次真实事故**：9 项检查不是设计出来的安全清单，而是失败案例的解剖结果。新增检查时先写清"它对应哪次线上异常、用什么回归验证"，否则会积累一堆永不触发的装饰性规则，反而稀释真正的拦截。
3. **决策与计算分离，分离线画在枚举边界上**：Agent 只输出动作名，数值、步长、钳位、边界全部归代码。评审时问一句"模型能不能输出一个越界的数"，能，就说明还没分干净。
4. **把状态放到文件系统，让进程随时可杀**：快照覆盖写、决策日志按日归档只追加、配置只读、共享板双方可写、日终报告次日启动时读。任何依赖会话记忆的状态，都会在超时和重启时变成幻觉。
5. **先解决因果可分辨，再谈自适应**：固定决策时刻，上一轮调整后强制 HOLD 至少一个完整观察窗口。缺这一条，团队必然把旧门控的效果读成新策略的反馈，然后开始震荡。
6. **权限按证据释放，蒸馏按职责分离**：新系统第一周只给小步，稳定运行后再放开上限；蒸馏交给独立角色，只收多日验证的规则，按当前状态检索注入。让决策者总结自己，等于把自我说服写进长期记忆。
