## 摘要

本文由 LangChain 开发者 Sydney Runkle 撰写，主张 Agent 的可靠性不能只靠好模型，而要靠精心设计的循环栈（引 swyx 的"loopcraft: the art of stacking loops"），并给出四层循环的工程实现：第一层 Agent 循环（模型在循环中调工具直到任务完成，对应 create_agent）；第二层验证循环（加评分器按评分标准检查输出、失败带反馈重试，评分器可以是确定性的或 LLM-as-judge，对应 RubricMiddleware）；第三层事件驱动循环（用 cron 定时与 webhook 把 Agent 接入生态系统后台运行，对应 LangSmith Deployment 与 Fleet 的 channels/schedules，典型案例是 openclaw 的 heartbeats）；第四层爬山循环——最重要的循环，自动化的是"改进"本身：分析 Agent 读取生产 trace，发现重复问题后提交 issue，直接重写运行框架的 prompt、工具或评分器配置。文章以内部文档 Agent（克隆仓库、读文件、写文档、开 PR，评分器跑测试查链接和 CI）为贯穿示例，并强调每层都可接入人工监督：Agent 循环中对敏感动作要求人工输入、验证循环让人类当评分器、应用循环输出前人工批准、爬坡循环改进部署前人工审核。结尾引 Satya Nadella 的判断：早早建立学习循环的公司让人类判断与 token 资本持续累积，将形成难以复制的优势。^[raw/articles/2026-06-17-别只盯着模型-Agent-真正的护城河-是这四层循环-高可用架构.md]

## 关键要点

- 四层循环分工：Agent 循环自动化工作、验证循环保证质量、事件循环规模化工作、爬坡循环持续改进；前三层自动化工作，第四层自动化改进
- 验证循环权衡：加入验证会增加每次运行的延迟和成本，当质量比速度重要时值得（大多数生产用例如此）；文档 Agent 评分器检查链接可访问、CI 通过、diff 只覆盖请求范围
- 爬坡循环的关键动作：外层循环的返回箭头不是回到最上层，而是伸进内部直接更新 Agent 循环——外层每跑一轮，内层变得更有效；LangSmith 的 trace 分析 Agent Engine 可搭建该层
- 爬坡循环的扩展方向：开放权重模型团队可接入 RL 微调，把 trace/eval 结果作为训练信号改进模型本身；记忆、检索到的技能等辅助上下文也可同样改进
- 人工监督落点：金融交易、数据库操作等敏感操作需要实时人工审核；发现"表达方式是否适合目标读者"这类品味判断是人工审核价值所在
- 文中 LangChain 组件映射：create_agent（第 1 层）、RubricMiddleware（第 2 层）、LangSmith Deployment/Fleet channels+cron/webhook（第 3 层）、LangSmith Engine（第 4 层）
