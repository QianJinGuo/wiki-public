## 摘要

本文由 LangChain 开发者 Sydney Runkle 撰写，主张 Agent 的可靠性不能只靠好模型，而要靠精心设计的循环栈（引 swyx 的"loopcraft: the art of stacking loops"），并给出四层循环的工程实现：第一层 Agent 循环（模型在循环中调工具直到任务完成，对应 create_agent）；第二层验证循环（加评分器按评分标准检查输出、失败带反馈重试，评分器可以是确定性的或 LLM-as-judge，对应 RubricMiddleware）；第三层事件驱动循环（用 cron 定时与 webhook 把 Agent 接入生态系统后台运行，对应 LangSmith Deployment 与 Fleet 的 channels/schedules，典型案例是 openclaw 的 heartbeats）；第四层爬山循环——最重要的循环，自动化的是"改进"本身：分析 Agent 读取生产 trace，发现重复问题后提交 issue，直接重写运行框架的 prompt、工具或评分器配置。文章以内部文档 Agent（克隆仓库、读文件、写文档、开 PR，评分器跑测试查链接和 CI）为贯穿示例，并强调每层都可接入人工监督：Agent 循环中对敏感动作要求人工输入、验证循环让人类当评分器、应用循环输出前人工批准、爬坡循环改进部署前人工审核。结尾引 Satya Nadella 的判断：早早建立学习循环的公司让人类判断与 token 资本持续累积，将形成难以复制的优势。^[raw/articles/2026-06-17-别只盯着模型-Agent-真正的护城河-是这四层循环-高可用架构.md]

## 关键要点

- 四层循环分工：Agent 循环自动化工作、验证循环保证质量、事件循环规模化工作、爬坡循环持续改进；前三层自动化工作，第四层自动化改进
- 验证循环权衡：加入验证会增加每次运行的延迟和成本，当质量比速度重要时值得（大多数生产用例如此）；文档 Agent 评分器检查链接可访问、CI 通过、diff 只覆盖请求范围
- 爬坡循环的关键动作：外层循环的返回箭头不是回到最上层，而是伸进内部直接更新 Agent 循环——外层每跑一轮，内层变得更有效；LangSmith 的 trace 分析 Agent Engine 可搭建该层
- 爬坡循环的扩展方向：开放权重模型团队可接入 RL 微调，把 trace/eval 结果作为训练信号改进模型本身；记忆、检索到的技能等辅助上下文也可同样改进
- 人工监督落点：金融交易、数据库操作等敏感操作需要实时人工审核；发现"表达方式是否适合目标读者"这类品味判断是人工审核价值所在
- 文中 LangChain 组件映射：create_agent（第 1 层）、RubricMiddleware（第 2 层）、LangSmith Deployment/Fleet channels+cron/webhook（第 3 层）、LangSmith Engine（第 4 层）

## 深度分析

### 循环栈的本质：护城河在框架而不在模型

文章的论证结构值得注意：它把"Agent 为什么可靠"这一问题从模型层面整体搬到了框架层面。核心算法本身极简单——给 LLM 上下文，让它在循环中调用工具直到任务完成——正因如此，模型间的差距容易被框架设计抹平。作者引 swyx 的 loopcraft（stacking loops 的艺术）把这组设计上升为可独立修炼的手艺：循环的叠加与扩展才是构建有效 Agent 的杠杆点。^[raw/articles/2026-06-17-别只盯着模型-Agent-真正的护城河-是这四层循环-高可用架构.md:18-22]

这一判断与 Steipete、Boris、Andrej 等从业者的公开结论互相印证：Agent 的潜力在于围绕它构建的循环。^[raw/articles/2026-06-17-别只盯着模型-Agent-真正的护城河-是这四层循环-高可用架构.md:117] Satya Nadella 进一步上升到组织竞争层面：早早建立学习循环的公司让人类判断与 token 资本持续累积，形成难以复制的优势。^[raw/articles/2026-06-17-别只盯着模型-Agent-真正的护城河-是这四层循环-高可用架构.md:121]

四层分工清晰：Agent 循环自动化工作，验证循环保证质量，事件驱动循环规模化工作，爬坡循环持续改进。第三层的价值在于把 Agent 从"需要手动调用的东西"变成生态系统中持续运行的组件——新文档落地、定时任务、webhook 到达都可以触发运行，Fleet 的 channels/schedules 与 openclaw 的 heartbeats 是其典型实现。^[raw/articles/2026-06-17-别只盯着模型-Agent-真正的护城河-是这四层循环-高可用架构.md:48-56] 贯穿全文的文档 Agent 则示范了第一层的完整形态：克隆仓库、读取文件、编写文档、打开 pull request。^[raw/articles/2026-06-17-别只盯着模型-Agent-真正的护城河-是这四层循环-高可用架构.md:26-30]

### 第四层为何最重要：返回箭头的指向

前三层自动化"工作"，第四层自动化"改进"本身。每次运行产生的 trace 记录了模型行为、工具调用与评分器反馈；爬坡循环让分析 Agent 读取 trace，在多条 trace 指向同一问题时提交 issue，直接重写运行框架的 prompt、工具或评分器配置。^[raw/articles/2026-06-17-别只盯着模型-Agent-真正的护城河-是这四层循环-高可用架构.md:60-66]

关键动作是返回箭头的指向：不是回到最上层，而是伸进内部直接更新 Agent 循环——外层每跑一轮，内层变得更有效。改进对象也是开放的：开放权重模型团队可接入 RL 微调，把 trace/eval 结果作为训练信号改进模型本身；记忆与检索到的技能可用同样方式改进。^[raw/articles/2026-06-17-别只盯着模型-Agent-真正的护城河-是这四层循环-高可用架构.md:68-70] 文末的对照表把四层收敛成一页速查：循环 1 自动化工作、循环 2 保证质量、循环 3 规模化工作、循环 4 持续改进，并逐一给出对应的 LangChain 组件。^[raw/articles/2026-06-17-别只盯着模型-Agent-真正的护城河-是这四层循环-高可用架构.md:92-115] 作者的路线判断同样明确：循环 1 和循环 2 已被思考很久，现在的焦点应转向循环 3 和循环 4——价值在那里持续累积。

### 验证循环的经济学：用延迟换质量

验证循环在 Agent 外包一层评分器：按评分标准检查输出，失败带反馈重试；评分器可以是确定性检查，也可以是 LLM-as-judge。^[raw/articles/2026-06-17-别只盯着模型-Agent-真正的护城河-是这四层循环-高可用架构.md:34-38] 对权衡的表述很务实：加入验证会增加每次运行的延迟与成本，"当质量比速度更重要时它是值得的，而大多数生产用例都属于这种情况"。^[raw/articles/2026-06-17-别只盯着模型-Agent-真正的护城河-是这四层循环-高可用架构.md:44] 文档 Agent 评分器给出可抄的检查清单：测试通过、链接可访问、CI 通过、diff 只覆盖请求范围——这几类错误不需要人工审核。^[raw/articles/2026-06-17-别只盯着模型-Agent-真正的护城河-是这四层循环-高可用架构.md:40]

### 人工监督的四层触点

人工监督不是外挂补丁，而是每层都有自然落点：Agent 循环对敏感动作要求人工输入，验证循环让人类为敏感工作流担任评分器，应用循环在输出返回用户前由人批准，爬坡循环的改进在部署前经人工审核。^[raw/articles/2026-06-17-别只盯着模型-Agent-真正的护城河-是这四层循环-高可用架构.md:74-86] 对人工审核价值的定位尤其准确：自动评分器能检查链接可访问性，但"表达方式是否适合目标读者"这类品味判断只能由人完成——来自上下文、经验与品味的判断正是人工审核的价值所在。

## 实践启示

1. **从第四层开始规划而非最后补**：trace 数据从第一天就在产生，若运行框架没有把 trace 分析与配置改写做成循环，这些数据只是存储成本；LangSmith Engine 是现成的第四层实现参照。
2. **评分器清单先行**：不必一步到 LLM-as-judge，先用确定性检查（测试、链接可达、CI、diff 范围）覆盖机器可判定的错误，把人工审核留给品味判断。
3. **延迟预算按用例分配**：质量/速度权衡不是全局开关，按工作流分别决定——文档类任务可慢而准，实时对话要收缩验证深度。
4. **敏感操作保留人工审核位**：金融交易、数据库操作等动作无论循环栈多成熟都保留实时人工审核；自动化程度提升应把人挪到评分器与爬坡审核位，而不是移出循环。
5. **爬坡循环优先改配置而非代码**：让分析 Agent 改 prompt、工具、评分器等可热更配置，框架代码改动仍走人工审核的 PR 流程。
6. **与已有循环框架互参**：四层栈与 [[concepts/loop-engineering-methodology|Loop Engineering 方法论]]、[[concepts/agent-self-improvement-loops|Agent 自改进循环]] 高度同构，可与 [[entities/loop-engineering-langchain-four-layer-loopcraft|四层循环栈（另一来源）]] 及 [[entities/langsmith-engine-self-improving-agent-trace-based|LangSmith Engine 专题]] 对照阅读。
