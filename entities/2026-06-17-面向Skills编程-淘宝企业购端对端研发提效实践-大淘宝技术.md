## 摘要

淘天行业运营技术团队提出"面向Skills编程"范式：把领域知识、工作流、约束规则封装为可版本化的 Skills 单元，让 LLM 在确定性框架内生成代码，实现从"人写代码"到"人沉淀 Skills、AI 写代码"的升级；经半年实践（2025.8-2026.2），商品域端到端交付周期从 23.5 人日缩短至 8 人日（提效 65%），代码一次生成成功率从不足 50% 提升到 90% ^[raw/articles/2026-06-17-面向Skills编程-淘宝企业购端对端研发提效实践-大淘宝技术.md]。文章完整记录了五阶段演进：Vibe Coding 验证可行性但产出不稳定 → Prompt 模板把代码采纳率提到 70% 但无法约束中间思考过程 → SDD 规范驱动把可用率提到 80% 但 Spec 编写强依赖个人经验 → Skill 沉淀（Anthropic Agent Skills 标准：SKILL.md + references/ + scripts/）实现"经验即代码" → 云端集成（OneDay + Aone 沙箱生码平台）让产品业务等非技术角色也能触发全链路 ^[raw/articles/2026-06-17-面向Skills编程-淘宝企业购端对端研发提效实践-大淘宝技术.md]。调优方法论的关键结论是：50% 到 90% 的提升全部来自知识注入和约束迭代而非换更强的模型；高精度环节用确定性脚本（如接口提取）、模型不稳定的用架构拆分绕过（推拉分离、每个接口独立子 Skill、约 8k tokens 粒度）、反复出错的沉淀为约束（ADJUSTMENT_PLAN 机制把 11 类高频问题全部收敛） ^[raw/articles/2026-06-17-面向Skills编程-淘宝企业购端对端研发提效实践-大淘宝技术.md]。文章还介绍了三层原子能力/模板/适配分层架构（适配层代码量减少 60%、原子服务覆盖 90%+ 对接场景）和三级索引知识库与 kn-fetcher 分发工具 ^[raw/articles/2026-06-17-面向Skills编程-淘宝企业购端对端研发提效实践-大淘宝技术.md]。

## 关键要点

- 业务背景：淘宝企业购"定制对接模式"需反向适配大中型客户（自研商城、外部 SaaS 采购平台）的接口规范，涉及商品、交易、结算三大业务域，适配代码几乎无法跨项目复用
- 阶段 2→4 的典型失败案例与修复：某 ISV 15 个接口 AI 只完整实现前 4 个、后续用"类似"带过，解法是把方案生成拆为 pull-generator 编排加 pull-indexer、pull-model-designer、pull-interface-generator × N 四个子 Skill；阶段 4 还解决了接口提取幻觉（脚本提取为主、AI 只做理解格式与检查补漏）、领域知识缺失（SPU/SKU 映射规则等内嵌进 references）与长上下文崩塌（每接口独立上下文处理）
- 代码生产阶段的工程化：ego-project-initialization Skill 前置工程初始化（占位符替换、AKSK 生成、Maven 编译验证）、四类代码模板驱动生成、按依赖顺序生成（通用基类→请求类→响应类→转换器→SPI 实现）
- 质量四层防线：事前约束 → 运行时约束 → 事后审查 Skill → 人工卡点；实测项目审查结果为接口覆盖 15/15、字段遗漏率 0%、映射方向全对
- 知识库三载体与 kn-fetcher CLI（pull/list/search 等命令），三级索引 GUIDE.md → rules/index.md → 知识文件（含标准化元数据），支持渐进式拉取
