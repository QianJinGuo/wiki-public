TokenSpeed 技术简介

TokenSpeed 从第一性原理出发， 专门为智能体推理场景设计。 它为智能体负载提供接近「光速级」的推理能力，核心包括：基于编译器的并行建模机制、高性能调度器、安全的 KV 资源复用约束、支持异构加速器的可插拔分层 kernel 系统，以及用于低开销 CPU 侧请求入口的 SMG 集成。 ^[raw/articles/2026-05-07-英伟达力荐-小团队两个月开源一款-光速级-智能体推理引擎-机器之心.md]

建模层 采用本地 SPMD（Single Program, Multiple Data，单程序多数据）设计，在性能与易用性之间取得平衡。TokenSpeed 允许开发者在模块边界指定 I/O placement 注解。随后，一个轻量级静态编译器会在模型构建过程中自动生成所需的 collective operation，从而无需手动实现通信逻辑。 ^[raw/articles/2026-05-07-英伟达力荐-小团队两个月开源一款-光速级-智能体推理引擎-机器之心.md]

TokenSpeed 调度器 将控制平面（control plane）与执行平面（execution plane）解耦。 ^[raw/articles/2026-05-07-英伟达力荐-小团队两个月开源一款-光速级-智能体推理引擎-机器之心.md]

控制平面使用 C++ 实现，并被构建为一个有限状态机（FSM），结合类型系统，在编译期而非运行期强制执行安全资源管理，包括 KV cache 状态转移与使用。请求生命周期、KV cache 资源以及重叠执行时序，都通过显式 FSM 状态迁移与所有权语义进行表示，因此系统正确性并非依赖约定，而是由一个可验证的控制系统来保证。 ^[raw/articles/2026-05-07-英伟达力荐-小团队两个月开源一款-光速级-智能体推理引擎-机器之心.md]

执行平面则使用 Python 实现，以保持开发效率，使研究人员与工程师能够更快进行功能迭代，并降低整体认知负载。 ^[raw/articles/2026-05-07-英伟达力荐-小团队两个月开源一款-光速级-智能体推理引擎-机器之心.md]

TokenSpeed 的 kernel 层 将 kernel 从核心引擎中解耦，并将其视为一级模块化子系统。它提供了可移植的公共 API、集中的注册与选择机制、组织良好的实现结构、面向异构加速器的可扩展插件机制、经过整理的依赖体系，以及统一的快速迭代基础设施。 ^[raw/articles/2026-05-07-英伟达力荐-小团队两个月开源一款-光速级-智能体推理引擎-机器之心.md]

与此同时，团队还针对 NVIDIA Blackwell 架构进行了大量性能优化。例如，他们构建了 当前智能体负载场景下速度最快的 MLA（Multi-he ^[raw/articles/2026-05-07-英伟达力荐-小团队两个月开源一款-光速级-智能体推理引擎-机器之心.md]

## 深度分析

### 架构拆解：编译器并行建模 + 双平面调度 + 可插拔 kernel

核心包括基于编译器的并行建模机制、高性能调度器、安全的 KV 资源复用约束、可插拔分层 kernel 系统与低开销 CPU 侧请求入口^[raw/articles/2026-05-07-英伟达力荐-小团队两个月开源一款-光速级-智能体推理引擎-机器之心.md:36]。建模层采用本地 SPMD 设计：开发者只需在模块边界标注 I/O placement，静态编译器即在模型构建期自动生成 collective operation，免去手写通信逻辑^[raw/articles/2026-05-07-英伟达力荐-小团队两个月开源一款-光速级-智能体推理引擎-机器之心.md:38]；调度器将控制平面（C++ 实现的 FSM）与执行平面（Python，保留迭代效率）解耦；kernel 层是支持异构加速器的一级模块化子系统^[raw/articles/2026-05-07-英伟达力荐-小团队两个月开源一款-光速级-智能体推理引擎-机器之心.md:40-46]。

相关概念：[[concepts/inference-optimization]]、[[concepts/attention-mechanism]]。

### 智能体负载、KV-cache 与调度设计

Coding Agent 上下文常超 50K tokens、对话数十轮，多数公开基准无法捕捉这种行为^[raw/articles/2026-05-07-英伟达力荐-小团队两个月开源一款-光速级-智能体推理引擎-机器之心.md:54]。流量结构随之改变：prefill 集中于带长前缀 KV cache 的 prefill（五种典型负载），decode 是小 batch 带 speculative decoding 的长前缀场景；优化目标变为在维持单用户 TPS 下限（通常 70，有时 200+）的同时最大化单 GPU TPM^[raw/articles/2026-05-07-英伟达力荐-小团队两个月开源一款-光速级-智能体推理引擎-机器之心.md:56]——这是「延迟下限约束下的吞吐最大化」，与 chat serving 的无约束吞吐优化是两类问题。KV 侧，请求生命周期、KV 资源与重叠时序全部表示为显式 FSM 状态迁移与所有权语义，由类型系统在编译期强制执行，把运行时竞态与泄漏前移到构建期^[raw/articles/2026-05-07-英伟达力荐-小团队两个月开源一款-光速级-智能体推理引擎-机器之心.md:42]。MLA 针对长前缀调优：decode kernel 将 q_seqlen 与 num_heads 分组以填满 Tensor Core，prefill kernel 精调 softmax，且已被 vLLM 上游采用^[raw/articles/2026-05-07-英伟达力荐-小团队两个月开源一款-光速级-智能体推理引擎-机器之心.md:48,50]。

相关概念：[[concepts/coding-agent-architecture]]、[[concepts/speculative-decoding]]。

### 基准声明及其局限

评估基于 SWE-smith 轨迹（与 EvalScope 合作，团队称其密切反映生产 Coding Agents 流量），以 TPS/User 对 TPM/GPU 帕累托曲线对照 Blackwell SoTA 的 TensorRT-LLM；在 Kimi K2.5、无 PD 解耦、Attention TP4 + MoE TP4 配置下，声称整个帕累托前沿均占优：batch 1 约快 9%，100 TPS/User 附近吞吐约高 11%，带 speculative decoding 的解码延迟几乎减半^[raw/articles/2026-05-07-英伟达力荐-小团队两个月开源一款-光速级-智能体推理引擎-机器之心.md:56-70]。Caveats：曲线均不含 PD 解耦；项目 2026 年 3 月中旬才启动，PD 分离、KV 存储仍在合并^[raw/articles/2026-05-07-英伟达力荐-小团队两个月开源一款-光速级-智能体推理引擎-机器之心.md:72]；数据为厂商自评，对照品不含 vLLM/SGLang，也无完整复现配置，宜作方向性信号而非精确结论。

## 实践启示

1. **重定义优化目标**：智能体 serving 指标是「单用户 TPS 下限（70-200）约束下单 GPU TPM 最大化」——容量规划先定下限，再按帕累托前沿选并发点。
2. **用编译期手段消灭运行时资源错误**：FSM + 类型系统在编译期强制 KV cache 所有权与状态迁移，自建推理基础设施时可把关键资源生命周期做成静态可验证的约束。
3. **优先优化长前缀 prefill**：五种典型负载全是带长前缀 KV cache 的 prefill，50K+ 上下文应用应先做前缀复用与 prefill kernel 调优。
4. **看清自评基准的边界**：9%/11%/近 2× 数据均不含 PD 解耦且底层未完成^[raw/articles/2026-05-07-英伟达力荐-小团队两个月开源一款-光速级-智能体推理引擎-机器之心.md:56-72]——POC 应回放自有流量，并优先验证 MLA 内核替换（已入 vLLM）等低成本路径。
