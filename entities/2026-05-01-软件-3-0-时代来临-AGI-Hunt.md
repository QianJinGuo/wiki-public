## 摘要

文章梳理 Karpathy 在 Sequoia AI Ascent 2026 炉边对话及后续长帖中提出的"Software 3.0"框架：Software 1.0 是人写代码（作者），2.0 是用数据训练神经网络（教练，2017 年他提出"训练即编程、数据集就是源代码"），3.0 则是通过 prompt、上下文、Agent、工具、记忆和验证来编程（指挥官）——LLM 成了新型计算解释器，prompt 就是源代码，context window 成为新的编程界面。Sequoia 合伙人 Stephanie Zhan 用一句话概括对话核心："Vibe Coding 抬高的是地板，Agentic Engineering 抬高的是天花板"——前者让不懂编程的人能用自然语言做出可用应用，后者要求专业开发者设计 Agent 生成、编码、测试、互查的整套系统而不牺牲安全与可维护性。Karpathy 自述 2025 年 12 月经历了从自己写 80% 代码到 Agent 写 80% 的"翻转"，甚至患上每天对 Agent 说话 16 小时的"AI 精神病"。^[raw/articles/2026-05-01-软件-3-0-时代来临-AGI-Hunt.md]

两个关键论断值得注意。其一是"传统软件自动化的是你能规格化的东西，AI 自动化的是你能验证的东西"：模型能重构十万行代码库、发现零日漏洞，却会说"你的车在 50 米外的洗车店，建议步行过去"——这种"锯齿状智能"不仅与可验证性有关，还与经济学有关，TAM 决定实验室 RL 训练覆盖哪些领域；创业机会在于找到可构造验证环境但尚未被大实验室 RL 覆盖的领域。其二是他自己的 MenuGen 项目：拍照菜单直接交给 Gemini 在原图上叠加菜品图片，传统 OCR→NLP→图像搜索→前端的中间层整个变得多余——"有些应用不是被做得更快了，是被模型原生能力直接吞掉了"。他还主张未来软件应为 Agent 重写而完全不考虑人类用户（用 .md 文件替代 .sh 安装脚本，"LLM 就是一个高级的英文解释器"），同时强调系统规格设计、概念理解和品味是人的不可外包之处——"你可以外包你的思考，但不能外包你的理解"。^[raw/articles/2026-05-01-软件-3-0-时代来临-AGI-Hunt.md]

## 关键要点

- Software 2.0 文章写于 2017 年 11 月 Karpathy 还在 Tesla 做 Autopilot 时，他自认写得太早、没预见到 LLM。
- Harness 概念最早由 HashiCorp 联创 Mitchell Hashimoto 于 2026 年 2 月提出：每当 Agent 犯一个错，就工程化一个方案让它不再犯。
- Anthropic 的长时运行 Agent 方案：搭建环境、创建进度文件（claude-progress.txt）、建立基准 commit，每个新 context window 先读 git log 和进度文件再继续。
- 三代软件中人类角色从作者→教练→指挥官（how→show→what），失去执行细节控制、获得更高层次杠杆；瓶颈从 GPU 空闲变成 token 没花完。
- Karpathy 的远景展望是"全神经计算"：绝大多数计算由神经网络处理，传统 CPU 降级为协处理器。

## 深度分析

### 可验证性是新自动化边界的真正判据

Karpathy 对三代范式的划分（1.0 人写代码、2.0 用数据训练网络、3.0 用 prompt/上下文/Agent/工具/记忆/验证来编程）^[raw/articles/2026-05-01-软件-3-0-时代来临-AGI-Hunt.md:175-183] 容易被读成单纯的技术史叙事，但真正决定哪些工作能被 3.0 吞掉的是第 06 节的判据：传统软件自动化的是你能规格化的东西，AI 自动化的是你能验证的东西^[raw/articles/2026-05-01-软件-3-0-时代来临-AGI-Hunt.md:239-249]。可验证的领域——代码跑测试、数学可演算、漏洞可扫描——能进入强化学习循环持续变强；不可验证的领域则屡现「车在 50 米外的洗车店，建议步行过去」式的断崖，模型能重构十万行代码库却栽在常识上，即「锯齿状智能」^[raw/articles/2026-05-01-软件-3-0-时代来临-AGI-Hunt.md:251-255]。

更关键的是他在事后推文中补上的经济学一层：锯齿状分布不只与可验证性有关，收入和市场规模（TAM）决定前沿实验室的 RL 训练选择覆盖哪些领域^[raw/articles/2026-05-01-软件-3-0-时代来临-AGI-Hunt.md:261-267]。Claude 之所以擅长重构十万行代码，是因为有人付钱训练这个能力；「怎么去洗车」没人付钱训练，就永远留在分布之外。这与 wiki 中 [[concepts/rlvr-reinforcement-learning-verified-reasoning]] 记录的 RLVR 路线互为印证：验证器既是能力放大的引擎，也是能力盲区的成因。

### 「吞噬」与「加速」：两条完全不同的产品路径

文章最具洞察力的区分是：LLM 不只是加速已有工作流的工具，有些应用会被模型原生能力直接吞掉^[raw/articles/2026-05-01-软件-3-0-时代来临-AGI-Hunt.md:101-103]。MenuGen 是最干净的标本——传统方案 OCR→NLP→图像搜索→前端的整个中间层 App，被「把照片扔给 Gemini 在原图上叠加菜品图片」一步取代^[raw/articles/2026-05-01-软件-3-0-时代来临-AGI-Hunt.md:191-199]。他给出的提问模板是「不要只问 AI 能帮你更快地构建什么，要问 AI 让什么变得不再必要」^[raw/articles/2026-05-01-软件-3-0-时代来临-AGI-Hunt.md:201]。「用 .md 替代 .sh/.py/.go」的安装脚本案例则把这一逻辑推向开发者工具本身——LLM 是高级的英文解释器，能按系统环境内联调整安装过程^[raw/articles/2026-05-01-软件-3-0-时代来临-AGI-Hunt.md:291-299]。两类路径对产品决策的含义完全不同：加速路径要重排工作流，吞噬路径要敢于整个砍掉中间层。

### 地板与天花板：同一枚硬币的两面

Stephanie Zhan 的概括——Vibe Coding 抬高地板（准入），Agentic Engineering 抬高天花板（卓越，不牺牲安全、可靠性、可维护性与品味）^[raw/articles/2026-05-01-软件-3-0-时代来临-AGI-Hunt.md:91-97]——背后是 Karpathy 2025 年 12 月自述的 20/80「翻转」：从自己写 80% 代码变为 Agent 写 80%，乃至患上每天对 Agent 说话 16 小时的「AI 精神病」^[raw/articles/2026-05-01-软件-3-0-时代来临-AGI-Hunt.md:215-219]。地板侧是门外汉用自然语言做出可用应用；天花板侧是专业者设计 Agent 生成、编码、测试、互查的整套系统^[raw/articles/2026-05-01-软件-3-0-时代来临-AGI-Hunt.md:225-235]。这组概念在 wiki 的 [[concepts/agentic-engineering-paradigm]] 中已有系统展开，此处补充其判别功能：判断一个团队的 AI 转型深度，看它把 Agent 当「助手」（地板用法）还是当「系统组件」（天花板用法）。

### Harness 是 Agent 时代的「交接协议」

Harness 部分最有价值的不是概念溯源（Mitchell Hashimoto 2026 年 2 月提出的「每犯一个错就工程化一个方案」^[raw/articles/2026-05-01-软件-3-0-时代来临-AGI-Hunt.md:279-283]），而是 Anthropic 的长时运行方案给出的可复制结构：初始化 Agent 搭环境、建 claude-progress.txt 进度文件、立基准 commit，每个新 context window 先读 git log 和进度文件再续^[raw/articles/2026-05-01-软件-3-0-时代来临-AGI-Hunt.md:285-289]——本质上是给无状态模型外挂一份持久化的交接文档。Karpathy 的「为 Agent 重写软件、完全不考虑人类用户」^[raw/articles/2026-05-01-软件-3-0-时代来临-AGI-Hunt.md:291-297] 则预示了接口范式的迁移：机器可读接口、明确权限声明、可分解工作流取代按钮和菜单。这与 [[concepts/harness-engineering]] 的框架一致：模型是 CPU，harness 是操作系统。远景上他抛出的「全神经计算」（神经网络处理绝大多数计算、CPU 降级为协处理器）^[raw/articles/2026-05-01-软件-3-0-时代来临-AGI-Hunt.md:349-355] 是同一逻辑的终局推演，也与 [[concepts/software-3-0-stack]] 的栈模型衔接。

## 实践启示

1. 用「可验证性」筛业务场景：先问这件事的输出能否被客观评估（测试/演算/扫描/评审），再决定投入 Agent 化；不可验证的任务先构造验证环境，否则只会收获锯齿状的失望。参见 [[entities/jagged-ai-frontier-mollick]]。
2. 找「可构造验证环境但未被大实验室 RL 覆盖」的缝隙领域：自己设计奖励函数，即便主流模型无针对性优化，也能靠微调拿到显著优势^[raw/articles/2026-05-01-软件-3-0-时代来临-AGI-Hunt.md:269]。
3. 用「吞噬测试」重审现有产品：列出工作流里每一层，逐层问「这个中间层是否已被模型原生能力吞掉」——MenuGen 说明 OCR→NLP→搜索→前端这种多层管线可以整体消失^[raw/articles/2026-05-01-软件-3-0-时代来临-AGI-Hunt.md:193-201]。
4. 建立 Harness 制度而非依赖个人习惯：每次 Agent 犯错就沉淀一个工程化修复进 harness，用进度文件 + 基准 commit 的交接结构支撑跨 context window 的长任务^[raw/articles/2026-05-01-软件-3-0-时代来临-AGI-Hunt.md:281-289]。
5. 守住三件不可外包的事：系统规格设计（如以稳定 user ID 而非邮箱关联资金）、概念理解（真懂张量/内存/存储原理而不止 API 名字）、品味（判断「能跑但很丑」的代码）——可以外包思考，不能外包理解^[raw/articles/2026-05-01-软件-3-0-时代来临-AGI-Hunt.md:307-317]。
6. 把「token 没花完就焦虑」当新常态指标：瓶颈已从 GPU 空闲移到人的吞吐意愿，控制多少 token 吞吐量决定做多少事^[raw/articles/2026-05-01-软件-3-0-时代来临-AGI-Hunt.md:345]。
