## 深度分析

### 物理可行性作为验收标准：为什么"重建得像"在机器人领域失效

视觉生成领域的评价惯性是"看起来对"，但机器人操作的验收必须是"做得到"。Real2Gym 的核心裁决是把验收权从渲染图移交给物理引擎：场景必须在 MuJoCo 中真正完成抓取、放置与接触才算合格，执行轨迹还要导回 Blender 与原视频对照，核查视觉对应与物理可行性 ^[raw/articles/token用量减少749real2gym把仿真经验变成真机可复用技能.md:45-53]。这一裁决的根源是机器人操作对几何误差的极端敏感性——杯口稍窄、物体偏移、碰撞模型封住内腔，这类人眼无感的瑕疵会让画面上完全合理的动作在物理层直接失败 ^[raw/articles/token用量减少749real2gym把仿真经验变成真机可复用技能.md:29-33]。

更精巧的是纠错预算的分配：系统不均匀检查整个场景，而是围绕**交互关键帧**（物体被抓起、接触支撑面、夹爪释放的时刻）做自检与局部修正 ^[raw/articles/token用量减少749real2gym把仿真经验变成真机可复用技能.md:37-43]。这承认了一个事实：场景质量对 Agent 的价值不是均匀分布的，只有动作将要发生的时空邻域才值得精修——倒杯案例里杯沿附近的尺寸误差是唯一致命项，其余部分的重建精度可以放宽。验证通过的场景还能改变物体位置、桌高、材质、光照或加入干扰物来扩充任务分布，影响运动空间的变化需重新验证 ^[raw/articles/token用量减少749real2gym把仿真经验变成真机可复用技能.md:47-53]。

### 阶段级代码决策：与端到端策略的分野

端到端范式把感知-决策-控制压进同一个策略网络，泛化依赖海量数据，失败只能归因到整个网络。Real2Gym 的 Agent 侧走另一条路：每轮决策的产出不是单个动作，而是**执行一个操作阶段的代码**——接近杯子、闭合夹爪、抬起并检查抓稳，一次响应打包多个动作与验证条件，SAM3 提供物体定位、GraspNet 提供抓取候选 ^[raw/articles/token用量减少749real2gym把仿真经验变成真机可复用技能.md:55-63]。

与端到端策略相比，分野有三点：

1. **可归因性**：代码与验证条件是显式的，失败能定位到某个具体步骤；端到端策略失败只能整体重训。
2. **Token 经济**：平均模型响应 31 → 14 次、策略执行 Token 用量 -74.9% 直接来自决策粒度从动作提升到阶段——LLM 被调用的次数由"阶段数"而非"动作数"决定 ^[raw/articles/token用量减少749real2gym把仿真经验变成真机可复用技能.md:65-73]。
3. **免训练改进**：底层模型权重不变，所有改进发生在环境侧的技能库里，回避了真机数据训练的成本与安全风险。这与 [[entities/self-harness-shanghai-ai-lab-agent-improves-harness|Self-Harness（上海AI Lab）]] 的"harness 自改进、权重冻结"路线同构。

### 技能库自进化：可检验的经验，而非权重更新

Real2Gym 的自我改进通过更新技能库实现，且每次新任务从**独立上下文**开始、只接收选定的技能 ^[raw/articles/token用量减少749real2gym把仿真经验变成真机可复用技能.md:55-63]。这个设计有方法论上的关键意义：若经验持续累积在同一上下文窗口内，"复用有效"与"上下文记忆效应"无法区分；独立上下文 + 选定注入使技能成为可隔离检验的变量——第二次执行 87.5% 对基线 70.8% 的提升可以归因到技能内容本身 ^[raw/articles/token用量减少749real2gym把仿真经验变成真机可复用技能.md:65-73]。

经验的书写形式同样经过刻意设计：记录"相对物体如何行动、何时检查、失败后怎样修正"，而非绝对坐标或完整轨迹 ^[raw/articles/token用量减少749real2gym把仿真经验变成真机可复用技能.md:57-63]。相对描述使技能在复用时能根据当前观察重新定位与调整，从而跨场景、跨物体位姿迁移——这是技能库能持续复利的前提。

### 从"盘子上架"看闭环的完整形态

盘子上架是全文信息量最大的案例：抓取深度、盘沿朝向、狭窄空间放置精度三重约束须同时满足，两种方法初始全败。修复路径是录制人类示范 → 重建数字孪生 → 仿真中两次失败、第三次迭代获得技能 → 结合真机实时观察完成 ^[raw/articles/token用量减少749real2gym把仿真经验变成真机可复用技能.md:75-83]。系统的价值不在首次成功率，而在**失败的可修复性**：真机失败被转化为仿真训练材料而非被丢弃。这与仿真资产供给路线互为补充——[[entities/roboflywheel-embodied-simulation-assets-2026|RoboFlywheel 百万级仿真资产]] 提供规模化的通用环境，Real2Gym 提供从单个失败案例定制环境的通道；ego 视频数据侧的 [[entities/egosuite-open100k-embodied-human-video-data-open-source-2026|EgoSuite/Open100K]] 则是它的输入供给层。

局限同样清晰：点云噪声影响重建、阶段级控制在精细操作中有改进空间、真机验证限于 Franka 与平行夹爪 ^[raw/articles/token用量减少749real2gym把仿真经验变成真机可复用技能.md:85-89]。向灵巧手和人形扩展时，"阶段代码"的表达能力是否足以覆盖接触丰富的精细操作，是这条路线必须回答的开放问题。

## 实践启示

1. **场景/环境的验收标准要由下游任务定义**："重建得像"是视觉指标，"动作能在物理引擎中完成"才是机器人指标。任何 sim-to-real 管线都应把物理执行验证设为硬性关卡，而不是把渲染相似度当作质量信号。
2. **把 LLM 决策粒度从单动作提升到阶段**：一次响应打包"动作 + 验证条件"能同时降低 Token 成本与模型往返次数（31→14 次、-74.9%）。Agent 系统里最便宜的提升往往不是换更强模型，而是减少调用次数。
3. **经验要写成"相对物体 + 检查点 + 修正方法"**：绝对坐标的技能复用率极低；以物体为参照、内嵌"何时检查/失败怎样修正"的描述才能在新观察下重新定位、跨场景复用。
4. **用独立上下文让经验可被检验**：新任务从干净上下文开始、只注入选定技能，复用收益才能归因到技能本身而非上下文记忆——这也是评估"经验是否真的有用"的唯一干净实验设计。
5. **真机失败是最有价值的训练材料**：盘子上架的闭环（人类示范 → 数字孪生 → 仿真迭代 3 次 → 真机完成）说明失败任务不该被跳过或手工修复，而应被转化为可交互仿真环境，用最低成本迭代到成功。
6. **权重冻结 + 技能库是具身 Agent 改进的低成本起点**：不训练底层模型意味着改进可即时部署、可随时回滚（删技能即可），适合真机场景下安全敏感的迭代节奏。
