# 分析 100 万亿 Token 后得出的关于 AI 现状的真相！

**来源**：code秘密花园 ｜ **作者**：花园老师（ConardLi） ｜ **发布日期**：2025-12-08
**原文链接**：https://mp.weixin.qq.com/s/CyIEK7JtQvBS2_KGWhDEpg

本文是 code秘密花园 对 OpenRouter 一份 AI 技术报告的中文解读：报告基于超过 100 万亿 Token 的真实 LLM 请求调用记录，回答全球用户"用什么模型、干什么事、愿意花多少钱"^[raw/articles/分析-100-万亿-token-后得出的关于-ai-现状的真相.md]。

## 摘要

OpenRouter 用 100 万亿 Token 数据勾勒出 2025 年的 LLM 使用全景：北美闭源大厂仍平均占据约 70% 份额，开源模型年底拿下约三分之一，而增量几乎全部由中国开源模型驱动——从 2024 年底的 1.2% 起步，某些时段贡献近 30% 的总使用量^[raw/articles/分析-100-万亿-token-后得出的关于-ai-现状的真相.md]。开源阵营内部同样剧变：DeepSeek 曾超 50% 的统治被打破，年底无任何单一模型超过 25%，15B–70B 中型模型取代小型模型成为新宠。更深的迁移发生在能力层：推理优化型模型与真实工具调用接管过半流量，编程任务从年初约 11% 升至超过 50%。

## 核心要点

- **份额格局与中国引擎**：北美闭源模型平均约占 70%，开源模型年底约三分之一；开源增量几乎全部来自中国——从 2024 年底的 1.2% 起步，某些时段贡献近 30% 的总使用量。
- **热度退去后份额不回落**：增长紧随 DeepSeek V3、Kimi K2 等发布却得以保持，说明开源模型已进入长期生产环境而非尝鲜。
- **开源内部去中心化**：DeepSeek 总流量仍领先，但已从超 50% 的"半壁江山"降到年底无任何单一模型超过 25%；Qwen、MiniMax、Kimi、GPT-OSS 发布后几周内即可抢走大量份额。
- **尺寸风向反转**：15B–70B 中型模型成为新宠（Qwen2.5 Coder 32B 证明该量级潜力，Mistral、GPT-OSS 跟进），15B 以下小模型份额反降。
- **用途高度集中**：角色扮演占开源总流量超过 50%；中国开源模型的编程与技术类任务合计约 39%，显著高于全球平均。
- **推理与工具调用成为基线**：流经推理优化型模型的 Token 已超总流量 50%；真实工具调用供给从 gpt-4o-mini／Claude 3.5 扩展到 Claude 4.5 Sonnet、Grok Code Fast、GLM 4.5。
- **输入长度暴涨近 4 倍**：平均 Prompt 从约 1.5k 涨到 6k Token，编程请求常需超过 2 万 Token 上下文。
- **编程是最大且竞争最激烈的类别，价格几乎不影响需求**：编程份额从年初约 11% 升至超过 50%，Claude 首次跌破 60%（OpenAI 2%→8%，Google 约 15%）；价格降低 10%，用量增加不到 1%。

## 深度分析

### 一、两极平衡的份额格局：增量全部在开源一侧

报告的第一层结论看似"和平"：北美大厂的闭源模型依然主导，平均约占 70% 份额；开源模型稳步增长，年底拿下约三分之一，形成相对稳定的平衡^[raw/articles/分析-100-万亿-token-后得出的关于-ai-现状的真相.md]。但拆开看，这是静止存量加上单向流动的增量——新增量几乎全部流向开源，且几乎全部来自中国团队：从 2024 年底的 1.2% 起步，凭快速迭代周期与过硬质量（Qwen、DeepSeek 系列）在某些时段贡献了近 30% 的总使用量。这些增长在热度退去后依然保持，说明用户不是尝鲜，而是把开源模型接进了生产环境。

### 二、开源内部：从"一家独大"到"百花齐放"

开源阵营的权力结构被彻底重写。DeepSeek 在总流量上依然领先，但曾占据"半壁江山"（超过 50%）的统治地位已被打破，到 2025 年底没有任何单一模型能独占超过 25% 的份额，前排差距正在缩小^[raw/articles/分析-100-万亿-token-后得出的关于-ai-现状的真相.md]。拆掉这份垄断的不是一个挑战者而是一群：Qwen、MiniMax、Kimi 以及 GPT-OSS 等新模型一经发布就能在几周内抢占大量份额。背后有两个机制：一是用户切换门槛很低且乐于尝鲜；二是持续迭代是生存前提，"吃老本"行不通——DeepSeek 靠不断推出新版本保住头部位置，迭代缓慢的模型份额很快被更勤奋的对手瓜分。

### 三、尺寸与用途：中型崛起，角色扮演与编程构成双极

模型尺寸的风向出现清晰反转。15B 参数以下的小模型仍在不断涌现（如 Google Gemma 3），份额反而下降：赛道极其拥挤，用户忠诚度很低，没有哪一个小模型能长期坐稳位置^[raw/articles/分析-100-万亿-token-后得出的关于-ai-现状的真相.md]。取而代之的是 15B–70B 的"中型模型"——自 Qwen2.5 Coder 32B 证明该量级潜力后，Mistral 与 GPT-OSS 等跟进者迅速扩大了市场。70B 以上则不再赢家通吃，用户会同时评估 Qwen3、GLM 4.5、GPT-OSS-120B 并按实际表现灵活切换。用途侧同样极端集中：开源流量集中在角色扮演（超过 50%，因内容审查限制更少，更适合创意与情感互动）与编程辅助；而聚焦中国开源模型，编程与技术类任务合计约 39%，显著高于全球平均。编程领域闭源（如 Claude）整体仍主导，但开源内部流量曾在 2025 年中期向国产模型倾斜、随后因西方模型（如 LLaMA 系列）更新而回流——开发者"谁强用谁"，份额对模型质量反应极其敏感。

### 四、能力基线迁移：推理优化、工具调用与分析引擎

模型角色正在迁移：不再只做单轮生成或补全，而是越来越多地用于多步骤规划、工具调用与复杂逻辑推理，AI 从"聊天机器人"向能解决复杂问题的"智能体"进化^[raw/articles/分析-100-万亿-token-后得出的关于-ai-现状的真相.md]。两条量化证据：流经推理优化型模型的 Token 份额自 2025 年初急剧上升并已超过总流量的 50%，由供给侧（GPT-5、Claude 4.5、Gemini 3 等发布）与需求侧（复杂逻辑处理需求）共同推动；真实工具调用量（模型真正执行了外部工具操作，而非仅具备该功能）全年稳步上升，供给格局从年初 OpenAI 与 Anthropic 的双头垄断，变为下半年 Claude 4.5 Sonnet 抢份额、Grok Code Fast 与 GLM 4.5 入局。交互形态也随之改变：平均 Prompt 长度翻了近 4 倍（约 1.5k → 6k Token），典型用法是"喂给模型大量信息，换取精炼的高价值洞察"；且输入膨胀极不均衡，编程任务（代码理解、调试）单次请求往往超过 2 万个 Token 上下文。对企业与开发者而言结论直白：支持稳定的工具调用不再是锦上添花，而是必须项，缺乏可靠工具接口能力的模型会在自动化编排中迅速掉队。

### 五、价格、留存与这份数据的读法边界

价格与用量的关系最反直觉：需求对价格极不敏感，价格降低 10% 用量才增加不到 1%，用户选模型主要看"能不能干成事"^[raw/articles/分析-100-万亿-token-后得出的关于-ai-现状的真相.md]。市场据此分成四类：高价爆款（Claude Sonnet，约 $2/百万 token，用量巨大）、性价比巨头（DeepSeek V3、Gemini Flash，不到 $0.4，批量任务默认首选）、顶级专家（GPT-5 Pro，约 $35，只在最难、最不能出错的任务上使用），以及便宜到近乎白送却无人问津的廉价长尾。由此形成分工：闭源做高价值难事，开源做量大而精度要求不高的杂事；编程与角色扮演是最大的两个流量池，单价通常低于中位数 0.73 美元/百万 token，而"技术类"任务单价极高却用量依然很大，是利润最丰厚的一块。

留存规律同样残酷：只有真正解决具体难题的新模型才能长期留人，而最早进来的用户因系统与代码已基于该模型搭好、迁移成本高，先发优势几乎就是一切；平庸的模型（如 Gemini 2.0 Flash、Llama 4）用户试一下就全跑光。DeepSeek 则出现独特的"回头客"现象——不少用户先流失，一两个月后又回来，说明对比一圈后它在性价比或特定能力上仍是最优解。

最后必须明确口径边界：这份数据只覆盖 OpenRouter 的流量，天然偏向开发者、早期采用者与跨国 API 调用场景，因此 70%／三分之一／47% 这类比例反映的是该平台上的模型结构，而不是全球真实部署分布；"调用 Token 量"衡量的是使用强度，也不等于创造的价值。报告里那些结构性结论（份额对质量高度敏感、切换成本低、工具调用已成硬门槛、需求对价格不敏感）比具体百分比更耐迁移。

## 实践启示

1. **选型不按"开源/闭源"站队，按任务分层**：高难度、不能出错的核心任务交给闭源顶级模型，量大、容错率高的日常任务交给性价比开源模型，用模型组合而非单一标准答案。
2. **把工具调用当作硬性准入门槛**：评估候选模型时先验证工具调用与多步规划的稳定性，再谈能力与价格——这是企业级采用的分水岭。
3. **价格战不是获客手段**：降价 10% 只换来不到 1% 的用量增长，先把模型做到"好用"的及格线，便宜才有意义——只要足够好、足够稳，用户愿意为高价买单。
4. **为"喂大量上下文"设计产品与成本模型**：输入长度已翻近 4 倍、编程请求常超 2 万 Token，上下文成本、缓存策略与检索质量比输出单价更值得优化。
5. **用先发优势换复利，靠版本迭代守住它**：用户一旦把系统基于某模型搭好就很难换走，应尽早锁定早期用户；但停止迭代的份额会被迅速瓜分，持续发版是唯一护城河。
6. **押注 15B–70B 中型模型的成本/能力甜点**：小型模型赛道过度拥挤且留不住用户，中型模型在能力与运行效率间取得平衡，是本地部署与批量推理最值得关注的量级。
7. **引用这份报告时标注口径**：它代表 OpenRouter 的开发者流量而非全球分布，"Token 用量"也不等于价值，结论要按方向而非绝对值使用。
