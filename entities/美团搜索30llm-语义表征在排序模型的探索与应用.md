## 一、背景与动机

服务零售是将服务销售给最终消费者的商业活动，与之对应的概念为商品零售。服务零售和商品零售是美团零售业务的两个主要组成部分。 ^[raw/articles/美团搜索30llm-语义表征在排序模型的探索与应用.md]

在美团搜索场景下，相较于到家和其他到店业务，服务零售具有以下显著特点：

  * **品类丰富** ：覆盖丽人、休闲娱乐、家政、进场零售等众多细分行业。

  * **搜索需求类型丰富** ：交易型、信息型、留资型并存。

  * **供给非标准化程度高** ：交易内容的多维组合性（e.g. 券、时间、位次、场次、空间、技师等）以及基于"人"和"场所"进行履约，共同促使供给的个性化和非标准化。




传统精排模型的语义建模高度依赖文本匹配，但这类特征构建成本高、泛化能力弱，在面对服务零售大量长尾品类、复杂 Query 意图时尤为明显。例如，"宠物 SPA+洗澡"这个 Query 对应的商品名称可能是"萌宠清洁护理套餐"、"春节大扫除"这个 Query 对应的商品名称可能是"深度保洁服务套餐"，在这些 Case 中，搜索词和供给在文字上几乎没有重叠，但语义上是高度相关的。 ^[raw/articles/美团搜索30llm-语义表征在排序模型的探索与应用.md]

这类语义 Gap 在美团服务零售搜索场景（生活服务、休闲娱乐等）尤为突出。服务零售的品类长尾分散、商品描述非结构化、Query 意图复杂多样，传统特征工程难以覆盖。而大语言模型（LLM）在语义理解方面的能力成熟度正在快速提升，给我们带来了新的解题思路。 ^[raw/articles/美团搜索30llm-语义表征在排序模型的探索与应用.md]

从 2025 年 Q4 到 2026 年 Q2，服务零售搜索排序团队系统性地探索了 LLM 在精排模型中的应用，核心方向是用 LLM 为搜索词（Query）、商家（POI）和商品（Deal）生成高质量的语义向量表征，将语义匹配信息以 cosine 相似度的形式注入排序模型，弥补传统特征在语义理解上的不足。经过三期迭代，累计完成 3 个 Launch Review（LR），均已完成全量上线，带来了显著的线上收益。 ^[raw/articles/美团搜索30llm-语义表征在排序模型的探索与应用.md]

## 二、一期：精排引入大模型语义表征（验证可行性）

### | 2.1 核心思路

服务零售精排在语义层面的建模几乎为零，排序模型主要依赖少量文本匹配和 Query 统计类特征。所以一期的目标很纯粹：**验证 LLM 表征能否对精排模型有实质性帮助** 。如果用 LLM 生成的语义向量能带来正向收益，就值得投入更多资源深度优化。整个一期的设计都围绕「先把路走通」。 ^[raw/articles/美团搜索30llm-语义表征在排序模型的探索与应用.md]

**整体思路是** ：选择一个轻量级的 LLM 作为基座，对 Query 和 POI 的信息进行统一建模，通过微调，使模型仅依赖 ^[raw/articles/美团搜索30llm-语义表征在排序模型的探索与应用.md]

## 深度分析

**1. 训练目标与消费方式的错位是演进的主矛盾。** 一期把"Query 与商家是否匹配"当二分类来微调，但排序模型真正消费的是"多个候选中谁更匹配"的相对序关系。这个错位直接驱动了二期损失函数从点击率分类重设计为对比学习，并连锁决定了训练数据需要难负样本、表征提取需要更高效聚合。启示是结构性的：表征学习的目标函数必须与下游消费方式对齐，否则上游再强的 LLM 也只能产出"方向正确但分辨率不足"的信号。

**2. 表征注入排序的本质是一条"语义→特征"的降维管道，而非端到端替代。** 与 TIGER 式 Semantic ID 生成式检索不同，本工作没有用 LLM 重构排序模型，而是把 LLM 语义压缩为 64 维 cosine 相似度这一个特征，挂载到既有判别式精排上。一期仅凭这一条特征就拿到显著订单增量——说明在排序场景，LLM 价值的最高性价比形态是"蒸馏成轻量语义特征"，而不是把大模型直接搬进打分链路（参见 [[concepts/model-distillation-compression]]）。

**3. 延迟约束塑造了全部工程选型。** 排序链路毫秒级预算容不下在线 LLM 推理，因此 Query/POI/Deal 表征全部离线全量预计算，在线只做一次点查与分桶查表；一期"同序列三词表 token + 三次 Forward Pass + Attention Mask 隔离"的取表征方式被视为明显短板，二期改为 Query/POI/Deal 各自独立序列、特殊 token 用 nn.Parameter 可学习向量覆写末位 embedding，单次 forward 即得表征。效率优化不是锦上添花，而是方案能否成立的门槛（参见 [[concepts/inference-optimization]]）。

**4. 注入方式是架构级决策，门控融合胜过直接拼接。** 三期四种方案对比清晰：底层拼接交叉统计 +7bp、底层拼接 LLM 相似度+交叉统计 +18bp、输出塔前注入 +8bp 且部分指标负向、PEPNet 门控注入 +25bp。语义信号与既有特征在强度与量纲上不对等，直接拼接易被一方主导（与 UNGER 指出的"语义与协同 Embedding 直接拼接时语义信号占主导"互为印证），门控让模型自学融合权重才是最优解。

**5. 跨场景复用的隐藏成本是覆盖率而非模型本身。** 二期表征模型可原样复用到下挂精排，但表征的覆盖范围不能——Query Embedding 按商家精排样本圈选，直接迁移后 Query 覆盖率仅 81.24%，双覆盖（Query+Deal）仅 73.61%。配套的零向量边界+缺失值专用分桶保证了未覆盖样本不产生噪声。此外语义特征（"Query 与商品是否匹配"）与全域交叉统计特征（"哪类用户偏好这类商品"）在离线各自正向，叠加后效应超出预期（服务零售订单 +0.32%、大盘支付订单 +0.35%），证实两个维度捕获的是正交的匹配信号。

## 实践启示

1. **先单点验证，再体系化投入。** 一期用最轻量的路径（轻量 LLM 基座 + 一条 cosine 特征）验证可行性，拿到显著正向后再追加资源——避免一开始就重资产构建表征体系。
2. **损失函数跟着下游任务走。** 排序场景用对比学习 + 难负样本，而非二分类；业界共识"embedding 质量的天花板在负例质量，不在 backbone"，负例工程优先于换更大的模型。
3. **在线预算决定离线架构。** 表征全部离线预计算、分桶离散化后查表注入，把秒级 LLM 推理压缩到排序链路的毫秒预算内；取表征时优先设计单次 forward 的方案（可学习特殊向量优于多次 masked pass）。
4. **新特征注入优先考虑门控（如 PEPNet），慎用直接拼接。** 当新信号与存量特征强度不对等时，让模型学习融合权重，比手工决定拼接位置更稳。
5. **迁移表征前先审计覆盖率。** 表征模型可复用 ≠ 表征覆盖可复用；迁移到新场景时先统计 Query/item 覆盖率，并设计缺失值兜底（零向量 + 专用分桶），否则脏样本会侵蚀收益。
