# RLark：具身智能云原生纳管平台

## 深度分析

### 定位：从"设备接入工具"到任务级"塔台"

RLark 由清华与无问芯穹共同开源，解决的核心问题是：当机器人从单机走向机群，协同复杂度（逐台接入设备、逐任务部署程序、反复配置跨域网络、出问题逐一排查）会放大到人力不可维持的地步。它的架构选择是控制面与数据面分离：控制面承担"塔台"职责，统一维护资源信息、任务配置与通信关系；各集群 Agent 负责本地部署、资源同步与状态回传。关键抽象是自研的 embodied-runtime——通过设备插件发现并注册机器人、相机等真实硬件，将其转化为 Kubernetes 体系中可识别、可申请、可调度的资源，使其与 GPU 一起进入同一份任务编排。"像 GPU 一样调度机器人"的实质，是把硬件抽象做进了云原生资源体系，而不是简单做一层远程连接工具。

### 跨集群通信：真正的技术纵深所在

跨地域具身任务的瓶颈不在调度而在网络。RLark 的任务级跨集群网络互联做了一次关键解耦：将执行实例的通信地址与实际部署位置分离——为实例分配虚拟地址，经 TUN 虚拟接口由 gVisor 用户态网络栈处理，再通过 SSH 安全隧道转发，路由、隧道与转发关系由平台统一维护，并以"通信域（Domain）"组织互联范围和证书认证。在此之上，训练框架 RLinf 做流量本地化适配（技术源自其 RSS 2026 的 USER 系统）：观测处理、推理与真机交互就近在边缘完成，只回传训练所需数据，避免原始观测全量回传的带宽开销。专项测试显示：受限网络下大包单流吞吐较 VPN 方案提升约 49%，小包提升约 14%；高带宽环境下大包单流接近 2 Gbps；对比 EasyTier 明显减少跨地域真机任务的卡顿。按流量特征分治（大包/小包、高频交互边缘化）是这套通信层最值得借鉴的设计。

### 声明式编排与任务级观测：把实验从脚本拼接变成一份配置

RLark 用 Job→Task→Worker 三层模型描述一项具身实验：Task 声明训练、推理、真机交互等角色所需的资源、实例数量与部署位置，Worker 是实际执行实例，控制面通过持续调协（reconciliation）让实际状态与配置一致；有阶段依赖的流程用 Workflow 组织多个 Job。配合"任务级运行观测"——沿"任务→角色→Worker→节点/设备→日志"逐层下钻，并提供 Web Terminal 与 TensorBoard 入口——异常排查不再需要登录多台机器跨系统核对。这与通用编排系统（K8s Job、Argo Workflow）的思路同构，但为具身场景补上了设备维度。

### 实测数据与开源策略：可信度来自全链路而非功能清单

与 RLinf 结合，团队在广东云端 GPU 集群与北京机器人现场之间完成跨地域真机实测：3 个集群、近百个云边端节点、4 种型号具身设备；设备纳管从约 1 小时降到约 5 分钟，任务提交 10 秒内启动；一次连续约 36 分钟的运行推进至 323 个全局训练步，完整跑通设备申请→跨集群调度→真机数据回传→云端训练→策略更新的采集-训练-验证闭环。全栈开源（UI/API/后端/任务编排/跨集群互联/embodied-runtime）配合已有的 [[entities/华为云-昇腾-rlinf-具身智能-2026|华为云昇腾 RLinf 生态]]，表明 RLinf 系正在把具身智能基础设施做成一条从算力适配、纳管调度到训练框架的完整开放栈——这与 [[concepts/cloud-ai-infrastructure|云上 AI 基础设施]] 的演进路径一致：竞争焦点从模型本身下沉到谁能把真实世界设备组织成可调度的资源池。 ^[raw/articles/机器人也能像gpu一样调度清华联手无问芯穹开源具身智能平台rlark.md]

## 实践启示

1. **规模化前先做基础设施抽象。** 机器人设备能被申请、调度、复用之前，机群实验只能靠人工逐台拼接；具身团队应尽早把"设备纳管"做成平台能力而非运维脚本，纳管时延（小时级→约 5 分钟）是检验抽象是否到位的硬指标。
2. **把"可复用的任务配置"当一等公民。** RLark 最大的隐性效率杠杆是：一次实验完成的接入、部署与通信配置可在后续任务中复用，换设备/调规模/改参数只需改配置。设计实验平台时应优先保证配置的可迁移性，而不是功能的即兴堆叠。
3. **跨域通信按流量特征分治，而非一味加带宽。** 大包（+49%）与小包（+14%）吞吐分开优化，高频交互与原始数据在边缘就近处理、只回传训练所需——先分析任务的流量画像，再决定隧道、栈与部署位置。
4. **虚拟地址解耦通信地址与部署位置，是跨集群系统的可迁移模式。** 实例用虚拟地址互访、平台统一维护路由与隧道，适用于任何"执行实例分散多地、拓扑常变"的分布式 AI 系统，不必绑定在具身场景。
5. **观测体系按任务主线设计下钻路径。** 从"任务—角色—执行实例—节点/设备—日志"逐层定位，配合内建终端与训练可视化入口，避免用户在多台机器、多个系统之间人工拼异常信息。
6. **评估基础设施平台看实测链路而非功能列表。** 36 分钟连续运行、323 个 global step、全链路无人工干预跑通，这类端到端数据比"支持 XX 特性"更能说明平台可用性；选型时应要求厂商/项目给出同类实测。
