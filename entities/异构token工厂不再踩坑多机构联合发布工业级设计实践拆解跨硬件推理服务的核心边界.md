机器之心发布

随着大模型推理服务部署走向成本与算力双约束，  Prefill-Decode（PD）分离的异构推理  已从前沿方案进入生产落地。推理加速器的差异性体现在不同精度计算速度、访存带宽与存储大小、机内机间通信带宽等多方面。比如构建异构 Token 工厂时，  可以选择计算密集型的硬件算力运行 Prefill 阶段，高通信带宽的硬件算力运行 Decode 阶段  。此时 KV Cache 跨硬件、跨精度、跨互联传输成为常态，但业界长期缺乏统一设计范式 —— 硬件、量化精度、网络、KV Cache 分层存储的选型互相耦合，部署运维人员只能靠试错调参，极易出现字节传输成功但推理结果错乱、首 Token 延迟飙升、  KV Cache 数据污染  、故障恢复失效等问题。 ^[raw/articles/异构token工厂不再踩坑多机构联合发布工业级设计实践拆解跨硬件推理服务的核心边界.md]

异构推理已成常态，但缺一张全景图

大模型推理正在经历一场静默的架构变革。当前，异构推理已不再是可选项，GPU 供应紧张、多厂商混合部署成为常态、不同阶段对算力和带宽的需求天然不同。异构推理在性价比更优或供应更充足的芯片上运行 Prefill 阶段，在带宽更强的芯片上运行 Decode 阶段，通过混合数值格式传输 KV Cache 状态，跨越异构互联完成一次完整的推理请求。 ^[raw/articles/异构token工厂不再踩坑多机构联合发布工业级设计实践拆解跨硬件推理服务的核心边界.md]

多数团队仍在沿用同构时代的思路，DistServe、Splitwise、Mooncake、FlowKV 等系统各自解决了其中的  一部分关键问题  ，但每个系统都在独立地做决策，用什么加速器、什么精度、什么互联、KV Cache 放在哪里，却缺少一个统一的设计来回答：这些决策中，哪些必须联合做出，哪些可以独立决定？ ^[raw/articles/异构token工厂不再踩坑多机构联合发布工业级设计实践拆解跨硬件推理服务的核心边界.md]

> 核心问题：当异构推理组合了不同的加速器、数值格式、互联路径和 KV Cache 驻留层级时，哪些设计决策必须在 PD 边界处联合做出，哪些可以各自独立？

## 深度分析

这篇论文最反直觉的一点，是它不提供"更快"的推理系统，而是回答一个更根本的问题：当 Prefill 和 Decode 跑在不同厂商的芯片上时，哪些设计决策必须绑在一起做，哪些可以拆开？答案是五个设计轴的两两耦合分析：六组紧耦合收敛为三个核心边界决策，其余留作开放问题。这是一张"决策依赖图"，补上了 DistServe、Splitwise、Mooncake、FlowKV 各自解决局部问题、却无人回答"谁和谁必须联合决策"的空白。^[raw/articles/异构token工厂不再踩坑多机构联合发布工业级设计实践拆解跨硬件推理服务的核心边界.md]

关键抽象是 Runtime KV State：不只是 KV 张量本身，还包括表示格式、元数据、驻留信息和所有权状态。所有边界问题本质上都是围绕这个对象的生产（Prefill）、传输（PD 交接）与消费（Decode）展开的。论文最尖锐的洞察在于区分了传输故障与语义故障：NIXL、Mooncake 这类传输引擎搬运的是字节而非张量语义，若生产者与消费者对数值格式理解不一致，字节会"成功"到达却被错误解读——传输层不报错，推理结果已错乱。因此 KV 可移植性被定义为：Decode 必须能直接消费、或经显式验证的转换来消费传入状态；兼容性检查相应分为不可转换的不变量（模型身份、适配器、Token 范围）与可转换的差异（布局、分区、数值表示）。^[raw/articles/异构token工厂不再踩坑多机构联合发布工业级设计实践拆解跨硬件推理服务的核心边界.md]

受控实验把"耦合"从定性判断变成了数字：固定 BF16 KV 表示，Qwen3-32B + SGLang PD + NIXL 的拓扑从 6P2D 调到 4P4D，最高可满足 SLA 的注入率从 0.2 跌到 0.1；同样 4P4D 下把 KV 表示切成 FP8 e4m3，注入率又拉回 1.0。也就是说 P:D 资源比例根本不能脱离 KV dtype 单独评估——KV 精度直接改写 Decode 侧的带宽、容量与尾延迟压力，反过来决定计算放置的最优解。精度策略的影响还是非对称的：FP8 主要改善 TPOT，AWQ INT4 提升吞吐却推高 TTFT，这把精度从全局配置项重新定位为运行时角色。^[raw/articles/异构token工厂不再踩坑多机构联合发布工业级设计实践拆解跨硬件推理服务的核心边界.md]

沐曦 C600（Prefill，INT8/W8A8）+ 英伟达 Hopper（Decode，FP8）的 CPHD-GLM5.1 生产部署提供了工业级背书：64K 输入、90% 前缀缓存命中下，AIME 25/26 与 SWE-Bench Verified 与官方参考值偏差在可接受范围内，异构配置不引入可测量的质量退化。vLLM 与 SGLang 的源码级对比则揭示了生命周期管理的分叉：NIXL pull 由 Decode 端拿到坐标后读取分配，SGLang 由 Decode 端预分配并推送元数据——两条路径在容量核算、故障恢复与拥塞控制上特性迥异。^[raw/articles/异构token工厂不再踩坑多机构联合发布工业级设计实践拆解跨硬件推理服务的核心边界.md]

两个开放耦合同样有信息量：跨厂商 KV 统一传输栈缺失，本质是 KV 传输属于端到端通信栈属性而非传输层特性，现有适配层只能封装、无法标准化；网络与 PD 资源协同规划缺少一体化方法论。这为后续研究指出了比"更快调度"更底层的方向。^[raw/articles/异构token工厂不再踩坑多机构联合发布工业级设计实践拆解跨硬件推理服务的核心边界.md]

## 实践启示

- **把计算放置和 KV 精度当成同一个决策**：先固定 KV 表示再调 P:D 比例（或反过来）都会得出误导性结论；容量规划必须两者联合评估，实验设计里要交叉扫描，不能单轴扫描。^[raw/articles/异构token工厂不再踩坑多机构联合发布工业级设计实践拆解跨硬件推理服务的核心边界.md]
- **警惕"字节到达 ≠ 语义正确"**：跨精度 KV 传输不报错不代表没错，接入异构推理后应先用有标准答案的基准（如 AIME、SWE-Bench Verified）验证质量无退化，再上流量。^[raw/articles/异构token工厂不再踩坑多机构联合发布工业级设计实践拆解跨硬件推理服务的核心边界.md]
- **精度按阶段选，不做全局设置**：Prefill 侧追求算力利用率，Decode 侧受带宽约束，FP8 与 AWQ INT4 对 TTFT/TPOT/吞吐的影响非对称，应按运行时角色分别配置。^[raw/articles/异构token工厂不再踩坑多机构联合发布工业级设计实践拆解跨硬件推理服务的核心边界.md]
- **设计 PD 交接协议时先想清所有权**：Decode 端拉取（vLLM/NIXL 式）与预分配推送（SGLang 式）在故障恢复和容量核算上差异巨大，选型要与自己的容错和拥塞控制策略匹配。^[raw/articles/异构token工厂不再踩坑多机构联合发布工业级设计实践拆解跨硬件推理服务的核心边界.md]
- **兼容性检查分类处理**：模型身份、适配器、Token 范围是不可转换的不变量，传输前必须硬校验；布局、分区、数值表示是可转换差异，走显式验证的转换路径。^[raw/articles/异构token工厂不再踩坑多机构联合发布工业级设计实践拆解跨硬件推理服务的核心边界.md]
- **国产加速器切入推理的可行路径**：计算密集场景跑 Prefill、带宽敏感的 Decode 留给成熟生态，沐曦 C600 + Hopper 的生产验证提供了可参照的模板。^[raw/articles/异构token工厂不再踩坑多机构联合发布工业级设计实践拆解跨硬件推理服务的核心边界.md]
