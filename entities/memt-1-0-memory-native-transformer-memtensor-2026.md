# MemT 1.0：记忆原生 Transformer 与 Memory Scaling

## 一句话定位

MemT 1.0 是记忆张量（MemTensor）开源的一系列「记忆原生（memory-native）」模型：不把历史经验塞回上下文，而是在 Transformer 内部增加一条**与注意力并行的记忆计算通路**，把经验编码成可训练的矩阵状态，并在生成时通过记忆分支读取。公开的两个型号是 36B（激活 3B，基座 Qwen3.6-35B-A3B）与 288B（激活 17B，基座为继续后训练的 DeepSeek-V4-Flash），团队称这是记忆原生路线**首次在近 300B 参数规模上的工程验证**。^[raw/articles/memt-1-0-memory-native-transformer-memtensor-2026.md]

## 为什么现在讨论记忆：RSI 的第一块拼图

文章把「AI 自我改进（RSI）」拆成三块拼图：记忆、反馈、验证与更新机制。记忆负责让一次有效的改进成为下一次的起点，其余两块负责判断哪些改动值得进入下一轮——MemT 1.0 只做第一块，也是被长期低估的一块。这与 [[concepts/agent-memory-architecture|Agent 记忆架构]] 的语境不同：agent memory 关心「怎么检索、放进上下文」，记忆原生关心「怎么让模型自己学会读写的内部状态」。^[raw/articles/memt-1-0-memory-native-transformer-memtensor-2026.md]

## 架构：主干冻结 + 超记忆 + 局部记忆

参数化上，MemT 1.0 保留基座原有前向流程，只在选定 Transformer 模块插入原生记忆分支，拆成三层：

- **主干权重**：承载已有通用能力，训练记忆时保持冻结；
- **超记忆（hyper-memory）**：读写投影、门控等可训练参数，决定如何编码、更新、读取记忆；
- **局部记忆**：动态矩阵状态，保存交互中新加入的信息。

写入时隐状态经投影生成记忆的 K/V，由擦除、写入、遗忘门控调节已有矩阵中的关联；读取时当前输入映射为记忆查询，读出后归一化并经输出门控参与生成，与注意力输出融合。更新机制基于 Gated DeltaNet-2 做逐 token 生成并做稳定化处理——消融显示，把逐 token 更新换成整轮聚合，Nano 的记忆基准平均分从约 47.0 掉到 41.0，6 分差距说明 token 级连续更新更能处理记忆衰减并纠正轮内关联。^[raw/articles/memt-1-0-memory-native-transformer-memtensor-2026.md]

容量扩展走 **MoS（Mixture-of-Storage）**：把一个记忆原生模块扩成多个记忆专家，分别学习存储与路由，并采用**稠密融合**（所有专家都参与计算，路由权重决定贡献）——这与基座 MoE 的稀疏专家路由形成刻意对照。^[raw/articles/memt-1-0-memory-native-transformer-memtensor-2026.md]

## 训练：340 亿 token 的记忆语料与教师-学生蒸馏

记忆训练语料共 340 亿 token（继续预训练 200 亿 + 后训练 140 亿）。继续预训练格式统一：把长文本切成连续片段写入记忆，再让模型拿着记忆状态回答后续查询，每处理完一段就更新状态供下一段使用。后训练包含三类数据：记忆原生的语言建模数据、记忆存储与利用数据（摘要、续写、压缩等）、以及强化长程记忆的任务数据。关键设计是**冻结的主干充当教师**（可见完整历史），MemT 1.0 作为学生只能看到自己的记忆状态，沿 off-policy 蒸馏对齐教师分布。^[raw/articles/memt-1-0-memory-native-transformer-memtensor-2026.md]

## 实测：逼近文本记忆，优于无经验基线

| 场景 | 无经验 | 文本经验 | MemT-1.0-Nano |
|---|---|---|---|
| SWE-bench Verified 关键断点平均成功率（500 题 ×3 次） | 66.07% | 69.13% | **69.73%** |
| 三次全部成功比例 | 54.00% | 61.80% | **62.80%** |
| SWE-bench Multilingual 平均成功率 | 60.00% | 63.00% | **63.56%** |
| 11 项记忆基准平均分 | — | — | Flash 50.6 / Nano 47.0 |

作者自己的结论比较克制：程序性经验能被原生记忆保留，表现与显式文本经验接近，优势更多体现在平均成功率与重复执行的可靠性上；而文本记忆系统在长历史细节召回上仍有整体优势。^[raw/articles/memt-1-0-memory-native-transformer-memtensor-2026.md]

## 能力形态：经验改变的是行动顺序

Django `parse_http_date` 的两位数年份修复轨迹是文章里最有信息量的细节：无经验时 agent 找到 bug 后立刻改解析逻辑，定向复现与验证发生在后续步骤；两组有经验的都是先构建复现测试再改代码，而 MemT-1.0-Nano 还在首次修改后**重新检查了一项边界条件**并修正实现。也就是说，记忆带来的不是「知识更多」，而是「工作流顺序变了、检查点提前了」。这与 [[concepts/agent-memory-systematic-framework|记忆系统框架]] 里「经验通过流程而非检索发挥作用」的判断一致。^[raw/articles/memt-1-0-memory-native-transformer-memtensor-2026.md]

## Memory Scaling：第三条增长曲线

团队提出的框架是：推理时扩展（test-time scaling）与训练时扩展之外，还有 **Memory Scaling**——即「同样的经历，换一种内部表示、更新规则和读取方式，能不能用得更好」。这让提升记忆效果多了一组可通过训练与架构设计调整的变量，而不是只能在外部库里调检索参数。成本侧给出了具体数字：同样 128K 长历史下，Nano 的端到端推理速度约为完整上下文方案的 **1.86 倍**，每条轨迹的持久状态占用是完整上下文 KV Cache 的 **1/66**。^[raw/articles/memt-1-0-memory-native-transformer-memtensor-2026.md]

## 边界与判断

文章的自我限定值得保留：原生记忆**没有**证明长期上限高于外部记忆；精确删除、解释与恢复需要额外机制；对精确原文/来源/版本的查询，外部记录仍有价值。更现实的定位是分工——外部记忆负责可溯源原文，原生记忆负责执行经验的复用。对企业的含义是选型标准要加一条：不是只看单次任务表现，而是看「经过验证的经验能复用多少次」，因为重复工作流里省下的返工才是长期收益。^[raw/articles/memt-1-0-memory-native-transformer-memtensor-2026.md]

## 第二来源补充：机器之心的实测细节（2026-10-20）

同期机器之心的报道与上文同一发布，但补出了一批量子位版本没有的具体数字与部署语义，作为第二来源归档如下。^[raw/articles/memt-10-memory-native-rsi-jiqizhixin-2026.md]

**训练配方与两档注入**：基座准备走一条三轨数据流水线，配方经五轮全量训练、数百次实验定型，随后进行完整的记忆原生架构训练；教师为可读完整上下文的基座，学生只看记忆状态，用 KL 蒸馏对齐且只优化记忆参数。经验注入分两档，效果不同：^[raw/articles/memt-10-memory-native-rsi-jiqizhixin-2026.md]

| 指标 | 无经验 | 执行前注入 | 执行中触发注入 |
|---|---|---|---|
| SWE-bench Verified 平均成功率 | 66.07% | 69.33% | **69.73%** |
| 三次全成功率（pass³） | 54.00% | 61.60% | **62.80%** |
| SWE-bench Multilingual 平均 | 60.00% | 62.89% | **63.56%** |
| Multilingual pass³ | 45.33% | 53.67% | **55.33%** |

**与参数化基线的差距**：11 项记忆基准上 Flash 平均 50.6、Nano 47.0，位列参数化记忆方法第一、第二，比最强参数化基线 Temp-LoRA（38.1）分别高 12.5、8.9 分——但仍落后于记忆张量自家的文本记忆系统 MemOS，即原生记忆以保真度损失换取可学习与可扩展。^[raw/articles/memt-10-memory-native-rsi-jiqizhixin-2026.md]

**成本曲线随历史增长而非线性恶化**：双 GPU、单并发、固定生成 128 token 条件下，128K 历史时 Nano 端到端推理约为完整上下文方案的 1.86 倍、持久状态占用约 1/66；历史到 256K 时加速比扩大到 **3.99 倍**，首 token 延迟（TTFT）的优势也随历史增长而扩大。单会话持久状态大小与历史长度增长解耦，是「越用越久但不越用越贵」的工程前提。^[raw/articles/memt-10-memory-native-rsi-jiqizhixin-2026.md]

**长对话的分段保真**：在一条 6.5 万 token 的英文长对话上，MemT-1.0-Nano 能在 4K 处精确召回、在 16K 处对未提及信息正确回答「我不知道」、在 32K 处做链式规则推理、在 64K 处区分「已确认的变更」与「仅被提议的变更」。对记忆系统而言，知道自己「没记住什么」往往比记住更难也更重要。^[raw/articles/memt-10-memory-native-rsi-jiqizhixin-2026.md]

**latent memory slot 的提交语义**：每段对话维护一个潜在内存槽，历史通过 commit 操作写入，原始文本不被保留；回答时只读内存、不扩展不复制，每个请求获得临时工作状态并在回答结束后释放，提问与回答本身不被提交——因此在特定对话节点上，无论问什么，依据的内存内容都相同。这解释了「记忆变成模型侧资产」的具体机制：部署时把记忆状态与用户/任务轨迹绑定，通过序列化、保存与恢复实现跨会话延续，外部存储只承载状态与原始资料。^[raw/articles/memt-10-memory-native-rsi-jiqizhixin-2026.md]

**与 MemOS 的链路关系**：文章把 MemT 1.0 定位成「MemOS 3.0 明文记忆 + 参数化记忆」完整链路中模型侧的一环——高频读写的记忆与经验被内化后，长期使用的边际成本下降；这也解释了为什么「记忆原生化是 RSI 的必要条件」：Agent 若要修改自身代码、验证效果、再让新版本继续优化自己，必须有一套让有效成果进入后续计算的机制。^[raw/articles/memt-10-memory-native-rsi-jiqizhixin-2026.md]

## 深度分析

### 判据不是「记忆在模型里」，而是梯度能不能回到写入

三类记忆各有硬伤：激活记忆随会话消失、成本线性涨；参数记忆不能逐条编辑；外部记忆可溯源却每次都要检索。记忆原生加的是第四类：可写矩阵状态。^[raw/articles/memt-10-memory-native-rsi-jiqizhixin-2026.md]

分界不在状态放哪，而在训练信号怎么走：读写若只是前向计算，模型学到的只是「把文本压进状态」，那是压缩器。MemT 1.0 让回答预测的误差梯度沿读出回溯、再沿更早的写入更新回去。冻结主干因此是必需而非便利——主干不动，读写规则才是唯一可塑项。本质是把可塑性关进一个小型可写基质，用容量上限换掉稳定性冲突——与 [[nju-same-moe-continual-learning|MoE 持续学习的遗忘治理]] 同构。

### 「第三条曲线」的证据只到点，不到线

Memory Scaling 把记忆从数据问题变成优化问题：同样的经历换表示、更新规则、读取方式能否更好。侧证齐：MoS 让容量与主干宽度解耦，两档各有独立动态记忆规模（336M / 10M），更新粒度可调（逐 token 47.0 对整轮 41.0），推理成本随历史摊薄。^[raw/articles/memt-10-memory-native-rsi-jiqizhixin-2026.md]

但「轴」要求曲线，不是点：两个容量点、一组消融，没有容量-效果关系，也没说收益何时饱和。且 MoS 用稠密融合，容量直接换算成 FLOPs，与 MoE 靠稀疏性解耦容量和算力的方向相反。容量能否「便宜地变大」正是该曲线成立的核心，原文未答。

### 蒸馏的机制预先限定了结论

教师是读得到完整上下文的冻结主干，学生只看自己的记忆状态，KL 对齐，只训记忆参数。一个被低估的后果：教师唯一优势是看得见原文，于是目标函数在奖励记忆分支复现「全上下文本会算出的分布」——学生学不到教师没有的能力。^[raw/articles/memt-10-memory-native-rsi-jiqizhixin-2026.md]

于是「逼近文本记忆」近乎定义成立：上限就是全上下文本身；「融会贯通」属外推。代价是 340 亿 token 语料加教师前向，为参数占比极小的模块付账。成本非对称：推理端便宜（128K 1.86 倍、状态 1/66，256K 3.99 倍），训练端昂贵——说「更便宜」必须指明是哪一端。

### 分段保真不等于文档级召回

6.5 万 token 长对话的四个探针（4K 召回、16K 正确拒答、32K 链式规则、64K 区分已确认与仅被提议的变更）确实漂亮，拒答尤其难；但这是单条英文对话的定点探测而非语料级平均，外推到中文、多文档没有依据。^[raw/articles/memt-10-memory-native-rsi-jiqizhixin-2026.md]

并排看：Verified 69.73% 对 69.13%（差 0.6pp）、Multilingual 63.56% 对 63.00%，真正拉开的是 pass³ 62.80 对 61.80——压的是执行抖动，不是知识上限。11 项基准上它仍落后同门的 MemOS 文本记忆，赢的是参数化这一组（对最强基线 Temp-LoRA 38.1 领先 12.5/8.9 分）。

### 在 RSI 争论里的坐标

三块拼图里只做记忆：它让有效改进成为下一次的起点，却不判断哪次有效；缺验证器时，持久化错误经验比遗忘更糟。放进 [[ai-recursive-self-improvement-nanogpt-prime-intellect|递归自我改进]] 的讨论，它提供的是持久化基座，不是改进机制。

有张力的是二阶路径：局部记忆经训练沉淀进超记忆参数、再改善记忆管理，成立才谈得上「改进的改进」，目前纯理论。而 latent memory slot 的提交语义值得细看：提交不留原文，问答不入库，同一对话节点上无论问什么都依据同一份内存内容。记忆由此从会话内状态变成可版本化资产，也让 [[parametric-memory-survey-chenzikang-alitech-2026|参数化记忆]] 落到可部署对象，代价是可解释性被前置放弃。^[raw/articles/memt-10-memory-native-rsi-jiqizhixin-2026.md]

## 实践启示

1. **按经验形态分流，不按技术新旧选型。** 程序性经验（先复现再改、检查点顺序）走记忆原生；逐字原文、来源、版本与合规凭证留给外部记录。判据是复用的方式是执行还是引用：前者要进计算图，后者要可举证。

2. **验收看 pass³ 与方差，不看单次平均分。** 0.6pp 在 500 题规模上接近噪声，可重复性的 1 个百分点才是产品差异。一次性任务先别上；同类工单反复跑，方差就是钱。

3. **成本算三笔，别只报推理加速。** 推理（128K 1.86 倍、256K 3.99 倍、状态 1/66）是唯一便宜的一笔；训练是 340 亿 token 加教师前向；运维是每用户/每任务的状态序列化、版本管理与换基座后的旧状态迁移——这条要提前验证，不是上线后的兼容 bug。

4. **别把记忆状态当审计日志。** 提交时原文不入库，删除、解释、恢复都要额外机制。要溯源时正确形态是「原文为准 + 状态为缓存」并对齐版本；指望从矩阵状态反查「记住了哪句话」是设计错误。

5. **用蒸馏复现做哨兵试点，而不是等官方权重。** 教师是自家冻结基座、学生只看状态、只训记忆参数——有基座与评测闭环即可复现。选一条高频工作流量化省下的返工次数，比在基准上追 0.6 个百分点更能判断该不该投入。
