## 摘要

淘天用户场景营销技术团队剖析了"AI 生成了 80% 代码但开发效率没提升 80%"的根源：模型层面有注意力机制 O(n²) 限制、注意力坍塌（斯坦福"Lost in the Middle"研究显示关键信息夹在长上下文中间时命中率明显下滑）和有效上下文天花板（上下文超过 180-200K 后输出质量明显下滑，这也是 Coding Agent 普遍把窗口限制在 200K 左右的原因）；方法论层面传统 Spec 模式存在"要求你在最不了解问题的时候做出最完整描述"的悖论，新型 Spec 工具（OpenSpec、Spec Kit）虽让 AI 生成规范但仍框架化、缺外部上下文注入、任务粒度单一；协作层面 Vibecoding 存在人机窗口不对称（AI 看到 165K tokens，人只记得最近 3-5 轮对话），80 轮对话后代码变成只有 AI 能理解的"认知债"。真实项目统计显示：AI 只在约 20% 的标准化场景中真正有效，80% 的复杂场景效果差甚至反效果。^[raw/articles/2026-06-22-场景营销前端-AI-Coding-从问题到方案-大淘宝技术.md]

解决方案是职责分离——把"上下文准备"和"编码执行"拆开：团队做了本地多 Agent 客户端"塔罗"（基于 Claude Agent SDK，定位工程师的 Coworker），其核心模块 Specflow 采用"DeepResearch"思路，由 Product Manager/UI Inspector/Tech Architect 三个 SubAgent（上下文隔离、并行执行、可插拔）从 PRD、设计稿、代码库做多角色深度分析、多轮澄清后生成结构化任务，再通过 Cursor Deeplinks 跳转 + MCP 回调形成双向通信闭环；D2C 场景在 D2C 平台输出的 IR 之上叠加视觉语义分析（标注"砸蛋按钮"、数据来源、切图还是 CSS 实现），让 Agent 不用从坐标颜色反推结构。文章主张以"需求完成上线时的人工干预次数"而非"采纳率"为指标，技术细节上借鉴 Cursor 动态上下文发现和 Manus 六大原则（文件系统作为无限上下文、通过复述操纵注意力、保留错误尝试），用多级提示词注入、PreToolUse Hooks 拦截、SubAgent 上下文隔离、TODO 复述机制防止目标漂移，并支持任务增量更新（需求变更只生成增量任务如 2.1，不推倒重来）与任务包导入导出实现团队复用。^[raw/articles/2026-06-22-场景营销前端-AI-Coding-从问题到方案-大淘宝技术.md]

## 关键要点

- 模块拆分原则：按功能模块拆（砸蛋主页面/奖品明细浮层/兑换流程）而非按工序拆（类型/组件/样式/交互/接口），因为每个任务要交给 IDE 独立执行、需要完整上下文。
- 压缩（compaction）是不得已的补救而非解决方案：信息有损（丢文件路径、变量名、边界条件）、上下文断层（"别人的笔记"）、隐含关联消失。
- 外置系统相对 Cursor 内置 Plan 的优势：提示词完全可控、分析结果持久化复用（重试成本只是再执行一次编码）、上下文精确控制、工程兜底（状态机+持久化）、任务管理（一个需求 5-10 个任务跨一周）。
- 多模态是补全信息链路的必要手段：PRD 里的流程图、时序图被下载丢弃，设计稿只给人看不给 AI 读，导致方案"形似神不似"。
- 提供给 IDE 的任务上下文有四个特点：精简（极少启动 tokens）、结构化、可执行（含文件路径代码引用）、自包含（无需对话澄清）。
