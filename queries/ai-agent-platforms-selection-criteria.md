# 主流 AI Agent 平台的选型标准是什么？各有什么优劣？

## 研究问题

**核心问题**：当前主流 AI Agent 平台有哪些关键选型维度？在不同维度上，各平台的实际表现和取舍是什么？

选型本质是在**能力边界**、**开发效率**、**运行成本**、**安全合规**四个维度上寻找当前项目最优解。没有全优平台，只有阶段最优。

---

## 一、选型维度框架

### 1.1 编排与架构模型

| 维度 | 关键问题 |
|------|---------|
| **单 Agent vs 多 Agent** | 平台是否支持多 Agent 协作？协作模型是层级式还是对等式？ |
| **Harness 内置程度** | 平台是否原生提供上下文管理、质量门禁、执行评判分离？ |
| **记忆持久化** | 是否支持跨会话记忆？记忆架构是向量检索、层级衰减还是文件系统？ |
| **工具/MCP 扩展性** | 工具调用是 Schema 驱动还是动态发现？是否支持 MCP 协议？ |

### 1.2 开发与运维效率

| 维度 | 关键问题 |
|------|---------|
| **Skill/Prompt 管理** | Skill 是代码级（TypeScript）还是声明式（Markdown）？是否支持自动轨迹蒸馏？ |
| **冷启动难度** | 从零到可用的最小配置是什么？是否有预置模板？ |
| **可观测性** | 执行轨迹、Token 消耗、调用延迟是否可见？ |
| **CI/CD 集成** | 是否支持自动化测试与回归？ |

### 1.3 成本与规模化

| 维度 | 关键问题 |
|------|---------|
| **计费模型** | 按 Token、按调用次数、按月订阅？是否有用量上限？ |
| **横向扩展** | 多实例部署是否支持状态共享？ |
| **上下文窗口** | 最大上下文是多少？压缩机制是否成熟？ |

### 1.4 安全与合规

| 维度 | 关键问题 |
|------|---------|
| **数据隔离** | 是否支持私有化部署？云端模式数据是否出域？ |
| **权限分级** | 工具调用是否有危险操作分级？是否支持 fail-closed？ |
| **审计追溯** | 执行轨迹是否完整保留？是否可以回放？ |

## 二、主要平台对比

### 2.1 Anthropic Claude Family（Claude Code / Claude Agent）

**代表实体**：

**优势**：
- 7 层记忆架构成熟，上下文管理精细（工具结果磁盘存储→微压缩→全压缩→做梦机制）
- Subagent 系统支持 7 种执行模式（同步/异步/Worktree 隔离/远端/Fork/Teammate）
- 按用量计费，模型能力领先

**劣势**：
- 无状态模型（每次调用新建进程），跨会话记忆需要自己实现
- Fork 模式继承父 Agent 完整对话历史，容易导致上下文污染扩散
- 危险命令防护依赖正则黑名单，无法替代沙箱隔离
- 官方承认存在 3 处质量退化问题（长程任务衰减、工具调用幻觉、压缩语义丢失）

**适用场景**：单次代码任务、IDE 集成、长程会话（需 Harness 补强）

---

### 2.2 OpenClaw

**代表实体**：

**优势**：
- 常驻进程 + 心跳/Cron，主动调度能力强
- 工具链（Harness/Prompt Cache/消息总线）工程化程度高，电商场景有大量实践
- 多渠道接入（50+）能力强

**劣势**：
- 默认开放策略，已知 13.5 万暴露实例，生产部署必须配置 fail-closed
- 无向量检索内置记忆系统，跨会话知识积累依赖文件系统
- 自进化能力弱（Skill only，无 RL 路径）

**适用场景**：需要 Cron 调度、多渠道接入的电商/运营自动化场景（安全加固后）

---

### 2.3 Microsoft Copilot Studio / Agentforce

**代表实体**：

**优势**：
- 企业级治理（Agent governance intelligent workflows）成熟
- 与 Microsoft 365/ Dynamics 生态深度集成
- Contact Center 场景（WhatsApp Voice）开箱即用

**劣势**：
- 平台锁定风险高，扩展性受限
- 自定义空间局限于 Power Platform 生态
- 透明度有限，Agent 决策可解释性弱

**适用场景**：Microsoft 生态内部企业、Contact Center 场景

---

### 2.4 国产平台（百度/阿里/字节/华为云 AgentRun）

**代表实体**：

**优势**：
- 机密计算原生支持（CPU→GPU 全链路可信），数据不出域
- 与国内云生态（阿里云/华为云）深度集成
- 中文场景优化，本地化支持好

**劣势**：
- Agent 平台成熟度较硅谷仍有差距（Skill 系统、Harness 体系相对初级）
- 模型能力受限于国产模型（benchmark 刷分与实际效果存在差异）
- 国际生态兼容性弱

**适用场景**：对数据主权有强要求、金融/政务/医疗等合规优先场景

---

### 2.5 Lightfield（及其他新兴平台）

**代表实体**：

**优势**：
- Skill 系统设计新颖（Markdown 声明式）
- 专注于影视/内容创作场景

**劣势**：
- 平台成熟度低，生产案例少
- 生态尚未建立

**适用场景**：内容创作垂直领域早期探索

## 三、选型决策树

```
项目类型？
├── 企业级 + Microsoft 生态
│   └── Copilot Studio / Agentforce
├── 需要数据不出域 + 机密计算
│   └── 阿里云 AgentRun / 百度智能云
├── 单次代码任务 + IDE 集成
│   └── Claude Code（即开即用）
├── 长期助手 + 自进化 + 记忆复利
│   ├── 需 Cron 调度 → Hermes / OpenClaw（加固后）
│   └── 无需 Cron → Claude Code + Harness
└── 电商多渠道自动化
    └── OpenClaw（安全加固后）
```

---

## 四、关键警示

1. **POC 成功 ≠ 生产可用**：所有平台在 POC 阶段都表现良好，生产阶段的核心差距在于 Harness 体系是否完整
2. **Benchmark 评分不等于实际效果**：国产模型 benchmark 刷分因素单一，实际效果与评分存在显著差距
3. **上下文窗口是共享资源**：多 Agent 并发时，上下文窗口是竞争性资源，需要分层管理
4. **安全配置不能依赖默认**：OpenClaw 的 13.5 万暴露实例证明，默认配置在生产环境是危险的

## 核心结论

主流 Agent 平台选型的核心矛盾是**"成熟度"与**"灵活性"**的取舍**：

- **Claude Code**：模型能力最强，但 Harness 需要自己搭，适合技术能力强、需求多变的团队
- **OpenClaw**：工程化程度高，但安全配置复杂，适合有安全加固能力的团队
- **Microsoft 生态**：企业级治理完善，但锁定风险高，适合已有 Microsoft 投入的团队
- **国产平台**：合规优势明显，但平台成熟度待提升，适合数据主权优先的场景

> 选型时优先问自己：这个平台的生产故障模式是什么？我是否承受得起？
