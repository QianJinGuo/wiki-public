# Harness Peer Review 的框架与最佳实践？

## 研究问题

如何设计一套科学、实用的 Harness Design Peer Review 框架，从原创性、专业性、见解深度、可操作性等维度系统性评估 Harness 设计文档的质量？

## 评审维度体系

### 1. 原创性（Originality）

| 评级 | 说明 | 评判标准 |
|------|------|----------|
| ⭐⭐⭐⭐⭐ | 核心贡献是高度凝练的"再创造"，而非文献综述 | 有反直觉规则提炼、新概念提出、量化数据支撑 |
| ⭐⭐⭐⭐ | 有明确创新点，但部分内容有较多文献引用痕迹 | 原创观点与引用内容边界清晰 |

**核心问题**：
- 是否打破了某个流行迷思？
- 是否提出了新概念（如"组件保质期"）？
- 是否有量化数据支撑，而非空谈概念？

### 2. 专业性（Professionalism）

| 评级 | 说明 | 评判标准 |
|------|------|----------|
| ⭐⭐⭐⭐⭐ | 引用准确专业术语，大量量化数据支撑 | 逻辑链条完整，从心态准备到工具选型到成本基线 |

**核心问题**：
- 术语使用是否准确（ReAct, Plan-Execute, Orchestrator-Worker 等）？
- 是否有量化数据（成本对比、效率提升、误报率等）？
- 逻辑链条是否完整？

### 3. 见解深度（Insightfulness）

**核心问题**：
- 是否指出了 Harness 与其他文档的本质区别？
- 是否有架构决策的辩证思考（没有盲目推崇某一方案）？
- 是否触及了领域的核心难点？

### 4. 可操作性（Actionability）

| 评级 | 说明 | 评判标准 |
|------|------|----------|
| ⭐⭐⭐⭐⭐ | 清单化执行 + 决策树清晰 + 场景化建议明确 | 可直接作为项目启动 SOP |

**核心问题**：
- 是否有具体的 Checklists（可直接作为项目启动 SOP）？
- 决策树是否清晰（工具选型、执行模式、瓶颈诊断）？
- 是否有明确的默认值（如 WIP=1）和验证方法？

## 综合评审结构模板

```markdown
## 综合评审意见
**总体评价**：[S/A/B/C/D 级定级 + 一句话概括]
**亮点总结**：
1. [最突出的优点]
2. [次要优点]
**改进建议（Minor Comments）**：
1. [可改进的点]
**结论**：[是否推荐收录 / 推广 / 归档]
```

## 最佳实践清单

- [ ] 评审前先通读全文，形成第一印象
- [ ] 按维度逐项评分，每项需有具体证据支撑
- [ ] 综合评价需平衡客观数据与主观判断
- [ ] 改进建议需具体可执行，避免泛泛而谈
- [ ] 结论需明确，不能含糊其辞
